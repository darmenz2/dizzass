# Stage 5 — общий UART и связка AML → UART

## Результат

Добавлен частично восстановленный **`libbitmain/src/uart.c`**: шесть процедур
открытия, настройки скорости, чтения, записи, очистки очередей и освобождения.
Структура проекта остаётся модульной, поверх выбранного публичного cgminer.
Это исходники и библиотеки, **не рабочий T21 cgminer и не образ для установки**.

Оригинальный ELF не изменён:
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

## 1. Дополнительный настоящий исходный путь

Ранний эвристический экстрактор обрезал строку по адресу `0x5edbbf` до
`/tmp/build/` (11 байт). В конструкторе по `0x10eae4` граница цикла равна
**33**, XOR по `0x10eb14` равен `0xaa`. Выполнение этого ограниченного участка
на исходных байтах восстанавливает `/tmp/build/libbitmain/src/uart.c\0`.

Исторический Stage 1 не переписан. Исправление сохранено отдельно в
`evidence/stage5/source-string-corrections.json`; генератор дерева использует
эту проверяемую поправку. Теперь **46 наблюдаемых путей**, из них **5 частично
восстановленных и 41 невосстановленный**. Это не полный перечень исходников
производителя и не процент готовности.

## 2. Перенесённые процедуры UART

| Процедура | Адрес оригинала | Подтверждённое поведение |
|---|---|---|
| Открытие | `0x10e0c8` | open с флагами `0x902`, копия пути, mutex, настройка 44-байтного kernel termios2, затем 115200 |
| Скорость | `0x10e518` | чтение termios2, маска `0xeff0eff0`, установка `0x10001000`, обе скорости, обновление сохранённого baud только после успеха |
| Запись | `0x10e6c0` | до пяти полных попыток, блокировка на каждую запись, проверка errno, задержка 20 мс |
| Чтение | `0x10e938` | FIONREAD, затем один read с полным запрошенным размером, без ограничения размером доступной очереди |
| Очистка | `0x10e994` | направление 2, очистка обеих очередей в исследованном Linux ABI |
| Освобождение | `0x10e9a0` | освобождение пути, закрытие fd, уничтожение mutex, сброс baud |

Новый заголовок `include/xminer/recovery/uart.h` — **интеграционный API**, не
восстановленное имя/ABI заголовка VNish. Внешние функции Linux/libc/mutex/sleep
передаются явными callbacks; строки диагностики и XOR-конструкторы не перенесены
в рабочую библиотеку. ARM-мьютекс оригинала не подменяется структурой pthread
другой архитектуры.

### Существенные условия и ошибки

**RX:** ошибка `FIONREAD` и пустая очередь одинаково дают `0`. Это не позволяет
по одному результату этой функции отличить отсутствие данных от отказа ioctl.
Восстановление сохраняет наблюдаемое поведение; оно не объявляется удобным
контрактом для диагностики реального устройства.

**TX:** при неполном результате и `errno == 11` оригинал заново передаёт
**весь буфер**, не оставшиеся байты. Это относится и к положительной короткой
записи со старым значением errno. Между попытками — 20 мс; после пятой неуспешной
попытки в этой ветви задержка также выполняется. При `EINTR` автоматический
повтор по этому коду не делается.

Функция явно называется `vn135_uart_write_legacy`: это точное восстановление
проверенного поведения, **не безопасная универсальная write-all реализация**.
Полевое проявление повторов или повреждение команд на физическом T21 не доказаны.
Положительный short write сам по себе допустим для Linux, а errno имеет смысл
как описание ошибки при ошибочном возврате; см. первичные man-pages ниже.

**Открытие:** в оригинале результат инициализации mutex и результат копирования
пути не приводят к немедленному отказу. Ошибка более поздней настройки оставляет
частично созданное состояние для явного destroy. Производственный адаптер
должен отдельно определить безопасную политику таких отказов.

**Добавленные ограничения нового API:** проверки NULL/callbacks/занятого
контекста, максимального размера и повторного destroy. Это отдельно обозначенные
ограничения нового интерфейса, не восстановленные гарантии VNish. Закрытие должно
выполняться после остановки всех пользователей контекста.

## 3. Исправление интерпретации Stage 3

По `0x1180e0` исходный AML TX делает `BL 0x10e6c0`. Поэтому прежнее выражение
«одна запись» было слишком сильным: **AML вызывает один раз UART-helper,
который способен сделать до пяти системных write**.

Исправлены комментарии `aml/chip.c` и контракт `aml_chip.h`. Сам верхний алгоритм
не менялся. Добавлен тест, в котором исходные AML и UART исполняются **совместно**
в локальном интерпретаторе; UART больше не заменяется константным ответом.
Сравниваются кадр `55 AA + payload`, возвращаемое значение и последовательность
выделения памяти, двух уровней блокировки, write, errno, sleep и освобождения.

Два уровня блокировки оригинала различаются: внешний AML mutex и внутренний
mutex UART. При интеграции нельзя без анализа свести их к одному нерекурсивному
mutex. Тест сравнивает последовательность вызовов, не реальную конкурентность.
Связка ещё не подключена к работающему хешированию.

### Настоящий Linux-псевдотерминал — отдельно от сравнения ARM

`tests/test_uart_linux_pty.c` создаёт собственную пару PTY. Новый тестовый адаптер
вызывает настоящие `open`, `ioctl`, `read`, `write`, pthread mutex и `close`
только для этой пары. Статические проверки сверяют ioctl-константы и структуру
termios2 с заголовками ядра Linux текущего host.

Проверены первоначальные 115200, установка 250000, raw-флаги, фрагментированный
RX (2 и 7 байт), сохранение двоичных/управляющих байтов, передача кадра с `55 AA`,
очистка и закрытие. Этот тест прошёл обычную GCC/Clang-сборку и GCC ASan/UBSan.

**PTY не моделирует электрический UART, скорость физического провода, FIFO
контроллера, ответы BM-чипов или поведение хешплаты.** Это интеграционный тест
Linux-слоя, а не стендовый тест T21. В тесте legacy TX прошёл с одной успешной
записью; сценарии повторов проверены отдельно с подставленными результатами.

## 5. Привязка модели и то, что ещё отсутствует

Поиск в распакованном ramdisk и просмотр model/work-gen/dispatch участков не дали
достаточной цепочки доказательств для утверждения **T21 → chip1398**.
Сосуществование названий BM1368/BM1398 и других драйверов — не доказательство
выбора конкретной моделью. Эти селекторы и типы нельзя смешивать по совпадению
номеров. Привязка по runtime-конфигурации и вызываемым таблицам остаётся открытой.

Не восстановлены полный диспетчер/инициализация цепей, синхронизация входного
потока по преамбуле, полная проверка/разбор ответов регистров и nonce, аппаратные
переходы baud/PLL, PSU, датчики, охлаждение, защиты, рабочий тракт и автотюн.
`full-runtime` по-прежнему завершается ошибкой, а не выдаёт фиктивный майнер.

Upstream cgminer в этот архив не добавлен. Повторное обращение за зафиксированным
GitHub-архивом завершилось `Temporary failure in name resolution`. Сборщик overlay
сохранён; его проверка на тестовом Git-дереве не считается полной сборкой upstream.
Никакой ASIC, сервер HashStat, пул или исходный пользовательский checkout не менялся.

## Команды

```sh
make -f Makefile.recovery clean all test arm evidence-check sanitize
make -f Makefile.recovery linux-pty sanitize-linux-pty
python3 tests/test_assembler.py
python3 tools/update_overlay_inventory.py --check
```

Для наложения на чистый checkout выбранного cgminer:

```sh
python3 tools/assemble_on_cgminer.py --source /path/to/pinned-cgminer --output ../cgminer-vnish135
```

**Не заменять штатный `/usr/bin/cgminer` библиотекой.** Сборка выдаёт `.a`, не
исполняемый майнер. Новые проверенные модули ещё не зарегистрированы как T21-драйвер.

- Linux man-pages, write(2): https://man7.org/linux/man-pages/man2/write.2.html

Они объясняют контракт Linux, а не доказывают содержимое VNish. Основание
реконструкции — сохранённый ELF, точные машинные инструкции и воспроизводимые тесты.

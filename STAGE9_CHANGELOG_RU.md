# Stage 9 — восстановление заголовка из сохранённого задания

**Модульная реконструкция. Не готовый T21 cgminer и не установочная прошивка.**
Пулы, серверы и физические ASIC не подключались. Исходный ELF не изменён:
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

## Реализованный участок

`src/frontend/cgminer.c` расширен восстановленным префиксом `0x30550–0x30a6c`.
Размещение в frontend — интеграционный выбор в существующем кластере cgminer,
а не отдельное доказательство имени исходного файла каждой процедуры.

Из явно переданного снимка и буферов код:

1. Копирует младшие байты 64-битного счётчика в указанное место coinbase.
2. Увеличивает полный счётчик с переносом между словами и wrap по модулю 2^64.
3. Считает SHA256d всей coinbase.
4. Для каждой Merkle-ветви считает SHA256d от `текущий корень || ветвь`.
5. Копирует 112 байт шаблона, заменяет 32 байта по смещению 36 корнем с перестановкой
   байтов внутри каждого 32-битного слова.

Даже при ширине вставки 0 счётчик увеличивается. Корень возвращается также отдельно
в сырых байтах digest. Публичные имена функций и типы нового API — не двоичный ABI VNish.

**112 байт — префикс исходного work, не весь work размером 632 байта.** Первые 80 байт
содержат заголовок в word-swapped представлении. Хвост 32 байта сохраняется из шаблона,
его нельзя считать дополнительными полями сериализованного Bitcoin-заголовка.
Суффикс оригинальной функции — строки, target из difficulty, учёт и владение объектами —
этим этапом не перенесён. Остальные байты work при сравнении не считаются восстановленными.

## Подтверждённая связь с кандидатом Stage 7

Выполнена в ограниченном интерпретаторе исходная цепочка:
`0x74f14 → 0x300ac → 0x30550`, с остановкой перед `0x30a6c`.

- `job_word_70` и `job_word_74` действительно передаются как младшее и старшее слова
  счётчика coinbase. Прежние имена полей оставлены для совместимости нового API.
- `version_word` проходит два REV, в вызывающем коде и обёртке. В результате в первый
  word work попадает исходное значение кандидата в little-endian представлении.
- Существующий `nonce` передаётся в префильтр без подстановки другого значения.

Условия теста: правильные template/reference уже выбраны и удерживаются вызывающим
кодом, выделение work успешно, mutex/rwlock успешны. Обёртка выполняется только до
исследованной границы. Это **не** восстановление всех её ошибок и полного consumer.

## Новые вспомогательные файлы

`reconstruction/support/sha256_bytes.c` — переносимый одноразовый SHA256/SHA256d для
сообщений переменной длины, построенный на ранее проверенной функции сжатия.
Реальные оригинальные SHA-инструкции выполняются при сравнении; результат не заменён
константой. Неполные блоки, границы padding и перекрытие входа/выхода проверяются отдельно.
Имя support-файла новое, не восстановленное имя библиотеки производителя.

`reconstruction/support/work_rebuild_pipeline.c` — **новый адаптер**, не полный
оригинальный поток обработки. Он копирует coinbase в предоставленный scratch-буфер,
подставляет счётчик и версию кандидата и вызывает восстановленный prefix. Сохранённый
снимок не меняется. Нет скрытых аллокаций, отправок, переподключений и аппаратных команд.

Вторая функция адаптера соединяет восстановление заголовка с префильтром Stage 8 и
сравнением target. Target передаётся явно: преобразование сложности в target не
придумано. Флаги `hash_computed`, `target_checked`, `meets_target` различают дубликат,
отказ старшего слова хеша и результат порогового сравнения. Код возврата 0 означает
завершённое вычисление, **не принятую пулом шару**.

## Границы и память

Новый API добавляет явно обозначенные проверки: длина coinbase <= UINT32_MAX;
ширина вставки счётчика 0–8; вставка внутри буфера; корректность указателей на пустые
и непустые массивы; безопасный размер списка ветвей; достаточная ёмкость scratch.
Неверные аргументы отклоняются до изменения output/scratch/last_nonce.

Оригинальный код не даёт доказанной проверки всех этих размеров. Проверки нового
API не выдаются за восстановленные защиты VNish. Массивы должны быть реально
доступны, изменяемые объекты должны быть неперекрывающимися, как указано в заголовке.
SHA-helper отдельно поддерживает перекрытие входа с 32-байтным выходом.

Оригинал меняет coinbase под write-lock, затем снимает его и берёт read-lock для
дальнейшей сборки. Тесты воспроизводят последовательность успешных вызовов, но не
параллельные потоки. Низкоуровневому новому prefix нужна внешняя синхронизация;
адаптер снимка использует отдельную копию coinbase. Это сознательная интеграционная
изоляция, не доказательство потокобезопасности исходного consumer.

`last_nonce` сохраняет прежнюю семантику Stage 8: изменяется до проверки хеша и не
откатывается после отказа. Нет утверждения о полной дедупликации между заданиями.
Индекс 0–31 и совпавший ключ сами по себе не подтверждают свежесть задания. Все поля
снимка, включая Merkle-ветви и target, вызывающий код обязан получать из правильного,
согласованного и удерживаемого задания.

## Наборы проверок

| Проверяемый новый контракт | Число случаев в воспроизводимом наборе |
|---|---:|
| SHA256 / SHA256d переменной длины против оригинальной SHA | 212 |
| Префикс сборки: все 112 байт, coinbase и 64-битный счётчик | 198 |
| Оригинальная цепочка caller → wrapper → prefix против адаптера кандидата | 144 |
| **Основные новые сравнения** | **554** |

Отдельно, без прибавления к 554: 144 композиции prefix/префильтр/target с оригинальными
участками; 212 проверок SHA с перекрытием памяти; 12 композиций на известном genesis;
338 нативных проверок, включая 11 вариантов фрагментации RX; 2 649 синтетических
проверок добавленных ADC/ADCS и LDRD/STRD. Это число тестовых случаев, не функций.
Новые сравнительные наборы повторяются на GCC и Clang. Санитайзеры покрывают нативные
C-наборы, не все Python/ctypes сравнения.

Ограниченный ARM-интерпретатор — локальный инструмент, не независимо сертифицированный
CPU. Он не запускает исходный ELF как Linux-процесс. Внешние memcpy/memset, успешные
аллокации и блокировки внедрены. Оригинальные SHA/арифметика/сборка выполняются.
Физические тайминги, потоковые гонки, аппаратные ответы и принятие пулом не проверены.

## Независимый исторический вектор

Из параметров genesis в Bitcoin Core v29.0 собраны coinbase, Merkle root и заголовок.
Генератор перепроверяет их Python hashlib. Нативный тест принимает **синтетический**
RX-кадр с известным nonce, разбитый на фрагменты 1–11 байт. После RX и кандидата
восстанавливает заголовок и получает ожидаемый хеш:

`000000000019d6689c085ae165831e934ff763ae46a2a6c172b3f1b60a8ce26f`.

Это сквозной офлайн-вектор на заранее известных данных. Не захват T21, не найденный
новый блок, не живая шара и не проверка жизненного цикла пула. Chip/core attribution
и reader задания в этом тесте — явно введённые фикстуры.

Первоисточник данных: Bitcoin Core `v29.0`, `src/kernel/chainparams.cpp`,
https://github.com/bitcoin/bitcoin/blob/v29.0/src/kernel/chainparams.cpp
(blob `ac3fc9eadad6f32500697f978c7bbfc17acc183a`). Дополнение SHA: RFC 6234,
https://www.rfc-editor.org/rfc/rfc6234.html . Они объясняют независимый тестовый
вектор и алгоритм, а поведение VNish обосновывают исходные байты ELF и сравнения.

## Сборка и продолжение

```sh
make -f Makefile.recovery all arm stage9
make -f Makefile.recovery stage9-clang sanitize-stage9
./build/vn135-rebuild-genesis
```

Групповая проверка чистого архива: `tools/verify_stage9.py`, логи в каталоге вне
исходников. Наследует группы Stage 8 и добавляет `rebuild-sha`, `rebuild-prefix`,
`rebuild-candidate`, `rebuild-native`, `clang-rebuild`. Инвентарь и карты оригинальных
байтов проверяются отдельно. Результаты реальных запусков — в передаваемом финальном
логе и машинной сводке; описание набора само по себе не заменяет протокол прогона.

46 наблюдаемых исходных путей; 7 частично восстановлены; 39 исключены. Теперь
компилируются **16 C-модулей**: 7 на наблюдаемых путях и 9 явно новых helper/adapter-файлов.
Полный список файлов производителя и процент восстановления не установлены.

Публичный upstream cgminer по-прежнему не включён и совместная полная сборка не
заявляется. Наложение сохраняет исходные пути, авторство и объектные каталоги.
Выход — host/ARMv7 библиотеки и офлайн-проверка, **не исполняемый T21-майнер**.

Остались target из сложности и полный work/consumer, жизненный цикл/владение
заданиями, очередь 72/68, проверка CRC ответов, T21 model dispatch, запуск хешплат,
PSU/датчики/охлаждение/защиты, интеграция драйвера upstream и автотюн.
**Не заменять штатный `/usr/bin/cgminer` этим комплектом.**

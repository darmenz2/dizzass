# Stage 12 — копирование work с изменением времени

**Модульные исходники и библиотеки, не готовый T21 cgminer.** Ничего не установлено
на оборудование. Нет подключения к пулам или серверу HashStat.

## Исходная база и выполненная работа

Продолжение точного Stage 11 (`8dc61d9bc4ec4a9b65e0b67ff5489c8873da2b681943fd87ca05dcb2079becd0`).
`reference/cgminer.vendor.elf` не изменён: 6 228 004 байта, SHA-256
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

В `src/frontend/cgminer.c` расширена реконструкция clone (`0x2ce84–0x2d108`):
теперь перенесены обе ветви изменения времени, с присутствующей строкой и без неё.
Поддерживаются корректные входные объекты, успешное выделение внешнего объекта и,
для сравнения с оригиналом, успешное выделение строки кодировщиком времени.
Нулевая ветвь и прежний API `vn135_frontend_work_clone_unrolled` сохранены.

Новое API `vn135_frontend_work_clone_time_legacy` принимает явные `fresh_id` и
32-битный `delta`. Это новые интеграционные имена, не исходный бинарный ABI.

| Файл | Изменения |
|---|---|
| `src/frontend/cgminer.c` | Clone с нулевым/ненулевым смещением времени, независимое копирование строк |
| `reconstruction/support/work_time_hex.c` | Четырёхбайтное значение времени ↔ восемь hex-цифр |
| `reconstruction/support/work_storage_pipeline.c` | Новый all-or-nothing адаптер для копии с изменением времени |
| `include/xminer/recovery/work_time.h` | Контракт входов, представления и ограничений |

Имена support-файлов/заголовков — наши. Их исходные названия в прошивке не доказаны.
Размещение clone во frontend сохраняет прежний интеграционный выбор внутри
подтверждённого исходными путями кластера, не отдельное доказательство имени каждой функции.

## Поведение оригинального clone

1. Создаётся копия 632 байт; в `+0x1bc` записывается новый идентификатор.
2. Строки копируются в порядке `18c → 1a8 → 19c → 1b0`.
3. При ненулевом смещении четыре байта `image + 0x44` трактуются как big-endian
   число, увеличиваются по модулю 2^32 и сохраняются в прежнем порядке байтов.
4. Если строка по `+0x19c` присутствует, её значение отдельно декодируется,
   увеличивается на тот же delta и кодируется строчными hex-цифрами.
5. Если строки нет, она не создаётся; меняется только поле заголовка.

**Время в заголовке и время в строке увеличиваются независимо.** Исходная функция
не исправляет их расхождение и не проверяет равенство. Переносы и wrap сохранены;
`delta=0xffffffff` означает сырой 32-битный addend, а не разрешённую политику пула.
В нулевой ветви строка копируется буквально, включая регистр букв.

Для ненулевой ветви оригинальный кодировщик `0x1068c`, вызванный с длиной 4,
выделяет **12 нулевых байт**, из которых 8 — hex-цифры и следующий байт — NUL.
Реконструкция сохраняет этот размер и оставшиеся нули. Общий кодировщик произвольной
длины здесь не объявляется восстановленным; проверен конкретный четырёхбайтный контракт.

**Clone не вычисляет новый хеш, не меняет target, не сбрасывает nonce/last_nonce,
не проверяет свежесть задания и не согласовывает пределы времени с пулом.** Он
копирует эти непрозрачные поля без изменений. Проверка SHA256d выполняется отдельно.
Ни успешная копия, ни совпадение хеша не означают принятую пулом шару.

## Что добавлено сознательно, а не найдено в оригинале

Исходная функция после `BL 0x107b0` не проверяет возвращаемый статус декодирования.
При неверном тексте часть временного буфера может остаться незаписанной. Такое
поведение не переносится как определённая функция над произвольной строкой.

Новый API при `delta != 0` и присутствующей строке требует **ровно восемь корректных
ASCII hex-цифр**. При несоответствии возвращается `VN135_STORAGE_INVALID` до любых
выделений/мутаций. Нулевой delta сохраняет прежний договор Stage 11: произвольная
корректная NUL-terminated строка копируется без разбора как время.

В оригинальном hex-кодировщике нет проверки NULL перед записью в результат calloc.
Этот исход не исполнялся и не объявляется дифференциально восстановленным. Новый
C-код обрабатывает отказ как `PARTIAL`, помечает отсутствующую строку и продолжает
копирование последующих строк. Отказ внешнего выделения также обрабатывается новым guard.

`vn135_work_clone_time_atomic` — **новая политика публикации**, а не восстановленный
код производителя: освобождает все части неудачной копии и оставляет выход NULL.
Слово atomic не означает потокобезопасность или аппаратную атомарность. Как и прежде,
нужны доступные раздельные буферы, одна согласованная пара allocate/release и внешняя
синхронизация. Входные строки не изменяются; общие pool/template-объекты не удерживаются.

## Сравнение с оригинальными инструкциями

| Основной новый набор | Случаев |
|---|---:|
| Hex encode/decode четырёхбайтного времени | 1 188 |
| Clone: ветви времени, все нормализованные байты, строки, порядок выделений | 1 323 |
| **Всего** | **2 511** |

Из 1 323 clone-случаев 1 242 имеют ненулевой delta, 621 — отсутствующую строку времени,
513 — исходное расхождение строки и заголовка; 939 случаев проверяют частичные отказы
остальных строк. Это пересекающиеся группы, их нельзя суммировать.

Новый основной набор прошёл на GCC и Clang. Старый основной набор имеет 106 863 случая;
состав общего набора Stage 2–12 — **109 374**. Это количество тестовых входов,
не восстановленных функций и не процент готовности.

Отдельно, **без прибавления к основному итогу**:

- 70 композиций «оригинальный clone → оригинальный SHA256d», сравнённых с новой
  библиотекой и независимо с Python `hashlib`;
- 6 158 нативных сценариев / 43 397 утверждений с настоящими malloc/free, включая
  все байтовые значения в каждой позиции hex, отказы внешнего выделения/строк,
  новый откат, отсутствие строки, повторное освобождение и обратное смещение;
- шесть синтетически изменённых заголовков на основе сохранённого исторического
  вектора Stage 9. При обратном смещении восстанавливается первоначальный заголовок
  и известный хеш. Изменённые заголовки не объявляются допустимыми сетевыми блоками.

Нативный набор прошёл GCC/Clang и ASan/UBSan с `detect_leaks=1`. Санитайзеры относятся
к этому C-набору, не ко всем Python/ctypes сравнениям.

### Граница эталона

Используется прежний ограниченный локальный A32-интерпретатор; новые инструкции
ему не добавлялись. В оригинале исполняются clone, hex2bin, bin2hex и тело strdup.
Hex-алфавит не подставляется готовой константой в эталон: исполняется исходный
XOR-цикл `0x1ff00–0x1ff2c`. Его охватывающий конструктор найден в `.init_array`.
Таблица разбора по `0x5b0310` сверена побайтно, включая все 256 значений.

Внешние calloc/malloc/free, strlen, memcpy/memset, mutex и диагностика внедрены.
Основная арифметика и hex-конверсии оригинальные. Проверяются независимость копии,
все 632 байта после нормализации известных pointer-слотов, строки и порядок аллокаций.
Остальные поля от этого не становятся понятыми или совместимыми с оригинальным ABI.

Интерпретатор не является независимо сертифицированным процессором. Не проверены
конкурентность, полное пространство входов, аппаратные тайминги, физический ARM,
периферия или принятие пулом. Полный исходный ELF как процесс не запускался.

## Сборка и чистая проверка

```sh
make -f Makefile.recovery all arm stage12
make -f Makefile.recovery stage12-clang sanitize-stage12
make -f Makefile.recovery evidence-check
python3 tools/verify_stage12_all.py --logs /absolute/path/outside-source --workers 2
```

Полный runner содержит 38 групп / 74 команды верхнего уровня, включая ожидаемый
отказ `full-runtime` с кодом 2. Итог **фактически выполненного прогона поставленного
ZIP** передаётся отдельно в `VNish135_Stage12_Final_Verification.log` и `.json`.
Наличие runner само по себе не доказывает прохождение тестов.

`evidence/stage12/recovery-manifest.json` фиксирует 4 диапазона кода, 7 блоков данных/
литералов и 12 рёбер вызовов. Карта и данные проверяются `tools/check_stage12_evidence.py`.
`tools/generate_time_fixture.py` независимо воспроизводит шесть hash-векторов.

## Текущее состояние и продолжение

Компилируются **19 C-модулей**: 7 на наблюдаемых путях, 12 явно новых support/adapter.
Наблюдаемых путей по-прежнему 46; 39 невосстановленных исключены из сборки. Не добавлены
пустые функции с фиктивным успехом, монолит или заменяющий cgminer main.

Полное дерево публичного upstream cgminer не включено, совместная сборка настоящего
upstream не заявляется. Additive overlay и тест Automake сохраняют прежние имена,
авторство и раздельные объектные файлы. Сборка выдаёт host и freestanding ARMv7-A/A32
hard-float библиотеки, **не исполняемый майнер**.

Остаются общие внешние ссылки/владение и актуальность заданий, полноценный consumer,
очередь 72/68, CRC ответов, выбор T21-драйвера, запуск цепей, питание/датчики/
охлаждение/защиты, интеграция runtime и автотюн.

**Штатный `/usr/bin/cgminer` этим комплектом не заменять.**

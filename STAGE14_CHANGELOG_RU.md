# Stage 14 — проверка устаревания заданий и происхождение cgminer

**Модульные исходники и проверочные библиотеки. Не готовый майнер.** Никакой
физический ASIC, пул или сервер HashStat не подключался. Штатная прошивка не менялась.

Продолжение точного Stage 13, ZIP SHA-256
`f697156848c410f668a6659fc2a4ca209003d1b2f823cbbe1b44960650451f6b`.
Неизменённый ELF: `b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

## 1. Реализованный объём

В существующий `src/frontend/cgminer.c` перенесены два предиката. Размещение в
frontend — интеграционный выбор существующего кластера, не доказательство
исходного имени файла каждой функции. Строки diagnostics, XOR и живые блокировки
не переносятся; API работает по согласованному неизменяемому снимку.

| Оригинал | Новая реализация |
|---|---|
| `0x2a560..0x2a5f0` | Проверка пригодности pool по одному слову и четырём флагам |
| `0x32040..0x324c0` | Проверка work_block, режима share, состояния Stratum, job_id и срока |
| Новый adapter | Извлечение известных полей из нормализованного `vn135_work_storage` |

Новый заголовок `include/xminer/recovery/work_freshness.h` и
`reconstruction/support/work_freshness_snapshot.c` — наши интерфейсы/файл.
Они не объявляются родными структурами/ABI VNish. Новых заглушек нет.

## 2. Сохранённая логика

### Проверка pool

Результат «непригоден», если `word_1fc != 1` или отсутствует любой из флагов
`byte_3fc`, `byte_3fe`, `byte_209`, либо ненулевой `byte_1ea`.
Названия сырых полей намеренно сохранены по смещениям: не все их семантические
имена доказаны. Успешный возврат API и результат предиката — разные значения.

### Устаревание work

Последовательность:

1. Если сохранённый `work_block` отличается от текущего глобального слова — stale.
2. Срок: **600 секунд**, если signed rolltime <=60; иначе берётся rolltime.
3. Только при `share == 0`: проверяются два флага активности Stratum и, если обе
   строки существуют, равенство job_id. Несовпадение — stale.
4. Сравнивается возраст с выбранным сроком. **Равенство уже считается истечением.**

В ELF также есть минимум 5.0 секунд. В исследованной стабильной ветви выбор
600 либо rolltime>60 уже превышает этот минимум; код/константа сохранены буквально.
Не подставлена формула `max(600, rolltime)`: при rolltime=61 срок действительно 61,
а при rolltime=60 он 600. Проверены обе стороны этой границы.

`share != 0` пропускает проверки активности/job_id, **но не work_block и не возраст**.
Отсутствие хотя бы одной строки job_id само по себе не делает work устаревшим.
Это воспроизведение конкретного предиката, не универсальная политика принятия шар.

Возраст берётся из разности 64-битных секунд с оригинальным модульным SUBS/SBC,
затем signed64 переводится в double. Доли секунды не участвуют. Отрицательный
возраст на этой границе не отклоняется. Это не гарантия допустимости будущего
времени по правилам сети. C избегает signed overflow, явно сохраняя битовый результат.

## 3. Что не добавлено молча

Новый API требует согласованных, удерживаемых вызывающим кодом снимков и строк.
Он не получает данные от пула, не удерживает native-ссылку и не создаёт mutex.
Имена причин, флаги `job_ids_compared` / `time_compared`, проверки NULL/вида строки
и отказ при ненулевых нормализованных pointer-слотах — **наша диагностика/guards**.
На неверном входе результат не изменяется. Аргументы должны ссылаться на доступную
память и не перекрываться с выходом. Не воспроизводятся повреждённые указатели.

`VN135_WORK_CURRENT` означает только проход этого предиката. Он не доказывает
правильное поколение после переиспользования слота, clean_jobs/сессию, корректность
nonce, target или принятие пулом. Полный registry, lifetime и consumer не восстановлены.
Новый adapter не подключается к живой очереди автоматически.

## 4. Проверки нового этапа

| Основной набор сравнений с неизменёнными ARM-инструкциями | Случаев |
|---|---:|
| Pool predicate, состояния и неизменность входа | 1 440 |
| Stale predicate, исходные переходы и обращения к внешним функциям | 6 926 |
| **Всего основных новых сравнений** | **8 366** |

Все новые случаи выполнены на GCC и Clang. В оригинальном эталоне исполняются
полный исследованный предикат, VFP-сравнения, SUBS/SBC и **оригинальная signed64→double
процедура**. Clock, strcmp, успешные rwlock/unlock, косвенный вызов после unlock и
диагностика — явно подставленные операции. Конкурентность не эмулируется. Проверяются
порядок этих событий, отсутствие чтения времени на ранних отказах и неизменность
work/pool. Нет утверждения, что C snapshot-API исполняет оригинальные блокировки.

Отдельно, **не прибавляя к 8 366**: 408 композиций с adapter старого work-storage;
5 768 синтетических проверок SBC/SBCS/RSC/RSCS; 264 сравнения исходного преобразования
signed64→double с Python. 663 328 нативных утверждений проверяют главным образом
границы сроков, ошибочные виды строк, нормализацию и отсутствие изменений при ошибке.
Это не 663 тысячи восстановленных функций или независимых аппаратных опытов.
Нативный набор прошёл GCC/Clang ASan/UBSan с detect_leaks=1. Санитайзеры относятся
к нативному C-набору, не ко всем Python/ctypes сравнениям.

Локальный ARM-интерпретатор расширен SBC/RSC; это ограниченный инструмент, не
сертифицированный CPU. Неизвестные инструкции и обращения за границы останавливают
проверку. Исходный ELF не запускается как Linux-процесс. Нет физических таймингов,
проверки реального UART, питания, хешплат или сети.

Полный набор прошлых этапов содержит 121 099 основных случаев; вместе с новым
набором — 129 465. **Факт повторного запуска именно поставленного ZIP подтверждается
отдельными финальными JSON/логом, не одним наличием runner или этой таблицы.**

## 5. Параллельный поиск исходной ветки

Подробности в [UPSTREAM_LINEAGE_RU.md](UPSTREAM_LINEAGE_RU.md). Найдено соответствие
ряда восстановленных участков публичным `get_work_by_nonce2`, `gen_stratum_work`,
`set_target`, `diff_from_target`, `new_nonce`/`test_nonce`. Это подтверждает семейство
кода и помогает не переписывать открытый frontend с нуля, но не определяет уникальный
commit, от которого VNish ответвился.

Публичная S9-ветка `jameshilliard/cgminer:s9` действительно слита PR #730 в
`ckolivas/cgminer` 29.09.2018. Проверка графа показала, что выбранный pin `b8491c66…`
уже включает этот merge. Поэтому pin не переключён на случайный bmminer-форк.
**Точная ветка VNish не найдена; удалённый fork этой сессией не создан.**

В текущем подключении GitHub доступны read/search, а не create-fork. Добавлен
инструмент подготовки настоящего fork через `gh`, с проверкой аккаунта, commit/tree,
сохранением Git-истории, новой локальной веткой и опциональным локальным overlay.
Он ничего не коммитит и не пушит; private/vendor evidence не отправляется в GitHub.
Проверены только dry-run/guards: live-создание fork и полная сборка upstream здесь
не выполнялись. Никакое существующее хранилище пользователя не переписывается.

## 6. Сборка и продолжение

```sh
make -f Makefile.recovery all arm stage14
make -f Makefile.recovery stage14-clang sanitize-stage14
python3 tools/check_stage14_evidence.py
python3 tools/verify_stage14_all.py --logs /absolute/path/outside-source --workers 2
```

Подготовка плана fork (без сети):

```sh
python3 tools/prepare_cgminer_fork.py --output ../cgminer-vn135-base --apply-overlay
```

Явный запуск с настроенным `gh` на компьютере пользователя:

```sh
python3 tools/prepare_cgminer_fork.py --output ../cgminer-vn135-base --apply-overlay --execute
```

Компилируются 23 C-модуля: 7 наблюдаемых и 16 новых support/adapter. Экспортируются
88 функций нового API, не 88 полностью восстановленных исходных функций.
46 наблюдаемых путей сохраняются, 39 невосстановленных исключены из сборки.
Обновлённый additive overlay сохраняет прежние пути, авторство и раздельные объекты.

Остаются: полный consumer/registry/lifetime заданий, чистое соединение с реальным
upstream, T21 model dispatch, CRC ответов, запуск цепей, PSU/датчики/охлаждение/
защиты и автотюн. ARMv7 — freestanding-библиотека, не исполняемый майнер.
**Не заменять штатный `/usr/bin/cgminer`.** `full-runtime` должен возвращать отказ.

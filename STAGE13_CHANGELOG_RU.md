# Stage 13 — очередь nonce, FIFO и явная граница 68/72 байта

**Модульная реконструкция, не готовый T21 cgminer. Физическое оборудование, пулы
и серверы не подключались.** Продолжение точного Stage 12:
`0e38cbd48fbdaa979c56c0e6fc0ba099bc48e210d9a9ed5810e5946a8a3153f9`.
Неизменённый `reference/cgminer.vendor.elf`, 6 228 004 байта:
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

## 1. Восстановленный объём

На корректно инициализированном состоянии перенесены восемь процедур FIFO и семь
обёрток очереди nonce. Оригинальные имена файлов этого кластера пока не установлены.
Поэтому код находится на явно **новых** интеграционных путях, без выдуманного
объявления ещё одной папки/файла производителя восстановленными:

| Файл | Содержимое |
|---|---|
| `reconstruction/support/record_fifo.c` | Инициализация FIFO, push/pop, full/empty/count, reset/destroy |
| `reconstruction/support/nonce_fifo.c` | Инициализация, push/pop, full/empty, reset/destroy очереди nonce с внешней синхронизацией |
| `reconstruction/support/nonce_record_bridge.c` | **Новый** явный адаптер 68 заполненных байт кандидата и четырёх непрозрачных байт |
| `include/xminer/recovery/nonce_fifo.h` | Новый API и его ограничения; не бинарный ABI VNish |

Адреса оригинальных процедур:

| Процедура FIFO | Адрес | Обёртка очереди | Адрес |
|---|---|---|---|
| init | `0xd19b0` | init | `0xfa5a4` |
| push | `0xd19f0` | push | `0xfa5e0` |
| full | `0xd1bb0` | full | `0xfa87c` |
| empty | `0xd1de0` | empty | `0xfa7b4` |
| pop | `0xd1df0` | pop | `0xfa6e0` |
| count | `0xd20ac` | — | — |
| reset | `0xd212c` | reset | `0xfa944` |
| destroy | `0xd2144` | destroy | `0xfa97c` |

Исходная структура кольца занимает 28 байт на ARM32: begin/end/write/read pointers,
capacity/count/element_size. В новом переносимом представлении сохранён один
нативный указатель и числовые индексы элементов. При сравнении оригинальные
указатели нормализуются в индексы. **Это другой ABI**, даже на ARM.

Batch/peek-функции между этими адресами не объявляются восстановленными. Исходная
libc/malloc/pthread не переносится в C и не является частью этого этапа.

## 2. Подтверждённая политика переполнения

Оригинальная nonce-очередь выделяет **4096 элементов по 72 байта**, всего
294 912 байт, то есть 288 КиБ данных без служебных структур.

Последовательность оригинального push:

```
lock
    → проверка заполнения
    → если заполнено: удалить один самый старый элемент без выдачи данных
    → скопировать новый элемент
    → увеличить отдельное 32-битное слово на 1
unlock
```

Таким образом, новая запись вытесняет **самую старую**, а не отклоняется.
Это политика локальной очереди, **не измерение потерь на действующем T21**.
Синтетический стресс намеренно переполняет буфер; его число вытеснений зависит
от планировщика и ничего не говорит о нормальной скорости настоящего майнера.

Полезные детали, сохранённые в реконструкции:

- Push/pop переходят к началу на точной границе кольца. Pop с NULL отбрасывает
  один элемент; пустая очередь не изменяет выходной буфер.
- Reset сбрасывает количество и позиции, но не затирает память данных и не
  сбрасывает отдельное слово push. Init также не обнуляет это отдельное слово.
- Исходный destroy обнуляет только begin pointer после free. Числовые размеры,
  count и позиции в новой форме сохраняются; доступ к уничтоженному хранилищу
  запрещён новым guard. Сохранённые счётчики не означают наличия живых записей.
- Обёртки push/pop и запросы full/empty синхронизируются одним внешним mutex.
  Инициализация и уничтожение требуют отсутствия конкурентных пользователей.

Глобальные адреса оригинала проверены по инструкции и литералу:
mutex `0x654ad0`, кольцо `0x654ae8`, отдельное слово `0x654b04`.
Это описание конкретного ELF, не адреса для обращения на физическом ASIC.

## 3. Различие 68 и 72 байт больше не скрывается

Stage 7 доказал заполнение producer-ом 68 байт. Теперь оригинальный queue push,
кольцо и queue pop исполняются совместно в сравнении: **копируются все 72 байта**,
включая последние четыре. Это подтверждает передачу хвоста, но не его смысл.

Новый адаптер явно требует:

```
17 числовых uint32 полей кандидата
    → 68 байт little-endian
    + 4 байта, ЯВНО переданные вызывающим кодом
    → 72-байтный record
```

При распаковке хвост возвращается отдельно. Он не объявляется padding,
поколением, временем, указателем или CRC. Никакого чтения 72 байт через указатель
на 68-байтный объект нет. В тестах хвост заполняется известными разными маркерами;
это тестовые данные, а не установленное значение в прошивке.

68/72 ABI оригинального consumer в целом не восстановлен. Новый record не
разрешается вставлять в оригинальный runtime без проверки всего интерфейса.

## 4. Новые защиты, не приписанные оригиналу

Новый API проверяет нулевые/переполняющиеся размеры, состояние инициализации,
диапазоны числовых курсоров, NULL и соответствие размеров записи. Ошибка
выделения памяти не публикует очередь; уже созданный mutex уничтожается.

Результаты ошибок initialize/lock/unlock/destroy обрабатываются явно. Эти
проверки **добавлены**, тогда как исходные успешные последовательности проверяются
дифференциально. Отказы оригинальных malloc/pthread не выдаются за восстановленные
безопасные пути. Для очереди добавлен ready guard, включая повторное уничтожение.

**Ошибка unlock возможна после уже выполненного изменения очереди.** В новом
API это `VN135_FIFO_SYNC_ERROR`. Данные или счётчики к этому моменту могли
измениться. Такой возврат нельзя безусловно повторять. Тесты отдельно подтверждают
этот контракт; библиотека скрытых повторов не делает.

FIFO сам не блокируется. Queue использует переданный mutex. На протяжении жизни
объекта нужны одна пара allocator/free и один mutex, реальные доступные размеры,
неперекрывающиеся буферы и отсутствие неконтролируемых прямых записей в поля.

## 5. Сравнения с оригинальными инструкциями

| Основной новый набор | Случаев |
|---|---:|
| Восемь процедур FIFO, состояние и все байты хранилища | 8 748 |
| Семь queue-обёрток с настоящими исходными ring-процедурами | 2 977 |
| **Основные новые сравнения** | **11 725** |
| Состав предыдущего набора Stage 2–12 | 109 374 |
| **Состав набора Stage 2–13** | **121 099** |

Один случай — одна граница операции/состояния, не новая функция. Новый набор
прошёл GCC и Clang; повтор не увеличивает количество уникальных случаев.

FIFO-набор включает разные размеры, начало/конец кольца, пустоту, заполнение,
отбрасывание, reset и повторный destroy. Queue-набор использует настоящие 4096/72,
корректные явно заданные снимки состояния около границ и wrap отдельного слова.

Дополнительно, **не прибавляя к 11 725**:

- **72 композиции**: оригинальный producer Stage 7 продолжается через реальный
  `BL 0xfa5e0` по `0xc46fc`; далее выполняются оригинальные queue и FIFO. При
  извлечении сравниваются 68 полей и четыре непрозрачных байта. Chip/core остаются
  явно внедрёнными обработчиками, это не определение модели T21.
- **28 732 нативных сценария / 129 319 утверждений**: реальные malloc/free,
  независимая линейная FIFO-модель, переполнение, ошибки API/памяти/блокировок,
  rollback, повторное освобождение и 512 циклов pack/unpack.
- **11 офлайн-прогонов** при фрагментации RX от 1 до 11 байт: RX → кандидат →
  запись 72 байта → очередь → извлечение → заголовок → SHA256d/target. Вектор
  исторического первого блока взят из уже включённой проверенной Stage 9 фикстуры.
  Это известный nonce, не новый блок и не принятая пулом шара.
- **Двухпоточный тест pthread на 50 000 записях за запуск**: один producer и один
  consumer, порядок полученных номеров, все байты записи и равенство
  `получено + вытеснено = отправлено`. Число вытеснений недетерминированно.

Нативные последовательные и двухпоточные наборы прошли GCC/Clang ASan/UBSan
с `detect_leaks=1`. Это **не ThreadSanitizer**, не доказательство всех расписаний
и не запуск каждого Python/ctypes-сравнения под ASan.

### Ограничения эталона

Выполняются точные ARM-инструкции неизменённого ELF в прежнем локальном
ограниченном интерпретаторе. Набор инструкций не расширялся. Для выделения
4096 * 72 байт harness добавляет отдельную доступную область тестовой памяти.
Внешние malloc/free/memcpy и успешные mutex-функции внедрены; их реализации
не объявляются восстановленными. Решения full/drop/push/pop и изменение
состояния выполняются оригинальным кодом. Незнакомые инструкции и выход за
разрешённую память завершают проверку ошибкой.

## 6. Сборка и воспроизведение

```sh
make -f Makefile.recovery all arm stage13
make -f Makefile.recovery stage13-threaded
make -f Makefile.recovery stage13-clang sanitize-stage13
make -f Makefile.recovery evidence-check
python3 tools/verify_stage13_all.py --logs /absolute/path/outside-source --workers 2
```

Runner наследует все группы Stage 12. Наличие runner само по себе не означает
выполненный прогон. Финальный результат именно распакованного поставленного ZIP
передаётся отдельным логом/JSON. Группа `full-runtime` должна вернуть 2.

`evidence/stage13/recovery-manifest.json` хранит 17 диапазонов, из них один только
контекст вызова consumer, и 42 проверяемых ребра переходов/вызовов. Листинги
получены заново из исходного ELF, не из скомпилированного C. 15 процедур на валидных
состояниях и один producer-call проверяются отдельно от context-only участка.

## Текущее состояние

Компилируются **22 C-модуля**: 7 на наблюдаемых путях, 15 явно новых helper/adapter.
46 наблюдаемых путей производителя не превратились в полный список его файлов:
7 частично восстановлены, 39 по-прежнему исключены. Экспортировано 85 функций
нового API; это не число восстановленных оригинальных функций и не процент готовности.

Публичный upstream cgminer целиком по-прежнему не включён, его полная совместная
сборка не заявляется. Прежний additive overlay сохранён, имена/папки не объединены.
Результат — host и freestanding ARMv7-A/A32 hard-float библиотеки, не runtime-майнер.

Остаются владение внешними заданиями/пулами, актуальность заданий, полный consumer
и семантика хвоста queue-record, CRC ответов, выбор T21-драйвера, запуск хешплат,
питание/датчики/охлаждение/защиты, регистрация драйвера и автотюн.
**Штатный `/usr/bin/cgminer` этим комплектом не заменять.**

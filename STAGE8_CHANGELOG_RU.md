# VNishNet T21 AML 1.3.5 — Stage 8: SHA256d, target и выбор записи задания

**Модульная реконструкция, не готовый T21-майнер. Физическое оборудование, пулы и серверы не подключались.**

Продолжение Stage 7. Неизменённый ELF: 6 228 004 байта, SHA-256
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.

## 2. Полный SHA256d и порядок байтов

Оригинальная функция `0x2d994` читает 20 слов из первых 80 байт work, меняет порядок
байтов в каждом слове, считает SHA-256 от 80 байт, затем SHA-256 от полученных 32
байт. Результат записывается по `work + 0x120`. Оригинальная SHA-процедура —
`0x108f38`, с собственными compression/finalizer из ELF.

Новый API различает **сериализованный 80-байтный заголовок** и **80 исходных байтов
work с переставленными словами**. Это не взаимозаменяемые входы. Выход — 32 сырых
байта digest, без разворота для отображения. Оба API допускают перекрытие входа
с выходом: все нужные входные данные считываются до записи результата.

В сравнительных тестах полностью выполняются оригинальные hash-wrapper и SHA;
ожидаемый хеш не подставляется. Независимое сравнение — Python `hashlib`. Все
остальные байты тестового 632-байтного work должны остаться неизменны.

**Это не автоматическое продолжение 68-байтного кандидата Stage 7.** В потребителе
обнаружен вызов восстановления полного work по сохранённому шаблону (`0x300ac`).
Он ещё не перенесён. Для новых hash-функций вызывающий код обязан передать полный
80-байтный заголовок. Недостающие поля не дополняются нулями или догадками.

## 3. Target и предварительный фильтр — разные проверки

`0x10c1c` сравнивает восемь unsigned 32-битных слов от старшего к младшему.
На исследованной little-endian платформе это **hash <= target**, равенство проходит.
Новый переносимый API явно читает little-endian слова, не использует потенциально
невыровненные указатели `uint32_t *`. На месте вызова `0x327c8` передаются
`work + 0x120` и `work + 0x100`. Валидность значения target по правилам сети или
согласование сложности пула этой функцией не проверяются.

Ранее в frontend есть префикс `0x32f74–0x330a4`:

1. Равный предыдущему скалярному nonce отклоняется без вычисления хеша и мутаций.
2. Новый nonce сохраняется в last_nonce и записывается по `work + 0x4c` **до хеширования**.
3. Вызывается выбранная через function pointer процедура хеширования.
4. Старшее слово результата должно быть <= `0xffff` при числовом селекторе 1,
   либо равно 0 при остальных значениях.

Если последний фильтр отклонил результат, last_nonce уже изменён. Немедленный
повтор попадёт в duplicate-ветвь. Нулевой начальный last_nonce также отклоняет
nonce 0; новый API не добавляет отсутствующий у исходного поля флаг валидности.
Это описание локального контекста, не утверждение о глобальном обнаружении
дубликатов между заданиями или об ошибке реального T21.

Оригинальный hash-pointer берётся по смещению `+0x208`. В части тестов он
**явно выбран** равным `0x2d994`; это тестовая связка, а не доказательство выбора
этого callback моделью T21. Имена алгоритмов для числового селектора не придуманы.
Возврат `VN135_PREFILTER_CONTINUE` — проход только этого префикса, не accepted share.
Политика учёта и отправки после `0x330a4` не восстановлена этим этапом.

## 4. Три записи и проверка ссылки

Исследованный consumer-участок `0x74de4` ищет равенство 32-битного ключа по полям
`+0x278`, `+0x6f0`, `+0xb68`; шаг записей `0x478`. Ссылка расположена на четыре
байта дальше. Выбирается **первое** совпадение. При отсутствующей/непригодной ссылке
или нулевом поле по `reference + 0x1fc` поздние совпадения не пробуются.

Процедура `0x34d54` проверяет наличие этой ссылки в текущем массиве указателей:
возвращает 0 при наличии, 1 при отсутствии. Сравниваются указатели, их объекты
не разыменовываются. Оригинальные lock/unlock окружают поиск. Новый API принимает
согласованный снимок списка и требует внешней синхронизации, а не изображает
оригинальную глобальную таблицу и mutex. Счётчик <=0 сохраняет исходный результат
«отсутствует». При положительном count массив должен содержать как минимум count
доступных элементов; это не универсальный безопасный парсер произвольных указателей.

В 512 составных тестах выполняются **обе исходные процедуры** выбора и поиска,
а не только callback с ожидаемым ответом. Поле `+0x1fc` остаётся сырым словом;
ему не приписывается непроверенное название. Новые подробные коды ошибок —
диагностика API, в оригинале проверяется только путь continue/skip.

**Генерация задания, владение ссылкой, таймауты, переиспользование слота и
потокобезопасность всей очереди не доказаны.** Трёхэлементная выборка не заменяет
полный менеджер заданий. Queue ABI 72/68 из Stage 7 не меняется.

## 5. Воспроизводимые проверки

| Новые сравнения с оригинальными инструкциями | Случаев |
|---|---:|
| Полный SHA256d заголовка и неизменность прочего work | 305 |
| Target: все восемь решающих слов, равенство, unsigned-границы | 2 340 |
| Префильтр: результат, мутации и порядок вызовов | 883 |
| Изолированный выбор записи с внедрённым предикатом | 1 024 |
| Поиск ссылки (349) и совместная работа с consumer (512) | 861 |
| **Новые сравнительные случаи Stage 8** | **5 413** |
| Прежние Stage 2–7, повторённые на этой исходной базе | 96 439 |
| **Совокупный набор** | **101 852** |

Новые 5 413 случаев повторены на GCC и Clang; повтор не увеличивает число входных
случаев. В префильтре 752 случая проверяют границу с подставленным digest; ещё
131 используют выбор настоящей исходной SHA-функции, из них 3 — ранние дубликаты
без вызова SHA. Числа относятся к отдельным тестовым контрактам, не к числу функций.

Отдельно, не прибавляя к сумме: 198 C-проверок API/ошибок/памяти, 3 779 синтетических
проверок добавленной ARM-инструкции BLX register и 166 запусков офлайн CLI.
Неподдерживаемые Thumb/невыровненные BLX-цели вызывают ошибку интерпретатора.
Проверки ASan/UBSan и утечек выполнены на native C-наборах GCC/Clang, не на всех
Python/ctypes сравнительных случаях. Host и freestanding ARMv7-A/A32 hard-float
библиотеки собраны. Оригинальный ELF не запускался как Linux-процесс.

Ограниченный интерпретатор не является независимо сертифицированным CPU.
Внешние memcpy/memset/getter/logging/mutex подменяются. Стек для префильтра
устанавливается по прологу, VFP-сохранение пролога не исполняется. Границы остановки
явные; неизвестные инструкции, выход за память и исключения callbacks считаются
ошибками. Конкурентность, физический ARM и периферия не проверяются.

## 6. Наложение поверх обычного cgminer

После добавления `src/frontend/cgminer.c` реально воспроизведён конфликт объекта
с корневым `cgminer.c` при отключённом `subdir-objects`. В overlay включено
`AUTOMAKE_OPTIONS = subdir-objects`: исходные имена файлов сохранены, объекты
разнесены по каталогам. Automake-тест воспроизводит отказ без опции, затем строит
и линкует все 14 восстановленных единиц вместе с отдельным тестовым root main.

**Этот main — удаляемая тестовая фикстура, не симулятор/замена cgminer.** Он не
поставляется как исполняемый майнер. Реальная полная база `ckolivas/cgminer` пока
не включена и её совместная сборка не проводилась. Новая попытка сетевого скачивания
на Stage 8 не заявляется. Пин upstream и отказ перезаписывать исходные файлы сохранены.

## 7. Офлайн-утилита и команды

```sh
make -f Makefile.recovery all arm stage8
make -f Makefile.recovery stage8-clang sanitize-stage8
python3 tests/test_overlay_automake.py
```

`build/vn135-verify-header` принимает **160 hex-символов сериализованного заголовка**
и **64 hex-символа target в little-endian порядке байтов**. Печатает JSON с сырым
SHA256d, `meets_target`, `job_freshness_checked:false`, `submitted:false`.
Код выхода 0 означает завершённое вычисление, не истинность meets_target.
Некорректные длина/hex возвращают код 2. Нет сетевого доступа, UART, поиска nonce
или передачи шар. Это проверочная утилита, не cgminer и не аппаратный тест.

Полная проверка разделена на группы:

```sh
python3 tools/verify_stage8.py build --logs /absolute/path/outside-source
# Затем группы: core cache uart rx nonce clang-nonce
# verify-hash verify-target verify-prefilter verify-job verify-native
# clang-verify sanitizers automake evidence full-runtime-blocked
```

Для Linux PTY-нaборов требуется Linux. Для отдельной Automake-фикстуры нужны
Autoconf/Automake; для ARM-библиотеки — Clang/llvm-ar. Библиотека ARM не имеет Linux
sysroot и не является готовым ARM executable. Финальная проверка распакованного
ZIP передаётся отдельным логом/JSON, а не заменяется предыдущими протоколами.

## 8. Состояние и оставшиеся части

Наблюдаемых путей 46; частично восстановлены 7, исключены 39. Компилируется 14
C-файлов: 7 на наблюдаемых путях и 7 новых support/adapter-модулей. Это не процент
готовности полного закрытого проекта. Ни монолита, ни успешных функций-заглушек нет.

Не перенесены полное восстановление work из шаблона/coinbase/merkle, жизненный цикл
очереди и заданий, проверки их актуальности, сетевое принятие шар, T21 model dispatch,
аппаратный запуск/PLL/PSU/датчики/охлаждение/защиты, драйвер для upstream и автотюн.
Отдельные математические проверки SHA/target не отменяют эти ограничения.

**Не заменять штатный `/usr/bin/cgminer`. `full-runtime` продолжает намеренно
возвращать ошибку: полноценный исполняемый майнер не создан.**

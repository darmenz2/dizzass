# Профиль hwscan, системная передача TX88 и поздние ответы

## Результат и границы

Новый интеграционный слой читает файлы уже завершившегося hwscan, формирует
ограниченный аппаратный профиль, передаёт TX88 через настоящие Linux write/poll
и читает ответы через read и прежний разборщик. Задание остаётся настоящим
struct work; копирование, SHA256d, target и освобождение — из cgminer.

**Это не реализация физического hwscan и не готовый T21-драйвер.** Получение
нужной проекции профиля из JSON реализовано; сканирование платы, запуск питания,
настройка чипов/масок, CRC ответов и безопасный аппаратный reset не восстановлены.
Проверки работают с Linux PTY и синтетическим профилем, не физическим T21.

## Откуда взята схема

В исходном образе S12hwscan передаёт сканеру --platform из /etc/fw-info.json.
Сканер и cgminer содержат пути /var/run/hwscan/miner-model.json и hw-info.json.
Хеши оригинальных файлов и участков находятся в integration/evidence/hwscan_io.json.
Прошивка и hwscan не запускались как процессы.

Проверены оригинальные инструкции подготовки аргументов пяти json_unpack_ex:
корень miner-model, board, chip, корень hw-info, отдельная запись boards.
Оригинальный парсер не подменяется нашим: его запуск не заявляется. Выполняется
только подготовка ключей/форматов до вызова. json_object_get перехвачен, чтобы
зафиксировать board/chip; возвращает инертный указатель. Строки XOR декодированы
отдельно, их конструкторы на этом этапе не исполнялись.

Новый hwscan_profile.c использует уже имеющийся Jansson. Читает platform,
algorithm, chip.model, board.num_chips, num_boards, chip.uart_speed,
ver_roll_mask/ticket_mask, названия модели и boards[].id/model/status.
Поддержана только проекция AML + sha256d + BM1368 без bypass. Неизвестное
отклоняется; число чипов и скорость не подставляются из теста. Имя T21 не
проверяется как замена сканированию. Модель описания и обнаруженное имя сохраняются
раздельно: их строковое равенство не объявляется доказанным контрактом.

Маски сохраняются как метаданные, НЕ применяются к чипам. Полный профиль
питания, охлаждения, таймингов и частот этим типом не представлен. Готовность
платы status=ok в JSON — сообщение сканера, а не независимо проверенное железо.

## Чтение файлов

read_at получает открытые доверенные каталоги /etc и /var/run/hwscan. Используются
только фиксированные basename, openat с O_NOFOLLOW/O_CLOEXEC/O_NONBLOCK, регулярные
файлы, ограничение 256 КиБ. Дубли ключей, неверные типы, повторные ID, недопустимые
диапазоны и замеченные изменения файла отклоняются без публикации результата.
Дескрипторы и выделения освобождаются при отказах.

**Три файла не имеют доказанного общего номера поколения.** Повторная проверка
inode/размера/mtime/ctime обнаруживает изменения во время чтения, но не доказывает
атомарную публикацию комплекта. Вызывающий код обязан дождаться успешного окончания
сканера и исключить его повторный запуск на время чтения либо предоставить
заранее согласованный неизменяемый снимок. Новый код не запускает shell/hwscan.

## Настоящая передача

posix_tx88.c принимает уже открытый эксклюзивный O_RDWR|O_NONBLOCK UART, настроенный
raw 8N1, VMIN=1/VTIME=0, с точной скоростью профиля. Проверка termios2 не меняет
параметры. Устройство не открывается по угаданному пути. После создания канал
владеет dup-дескриптором; исходным больше нельзя пользоваться или менять его режим.

Пакет проверяется по фиксированным полям и CRC до записи. write вызывается
реально. При короткой положительной записи отправляется только остаток, не весь
кадр заново; старое errno после успешного write игнорируется. EINTR и EAGAIN
обрабатываются с CLOCK_MONOTONIC deadline через poll. Результат содержит точное
число подтверждённых syscall байтов и причину ошибки.

WRITTEN означает все 88 байт приняты ядром, **не физический ACK и не принятая
пулом шара**. Частичная/неопределённая отправка переводит запись в карантин и
навсегда останавливает программный канал: обрыв кадра может затронуть следующие
сообщения. NOT_SENT с timeout разрешает повторить ещё не использованный слот.
Ни tcflush, ни произвольная задержка не выдаются за очистку работы хешчипов.

## Смена задания и запоздавшие ответы

native_tx_channel.c сериализует передачу и приём одним mutex. При смене работы
прежний слот retire-ится ДО подготовки следующего. Это новая консервативная
политика, не объявленная точной копией планировщика VNish. Даже при последующем
отказе подготовки прежняя работа не возобновляется автоматически.

RX сохраняет частично собранный кадр при смене работы. Его окончание разбирается
с исходным wire-слотом и отклоняется, если слот уже retired, вместо переназначения
новому work. Эпоха неизменна на протяжении канала; чужая метка отклоняется до
чтения/потребления буфера. Объект результата владеет собственной native-копией.
Read ограничен одним новым чтением 128 байт за вызов, поэтому непрерывный мусор
не удерживает блокировку бесконечно. Отмена pthread отключена в критической секции.

После **32 успешных отправок — EXHAUSTED**, без скрытого wrap/reset. Оригинальные
инструкции 0xc4dbc..0xc4dd4 действительно увеличивают индекс modulo 32 ещё до
UART-вызова 0xc4ea8. Это НЕ доказывает отсутствие старого ответа на железе.
Новый канал не копирует такой wrap, пока не подтверждена аппаратная граница.

Stop дожидается текущей ограниченной операции, запрещает новые; **не останавливает
сам хешчип**. Уничтожение допускается после stop/join пользователей. Новый канал
не предоставляет resume/смену эпохи: создание следующего требует внешне доказанной
чистой аппаратной границы, а не сброса счётчика в программе.

## Проверки

- Пять оригинальных наборов ключей/форматов, 45 литералов и 32 перехода слота.
- Реальные PTY write/read: полный кадр, короткие записи, EINTR, сохранённое errno,
  обрыв после части кадра, timeout, закрытый терминал, неверный CRC/режим/скорость.
  Короткие записи и отказы задаются явными syscall-обёртками, переданные префиксы
  физически проходят через ядро PTY. Отдельно заполняется настоящая очередь PTY
  до EAGAIN для проверки kernel backpressure, без подмены poll в этом сценарии.
- Настоящий Jansson и read_at: корректный профиль, неверные поля/типы/платформа,
  дубли, symlink, FIFO и слишком большой файл. Тестовый профиль не является
  захватом реального T21. Отказы каждого malloc/read отдельно не перебирались.
- Настоящий cgminer + PTY: 32 TX88, 32 известных nonce, 31 ответ с началом ДО
  смены работы и концом ПОСЛЕ, ещё один ответ старого слота после исчерпания;
  33-я работа не передаётся; чужая эпоха не потребляет данные; копия переживает
  destroy. Отдельный префикс 7 байт + EIO останавливает весь канал.

Команда после обычной host-сборки:

```sh
make -f Makefile -f integration/hwscan-io.mk dizzass-hwscan-io-test
make -f Makefile -f integration/hwscan-io.mk SANITIZE=1 dizzass-hwscan-io-test
make -f Makefile -f integration/hwscan-io.mk CC=clang DIZZASS_HWIO_DIR=build/hwscan-io-clang DIZZASS_ROUTE_DIR=build/hwio-route-clang DIZZASS_JOBS_DIR=build/hwio-jobs-clang DIZZASS_NONCE_DIR=build/hwio-nonce-clang dizzass-hwscan-io-test
```

Факт прохождения смотрится по журналу конкретного commit. ASan/UBSan и Clang
покрывают новые объекты, интеграционные зависимости и включённый root cgminer.c,
но не все ранее собранные библиотеки. TSan и полный конкурентный stress нового
канала не выполнялись. Настоящий сетевой submit в новом тесте не запускается.

Production Makefile.am, ядро cgminer, reference ELF и исторический инвентарь
не изменяются. Новые файлы собираются отдельной целью. **Не устанавливать вместо
штатного cgminer: физический профиль, запуск/защиты и непрерывный аппаратный
оборот заданий всё ещё требуют завершения и испытаний на стенде.**

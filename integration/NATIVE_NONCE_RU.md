# Нативный адаптер nonce — следующий шаг после cgminer-first

`integration/native_nonce.c/.h` соединяет декодированные поля аппаратного ответа
с **настоящим `struct work` из корневого `miner.h`**. Это новый интеграционный
интерфейс, не новый майнер и не ABI закрытой прошивки.

## Путь данных

```
Уже выделенный обычный nonce-payload, 7/8/9 байт
  → аппаратное извлечение slot / nonce_word / version_bits
  → сопоставление с явно переданным удерживаемым native work
  → native copy_work_noffset(work, 0)
  → native test_nonce(copy, nonce_word)
  → native fulltest(copy->hash, copy->target)
  → собственная копия результата; native free_work при очистке
```

Нового SHA, расчёта target, coinbase/Merkle, сетевого стека и 632-байтного
параллельного work нет. Исходный work и его строки не изменяются. Копия хранит
общую ссылку на pool по штатным правилам cgminer — это НЕ удержание всех внешних
объектов и не новый refcount.

Перед копированием проверяются chain, slot, variant и соответствие версии.
Нельзя брать текущий job только потому, что совпал пятибитный slot. Вызывающая
сторона обязана передать точно сопоставленное живое задание и удерживать его
пул/шаблон. Этот этап не реализует slot-registry, поколения или stale-политику.

## Версия и endian

Аппаратное извлечение перенесено из сохранённых Stage 6/7, с числовыми селекторами
без присвоения им названий моделей. Специальный register-only режим не допускается
к этой функции вызывающим приёмником. Отсутствует новая проверка CRC.

`nonce_word` — число для `test_nonce`, а не обещание прямого равенства значению
nNonce, напечатанному обозревателем. Root cgminer хранит заголовок с перестановкой
байтов внутри слов. Для контрольного исторического вектора используется именно
подтверждённое представление `work->data`.

`version_base_word` должен происходить из задания, реально кодируемого для
хешплаты. Исследованный ответ даёт `base | version_bits`. Адаптер требует, чтобы
это равнялось LE-чтению первых четырёх байт удерживаемого native work. При
несовпадении он не подменяет версию и не пытается самостоятельно реконструировать
другой job. Согласование version-rolling с пулом и новый encoder пока отсутствуют.

`passes_diff1` и `meets_target` — две независимые математические проверки.
Код 0 означает выполненную проверку, не принятую пулом шару. Нет вызова submit,
изменения статистики/last_nonce, дедупликации или проверки актуальности.
Повтор той же проверки разрешён. Для дальнейшего runtime нужен штатный
submit_nonce-путь с правильным жизненным циклом, не слепой submit_tested_work.

## Проверки

После обычной Autotools-конфигурации и сборки:

```sh
make -f Makefile -f integration/native-nonce.mk dizzass-native-nonce-test
make -f Makefile -f integration/native-nonce.mk SANITIZE=1 dizzass-native-nonce-test
```

Тестовая единица включает **исходный корневой cgminer.c**, переименовывая main
только на время сборки теста. Типы, make_work/copy/free, test_nonce, sha256 и
fulltest не подменяются фикстурой. Остальные зависимости берутся из настоящей
сборки upstream. Сохранённые RX-процедуры используются только для сравнения и
подачи фрагментов в тесте; лишние секции отбрасываются линкером. Проверка nm
запрещает recovery SHA/frontend/work-функции в тестовом бинарнике.

Набор включает 2700 сравнений аппаратного декодирования с сохранёнными
процедурами, 11 фрагментаций исторического RX-вектора, ошибки сопоставления,
неизменность оригинала, независимость строк, повторную очистку, равенство target
и 128 вычислений настоящего cgminer с независимой проверкой Python hashlib.
Числа описывают набор; прохождение подтверждается только конкретным журналом CI.
Сетевые socket/connect и libusb_init обёрнуты аварийными отказами в тесте.

Sanitizer-цель инструментирует новый адаптер, тестовую единицу с native cgminer.c
и объекты RX. Прочие ранее собранные upstream-объекты остаются без инструментирования;
это не заявление о проверке всех зависимостей ASan/UBSan или полной отсутствии гонок.
Штатные core allocation helpers сохраняют fail-fast поведение при OOM.

## Граница интеграции

`Makefile.am`, штатное ядро, Stage 14, эталонный ELF и его инвентарь не изменяются.
Адаптер пока собирается отдельной целью, не регистрирует T21 и не включается
автоматически в исполняемый майнер. Основная native-сборка по-прежнему отделена
от исторической recovery-библиотеки. Все аппаратные тесты, привязка модели,
кодирование заданий и цепи/PSU/защиты/автотюн остаются отдельной работой.

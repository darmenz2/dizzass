# 1.3.5: мультиплексированная температура и общая остановка

База изменения: `40066b09fdca72f03233d546ccd551cebe27c1c1`.
Продолжается извлечение поведения сохранённой 1.3.5. Новая политика датчиков,
охлаждения, отключения питания или майнинга не создаётся. Это отдельная
офлайн-цель; производственный cgminer и ограничения слотов не изменяются.

## Уточнение следующего этапа: аргумент SMBus

Исследование нижних AML-функций установило, что последний скаляр вызовов
`fe440/fe518` — селектор протокола SMBus, а не количество байтов.
BYTE_DATA использует один байт; WORD_DATA — два. Send Byte передаёт
значение в поле команды и допускает NULL data. У raw-путей `fe528/fe538`
сохраняется отдельная семантика действительной длины. Исторические тесты ниже
меняли только первый значимый байт; новые составные проверки исполняют
оригинальные reader и SMBus и проверяют двухбайтные результаты.
См. `TRANSPORT_MONITOR_135_RU.md`. Остальная историческая область проверок
не расширяется автоматически этим уточнением.

## Что перенесено

| Полный управляющий путь синхронного чтения температуры | `0xb5f40` | `src/backend/temp.c` |
| Инициализация непосредственно опрашиваемого датчика | `0xb5d90` | тот же файл |
| Общая последовательность завершения майнера | `0x5fc54` | `src/backend/base.c` |
| Тело отдельного потока аварийного завершения | `0x72ba4` | тот же файл |

Это четыре целые точки входа через явно обозначенные границы нижних вызовов.
Ранее перенесённые ограниченные readers остаются неизменными как исторические
цели сравнения. В новой функции переиспользуется существующая обработка
показаний, в остановке — существующая процедура PSU OFF и сброса цепей.
Второе ядро cgminer, собственный SHA, Stratum или `struct work` не добавлены.

Прежние префиксы обоих файлов сохранены побайтно и проверены по точным Git blob.
Исходные пути этих модулей установлены предыдущими этапами. Новые C-имена и
типизированные структуры — проекции известных полей, не восстановленный vendor ABI.
Хеши ELF, диапазонов, литералов и исходных версий файлов — в evidence JSON.

## Синхронное чтение: теперь с мультиплексором

Сохранены все развилки именно этой функции: маршруты платы, прямого регистра,
платформенного транспорта и мультиплексора. Неподдержанный этой функцией тип
доступа возвращает исходную ошибку. Это не означает, что соответствующий
асинхронный механизм отсутствует во всей прошивке.

Удалённый канал при типе доступа, отличном от 4, вызывает исходную диагностику,
перевод датчика в состояние отказа и завершение до захвата блокировки шины.
Для типа 4 сохранена последовательность:

```
Снять выбор канала мультиплексора
  → выбрать канал датчика
  → записать и проверить конфигурацию датчика
  → исходные ожидания
  → прочитать локальное показание
  → при исходных условиях прочитать удалённое показание
  → снять выбор канала
  → обработать результат существующей процедурой показаний
```

Три внешние попытки не заменены бесконечными повторами. Внутри настройки есть
свой предел в три попытки. Сохранены места ожиданий после отказов, включая
отдельную задержку при ошибке финального снятия выбора. Ошибка последней операции
может повторить весь обмен. Счётчик ошибок датчика увеличивается один раз после
неудачи всей операции, а не за каждую внутреннюю попытку.

Номер канала преобразуется исходным регистровым сдвигом: используется младший
байт номера; сдвиг от 32 даёт ноль, затем значение ограничивается байтом.
Эти пограничные результаты не заменены новой проверкой номеров каналов.

Успешная проверка конфигурации очищает прежний флаг расширенного диапазона.
Синхронные байты расширяются со знаком; смещение 64 вычитается с байтовым
переполнением там, где это делает оригинал. Асинхронный обработчик предыдущего
этапа с беззнаковыми байтами не изменялся.

### Исходная поправка только для отдельного профиля

Исполнением оригинального конструктора строк получен внутренний тег
`u3s21exph`. Для соответствующего сочетания тега, удалённого канала и поля
питания применяется исходный коэффициент binary64 `0x1.2666666666666p+0`
и поправка из таблицы конкретного датчика. Порядок: отдельное умножение,
сложение с отрицательной поправкой, исходное преобразование в signed32.
FMA не используется. Поиск записи таблицы остаётся явным callback.

Этот тег не переименован в T21, коэффициент не распространяется на другие
модели. В остальных соответствующих ветвях вторым значением остаётся локальное
показание — отдельную «улучшенную» обработку удалённого канала не добавляли.

### Важная граница нижнего транспорта

Восстановлены идентичности вызовов, адреса, регистры, управляющие аргументы и
порядок. Значения длины в разных исходных helpers имеют разные соглашения.
Например, передаваемая длина 2 в одной ветви включает регистр, тогда как доступен
один байт данных. Нельзя автоматически превратить эти вызовы в `read(fd,p,n)`.

В этой проверке read-callback изменяет только первый значимый байт, остальные
байты scratch сохраняются. Семантика дополнительных выходных байтов и полные
тела низкого транспорта не доказаны. Явный scratch исключает неопределённые
чтения новой C-памяти, но не превращает неизвестный транспортный ABI в готовый.
Полнота управляющего пути не означает полноту физических транзакций.

## Проверка отправки запросов: существенное отрицательное доказательство

Выполнены оригинальные диспетчер чипа и инициализатор его таблицы для селектора
BM1368, а не только поиск текста. Четыре выбранные температурные операции —
подготовка доступа, чтение регистра, запись регистра и завершающая настройка —
в этом оригинале состоят из `mov r0,#0; bx lr`.

**Эти конкретные методы не записывают данные и не отправляют команды.** В C не
добавлялись новые успешные заглушки: результат оформлен как воспроизводимый аудит
оригинальных инструкций. Проверены 15 сочетаний выбора таблицы и 16 исполнений
четырёх листовых процедур с разными исходными регистрами и памятью.

Смещения методов относительно таблицы — c0/c4/c8/cc; в исходном backend таблица
находится по +110, что даёт поля +1d0/+1d4/+1d8/+1dc. Путать относительные
смещения этих двух объектов нельзя.

Это НЕ доказательство отсутствия любых температурных запросов в 1.3.5,
НЕ физическое подтверждение конфигурации T21 и НЕ полный перенос общего RX-worker.
Сам обработчик декодированных ответов из предыдущего этапа существует отдельно.
Универсальную отправку запросов через общий поток пока не объявляем законченной.

## Общая остановка: восстановлено тело, а не один вызов OFF

Поток аварийного завершения задаёт исходное имя `failure@btm`, отсоединяет
себя, вызывает общую процедуру завершения и возвращает исходный ноль.
Строка имени проверена по байтам сохранённого XOR-литерала; её конструктор в
этом наборе не исполняется. Рабочий поток физически не создаётся.

Общая процедура:

```
Выбрать путь маркера остановки
  → дождаться блокировки, сохранив исходные повторы
  → проверить прежнее состояние майнера
  → завершить выбранные рабочие потоки в исходном порядке
  → выполнить исходные вызовы очистки цепей и backend
  → вызвать существующее отключение PSU и сброс цепей
  → дождаться отдельного завершающего потока
  → выполнить оставшиеся вызовы индикации
  → записать состояние остановки и запросить запись маркера
  → снять блокировку
```

Девять условных позиций потока используют исходную развилку self-detach либо
cancel + join. Флаг очищается до запроса идентификатора текущего потока;
handle после cancel перечитывается. Последняя отдельная позиция использует
только join с выходным значением, уже после вызова отключения PSU.
Условия выбора первых двух позиций зависят от исходных селекторов.
Назначение всех потоков по догадке не переименовано в «температуру» или «UART».

Возвраты отмены/ожидания, очистки и записи маркера оригинал в этих местах
игнорирует. Новые тайм-ауты, повторное отключение и откат не добавлены.
В нескольких начальных состояниях существенная часть завершения пропускается.
Ожидание блокировки не получает придуманного предела: тестовый контракт требует
её конечного получения; зависание реального потока этим не исключается.

**Ошибка существующей процедуры отключения питания не препятствует записи
общего состояния «остановлен» и маркера.** При этом ранее сохранённые поля
питания могут остаться в состоянии ON. Этот случай проверяется отдельно.
Новый общий интерфейс объявлен `void`: регистру возврата исходной общей
процедуры не приписывается смысл электрического успеха. У worker собственный
возврат 0 сравнивается с оригиналом; у общей процедуры сравниваются состояние
и последовательность действий, а не побочное значение r0 после служебной арифметики.

В тесте действительно исполняется ранее восстановленное тело PSU-off caller,
но сами PSU OFF и reset остаются явно заданными результатами. Тела ряда
внутренних cleanup/backend-действий также не завершены. Наличие общей остановки
не доказывает исчезновение напряжения, разряд платы или отсутствие старых nonce.
Ограничение повторного использования аппаратных слотов не изменено.

## Проверки

* Синхронный reader и его initializer: **1 870 сравнений / 37 781 событие**.
* Общая остановка и worker, включая оригинальный power-stop: **581 сравнение /
  28 735 событий**. Сравниваются снимки флагов, handles и полей в точках вызовов.
* Аудит BM1368: **15 выборов таблицы и 16 исполнений исходных no-op методов**.
* Нативный C-набор: **7 212 сценариев / 103 995 утверждений**, включая canary
  вокруг объектов, все байты показаний, состояния, ошибки, каналы, границы буферов,
  порядок выключения и 256 значений флагов активности потоков.
* Локальные добавления модели инструкций: **84 проверки VNMLS.f64** и
  **360 побитных проверок VLDR одного S-регистра**, включая алиасы, старшие
  регистры, знаковый ноль, направления адресации и сохранение флагов/регистров.

Основных новых C/ARM-сравнений **2 451**, отдельно — аудит выбора методов.
Повторы компиляторами не увеличивают число уникальных сценариев.
Используется ограниченный интерпретатор, не независимая сертификация ARM.
Числовая область — конечные binary64 с обычным округлением; NaN/Inf, исключения
FPSCR и иной режим округления не проверялись. VLDR проверяется побитно, без
числовой интерпретации загружаемых значений. VNMLS не слитная FMA.

Нативные санитайзеры инструментируют выбранные C-модули и тестовый harness,
не Python-интерпретатор, ctypes-набор или весь cgminer. ОС, часы, шины и pthread
эффекты в сравнении задаются сценариями, не исполняются на контрольке.

Фактически выполнены новые сравнительные и нативные наборы на GCC 14.2 и
Clang 17; нативные ASan/UBSan прошли на обоих. Статический анализ Clang завершился
без диагностик. Прежние GCC-регрессии также прошли: температурные процедуры
1 766 сравнений / 2 835 native-сценариев / 253 сценария аварийного обдува;
маршруты и остановка цепи 3 336 сравнений / 1 831 native-сценарий;
resume 1 335 сравнений / 332 native-сценария. Исторические флаги scope в JSON
старых тестов не являются новым глобальным инвентарём готовности.
Результаты находятся в отдельном журнале и сводке выполнения. Workflow в этом комплекте только подготовлен;
новый GitHub Actions этим этапом не запускался и коммит не опубликован.
Рабочая папка собрана из архивов. Устаревший архивный header подготовки backend
обновлён локально до проверенного Git blob; это не изменение репозитория.
Полный свежий git checkout и сборка всего native cgminer не выполнялись.

## Запуск проверок и остаток

```sh
make -f integration/thermal-completion-135.mk dizzass-completion135-original dizzass-completion135-route dizzass-completion135-test
make -f integration/thermal-completion-135.mk SANITIZE=1 dizzass-completion135-test
```

Патч требует полной базы репозитория с прежними reference/tools и заголовками.
Включение выполняется только явными `VN135_THERMAL_READER_135` и
`VN135_BACKEND_SHUTDOWN_135` в отдельной тестовой цели. Корневой `Makefile.am`,
main cgminer, пулы, devfee и существующие защитные адаптеры не меняются.

Остаются: нижние соглашения и тела транспорта, полный общий мониторинг/RX-worker
с формированием измерительных запросов, внутренние cleanup-действия, физический
профиль и замкнутая интеграция с native-драйвером. Критерий отключения оборудования
и безопасного оборота слотов ещё требует отдельного доказательства.
**На T21 не устанавливать вместо штатного cgminer.**

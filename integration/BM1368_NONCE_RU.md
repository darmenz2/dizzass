# BM1368: привязка внутренних селекторов и определение чипа/core из nonce

## Что подтверждено по оригинальному ELF

Выполнен ограниченный участок исходного разбора названия чипа и отдельно
числовой диспетчер. Получена карта: BM1360=0, BM1362=1, BM1398=2, BM1366=3,
**BM1368=4**, BM1370=5, BM1489=6, BM1491=7. Неизвестное имя даёт 8.
Это значения перечисления прошивки, не номера физических цепей.

Для селектора 4 оригинальный диспетчер `0xd2760` вызывает `0xe4600`,
а `0xd280c` — `0xe4688`. В тестах исполняются сами диспетчеры, чтение
оригинальных глобальных переменных и обе процедуры; их результаты не
подменяются обработчиками. Количество чипов задаётся как входной снимок.

Также найден пропущенный прежним сканированием путь:
`/tmp/build/libbitmain/src/chip/chip1368.c`. Он получен выполнением оригинального
конструктора `0xe5408..0xe54cc`, который декодирует 42 байта по `0x5eb3e7`.
На эту строку ссылается диагностическая ветвь chip-helper. Поэтому новый C-файл
размещён на наблюдаемом пути `libbitmain/src/chip/chip1368.c`, а не в выдуманном
драйвере T21. Это **частичное восстановление файла**, не все его исходники.
Исторический инвентарь Stage14 и его контрольные суммы не переписаны.

## Реализовано

`dizzass_bm1368_locate()` получает внутренний селектор, согласованное количество
чипов и `nonce_word` из существующего `dizzass_nonce_decode_payload()`. Возвращает
вычисленные chip/core. Для проверенного диапазона количества чипов 1..256:

```
field = (nonce_word >> 9) & 0xffff
chip  = ((field * chips_per_chain) >> 16) & 0xff
core  = nonce_word >> 25
```

Это восстановленные вычисления, а имена C-интерфейса и проверки входов — новые.
При неизвестном селекторе, недопустимом количестве или NULL выхода результат
не публикуется. Диапазон 1..256 — контракт данного API, **не список поддержанных
реальных хешплат**. Непроверенная запасная ветвь оригинала для неверного индекса
не переносится; нет случайной подстановки номера чипа.

Nonce уже имеет нужный порядок байтов после существующего RX-декодера.
Дополнительный byte-swap дал бы неправильную атрибуцию. Это проверено составным
выполнением исходного участка RX `0xc4588..0xc45c4`: выбор смещения, REV,
диспетчеры и вычисления chip/core. В этой композиции нет внешних подмен.

## Связь с настоящим cgminer

Отдельная тестовая цель соединяет восстановленный потоковый RX, существующий
native nonce adapter, новый BM1368-helper и настоящий `struct work`/`test_nonce`/
`fulltest`/`free_work`. Новые SHA, target, Stratum и представление work не создаются.
Исходное задание остаётся неизменным; результат держит собственную native-копию.

Синтетический nonce известного исторического блока проверяется при 11 вариантах
фрагментации кадра. Количество 108 в этом тесте — **параметр теста**, не утверждение
о числе чипов конкретного T21. Отдельно проверяются 96 произвольных native RX
payload для трёх форматов, сверяемых с оригинальными инструкциями.

## Проверки и воспроизведение

Чистая функция: 2850 сравнений с оригинальным диспетчером, 288 составных RX
сравнений, 20 проверок карты селекторов/номеров, 13 неверных входов. При проверке
карты имён подменяется только strcmp, а литералы декодированы явно; полный
JSON-парсер и сканер железа не запускаются. Конструктор строки пути исполняется
отдельно оригинальными инструкциями. Есть 33047 нативных C-утверждений о диапазонах
и сохранности памяти. Большие счётчики не означают готовность полного драйвера.

После нормальной сборки cgminer:

```sh
make -f Makefile -f integration/bm1368-nonce.mk dizzass-bm1368-differential dizzass-bm1368-bounds dizzass-bm1368-native-test
make -f Makefile -f integration/bm1368-nonce.mk SANITIZE=1 dizzass-bm1368-bounds dizzass-bm1368-native-test
make -f Makefile -f integration/bm1368-nonce.mk CC=clang DIZZASS_BM1368_DIR=build/bm1368-clang DIZZASS_NONCE_DIR=build/native-nonce-clang dizzass-bm1368-differential dizzass-bm1368-native-test
```

Workflow `bm1368-nonce.yml` проверяет эти сценарии и неизменность production-ядра.
Санитайзеры покрывают новый модуль, native-адаптер/RX и тестовую единицу с root
cgminer.c; не все ранее собранные зависимости. Аналогично Clang пересобирает эти
единицы, а не весь upstream. Фактическое прохождение устанавливается по журналу
конкретного commit, не по наличию теста или этому описанию.

## Что пока НЕ установлено

**Полная привязка T21 к этой ветви пока не доказана.** Установлена связь
`название BM1368 -> селектор 4 -> оригинальные helpers`, но фактическое описание
конкретного устройства приходит из hwscan и его runtime-конфигурации. Не следует
подменять это жёстким `T21 -> 4` или считать любой неизвестный аппарат BM1368.

Также не установлены выбор отправителя TX86/TX88 для устройства, соответствие
ID передачи пятибитному RX-слоту, безопасное повторное использование заданий,
CRC ответов, запуск цепей, PSU и защиты. Новый модуль не меняет эти ограничения
и не позволяет обходить карантин/эпохи существующего реестра.

Нет команд аппаратуре, изменения питания, прошивки NAND, сетевой отправки шар
или регистрации T21. Вычисление chip/core не доказывает корректность самого
nonce и не даёт принятую пулом шару. **Это не готовая замена штатного cgminer.**

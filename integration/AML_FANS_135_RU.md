# 1.3.5: нижний AML-драйвер вентиляторов

База: `9b3924d0f5a75bd1d1ae24fcfd368d30cd0eb1c7`.
Переносится поведение оригинала, не проектируется новая политика охлаждения.
Это следующий нижний слой после уже восстановленного опроса состояния backend.
Ядро cgminer, существующий backend, PSU, защитные адаптеры и слоты не меняются.

## Что восстановлено

Впервые добавлен подтверждённый путь `libbitmain/src/aml/fan_ctrl.c`.
Конструктор зашифрованных строк выполняется оригинальными инструкциями и
даёт `/tmp/build/libbitmain/src/aml/fan_ctrl.c`. Начальная часть платформенного
диспетчера выполняется для AML; пять адресов её таблицы сверяются отдельно.
Это подтверждение выбора программной ветви, не испытание любой ревизии T21.

| Назначение | Исходный вход |
|---|---|
| Создание потока считывания оборотов | `0x118444` |
| Полное тело цикла считывания счётчиков и расчёта оборотов | `0x1184fc` |
| Задание PWM обоим каналам | `0x1189dc` |
| Задание PWM отдельному каналу | `0x118a04` |
| Чтение сохранённой аппаратной настройки PWM | `0x118cc8` |
| Выдача кэшированных оборотов по индексу | `0x11910c` |
| Остановка потока считывания | `0x119258` |

Это семь исходных точек входа, включая внутреннее тело рабочего цикла.
Операции ОС, времени и потоков представлены явными обязательными callbacks.
Нет встроенных успешных аппаратных заглушек. Интерфейс в `aml_fans_135.h` —
новые типизированные проекции, не vendor ABI и не бинарно совместимые структуры.

## Управление: два канала PWM

Оригинал обращается к каналам 0 и 1 в `/sys/class/pwm/pwmchip0`.
Порядок одной установки: открыть enable, period, duty_cycle; взять блокировку;
записать enable=0, period=100000, вычисленный duty_cycle, enable=1;
снять блокировку; закрыть открытые файлы. Значение ограничивается диапазоном
0..100. Внутри этого диапазона управляющее число duty_cycle равно проценту,
умноженному на 1000. Константы исходные, не рекомендуемые настройки стенда.

Все три открытия выполняются даже при отказе первого. Если одно не удалось,
записей настройки нет, но доступные handles закрываются. Возвраты fprintf,
блокировок и fclose не проверяются. Второй PWM-канал обрабатывается даже после
отказа первого. Новые повторы, откат и остановка при ошибке не добавляются.

Getter читает только period и duty_cycle канала 0, не оба канала и не enable.
При ошибке открытия возвращает 0. Пустой/нулевой period заменяется на 100000;
возвраты fscanf игнорируются. Умножение duty_cycle на 100 сначала переполняется
в 32 битах, затем выполняется **знаковое** деление и ограничение 0..100.
Нулевой результат сам по себе не различает ошибку чтения и настоящую настройку.

## Измерения: четыре счётчика, не четыре PWM-выхода

Worker именуется `fans@btm`, открывает `/proc/interrupts` и повторно читает его.
Он ищет подстроки меток 27, 26, 28, 29 вместе с `gpiolib`; это метки счётчиков
из данного образа, не доказанные номера физических GPIO каждого T21.
Используется первый числовой столбец, другие столбцы CPU не суммируются.
Сохранён поиск подстроки: например, строка с 127: также может совпасть с 27:.

Если предыдущее значение счётчика равно нулю, оно сначала заменяется новым:
такая выборка даёт нулевые обороты. В остальных случаях используется разность
нового и прошлого счётчика. Точная арифметика с 32-битным переполнением:
`((delta * 15u) << 2) >> 1`. Без переполнения это delta * 30, но безусловно
заменять исходную последовательность таким умножением нельзя.

После каждого полного прохода запрашивается ожидание 1000 мс. Фактическое
время не измеряется, нет нормализации по реально прошедшему интервалу.
Отсутствующая строка **не обнуляет старые обороты**. Getter только отдаёт кэш,
не проверяет свежесть. При неудачном открытии файла worker обнуляет четыре
пары счётчиков/оборотов, но не очищает прежний running или handle потока.

Инициализатор лишь вызывает создание потока: успешный возврат не доказывает,
что worker открыл файл или получил первую выборку. Остановка при running=0
вообще ничего не делает. При ненулевом running сначала записывается ноль;
текущий поток отсоединяется, иной вызывающий запрашивает cancel и join.
После cancel handle перечитывается. Ошибки этих операций игнорируются.
Остановка не очищает кэш/handle и не записывает PWM.

## Область эквивалентности и ограничения

Все используемые объекты и callbacks должны быть корректны. Handles — явные
32-битные значения для сравнения, не pthread_t/FILE ABI компьютера.
Matched-строка счётчика должна иметь двоеточие, допустимый токен и следующий
ASCII-пробел внутри строки. У оригинального разбора есть неограниченный поиск
разделителя; некорректные совпавшие строки этим переносом не исправлены и не
входят в проверенную область. Это не безопасный парсер произвольного ввода.

Состояние меняется синхронно на явно заданных границах callbacks. Исходный
несинхронизированный running не превращён в новый atomic-протокол. Гонки,
реальный cancel/join, электрические фронты PWM и точность оборотов не проверены.
Вместо pthread_exit выполняется явная терминальная граница и возврат тесту:
последующие байты исходной функции не исполняются как продолжение потока.

## Что проверено

Основной набор: **2605 сравнений / 16848 событий** за прогон:
инициализация 30, отдельный PWM 449, оба PWM 114, чтение PWM 315,
выдача оборотов 40, рабочий цикл 110, остановка 1547.
Сравниваются возвраты значимых функций, полное выбранное состояние и порядок
всех внешних вызовов. Исходные вложенные PWM-вызовы, цикл worker, преобразование
счётчика и знаковое деление действительно исполняются, не заменяются успехом.

Нативный набор: **1144 сценария / 28641 утверждение**, границы состояния,
частичные открытия, ошибки записей/чтения, все 256 значений running, повторные
измерения, сохранение старого кэша и перечитывание handle после cancel.
GCC/Clang и ASan/UBSan покрывают новый C-модуль и нативный набор. Санитайзеры
не проверяют Python-интерпретатор, ctypes-сравнения и весь майнер.

Исторические интерпретаторы не меняются. Локальный подкласс добавляет только
неокруглённую A32-инструкцию SMMUL; её модель проверена 64 арифметическими
фикстурами со знаковыми границами, совпадением регистра назначения и источника,
неизменностью флагов. Это не независимая сертификация ARM-эмулятора.
ELF, диапазоны кода, таблица меток и зашифрованные литералы закреплены SHA-256.

```sh
make -f integration/aml-fans-135.mk dizzass-fans135-original dizzass-fans135-test
make -f integration/aml-fans-135.mk SANITIZE=1 dizzass-fans135-test
```

Локальная папка использует сохранённый Stage14 для reference/tools, а не полный
актуальный Git checkout. Новые модули собираются автономно; старый backend не
переписывается. Проверка общего дерева и прежней подготовки в CI определяется
журналом конкретного коммита, не наличием этого текста или workflow.

## Следующее незакрытое место

Остаются верхняя инициализация записей вентиляторов, общий контроллер регулировки,
температурные датчики, аппаратные аварийные пути и их связь с native-драйвером.
Опрос backend уже восстановлен ранее, но прямое производственное связывание
этого нового AML-модуля с ним пока не добавлено. Полное охлаждение не объявляется
готовым. Автотюн, запуск хешцепей и оборот слотов этим этапом не изменены.
**Физический T21 не участвовал; вместо штатного cgminer не устанавливать.**

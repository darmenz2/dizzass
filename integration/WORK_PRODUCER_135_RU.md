# B-06: пакетный producer из `0xc2498`

Задача [#23](https://github.com/darmenz2/dizzass/issues/23), координация
[#2](https://github.com/darmenz2/dizzass/issues/2). База
`12446bed78a060a49364a80bcbfb4340b13f4f27`, ветка `codex/work-producer-135`.
Изменения ограничены десятью новыми файлами. Старые функции, интерфейсы,
production-сборка и области других исполнителей не меняются.

## Что реализовано

`vn135_work_producer_batch_135` восстанавливает участок `c2970..c2e80`:
количество итераций, проверку и повторное чтение индекса очереди, подготовку
coinbase/Merkle, 168 байт строки и публикацию индекса. Это **не весь `c2498`**.
На вход передаются уже захваченный локальный шаблон и отдельная копия счётчика.
Захват/смена шаблона, очистка, запуск потока, timed wait/cancellation и выход
из потока остаются вне этой реализации. Сигнал после смены шаблона за адресом
`c2e80` тоже не входит в неё. Нет зависимости от ожидающих review PR B-04/B-05.

Использованы неизменённые `vn135_sha256d_bytes` и `vn135_sha256_compress_block`.
Новый SHA, target, Stratum или ядро майнера не добавлены. Имеющийся frontend
prefix похож по назначению, но его счётчик меняется до хеширования, а оригинал
освобождает временный coinbase до Merkle-ветвей и увеличивает счётчик после
публикации. Поэтому prefix не подставляется вместо этой последовательности.

## Источник и доказательства

Архив пользователя `vnishnet-t21-aml-nand-v1.3.5.tar.gz`:
SHA-256 `20fabdd66255889315e61ae2a33ff2e4623566ca430f1cb8c90d9b938dc7b43c`.
Повторно извлечённый `usr/bin/cgminer` (6 228 004 байта) совпал с reference:
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.
ELF — данные, его процесс не запускался.

Ghidra 12.1.4 с JDK 25.0.4.1 использована фактически; полные C/asm/script/log
сохранены в `integration/evidence/work_producer_135.json`. Анализ ARM:LE:32:v8
не доказывает модель CPU, типы декомпилятора предварительны. A32 disassembly
уточняет порядок вызовов, размеры и адреса. Восемь диапазонов ELF закреплены
хешами; соседние `5ccf4/5cd70/5ce44/c2f6c` сохранены как контекст, не как
реализованные функции. IDA Free не использовалась для ARM-анализа.

Oracle начинает выполнение **оригинальных инструкций** с `c2970` и
останавливается перед `c2e80`. Исходный prologue задаёт `sp=entry_sp-416`,
`fp=entry_sp-8`, локальный шаблон `fp-152`, `r4=633bf0`, `r5=sp+160`,
`r10=sp+52`. Тест явно задаёт эти регистры, stack pointers и копии счётчика;
тем самым он не выдаёт фикстуру за тест полного outer lifecycle.

SHA `108f38` вместе с оригинальными init/update/compressor/finalizer и
`10f64c` исполняются без замены хешей ответом новой C-функции. Каждый исходный
SHA input дополнительно сравнивается с последовательностью на Python hashlib.
Hooks: `5ccf4`, mutex, успешное выделение/освобождение, memcpy/memset.
Единственная новая инструкция тестового интерпретатора — точный
`UMULL r1,r2,r0,r1` (`e0821190`) в `c2b80`; шесть отдельных векторов проверяют
low/high результат и неизменность flags. Общий интерпретатор не меняется.

## Порядок и представление данных

- `5ccf4` возвращает signed word. Его тело суммирует raw enabled bytes цепей;
  это не повод заменять getter константой или считать каждый byte равным bool.
  Здесь вызов остаётся обязательной внешней границей.
- При положительном результате первый проход выполняется до сравнения с
  удвоенным 32-битным пределом. Сдвиг переполняется как в ARM, сравнение
  счётчика итераций остаётся signed. Для отрицательного предела после сдвига
  возможен ровно один проход. Ноль/отрицательный исходный getter пропускают batch.
- Под mutex читаются head и tail, затем проверяется
  `((head+1) modulo 2^32) modulo 768 == tail`. После отдельного lock head
  читается повторно. Взятый head проверяется на `<768` и выбирает строку.
- В отдельный allocation копируется coinbase. Низшие 0..8 байт текущего
  uint64 counter записываются little-endian по исходному смещению. SHA256d
  coinbase выполняется до free; затем SHA256d(root || branch) в порядке ветвей.
  Отрицательный signed branch count не выполняет Merkle-цикл.
- До следующего lock заполнены все 168 байт строки. **`10f64c` разворачивает
  весь блок**, сначала 64 байта, затем отдельные 12 байт; это не только endian
  swap каждого 32-битного слова.
- Публикация повторно читает live head, прибавляет 1 с wrap32 и сбрасывает
  значения `>=768` в ноль. Она не увеличивает ранее выбранный индекс строки.
  После unlock увеличивается полный uint64 counter, даже при width=0.

| Строка | Содержимое |
|---|---|
| `0..63` | reverse64(template `+08..2b` + первые 28 байт word-reversed root) |
| `64..75` | reverse12(последний word-reversed root word + template word `+30` + word `+2c`) |
| `76..79` | ноль |
| `80..111` | root с разворотом байтов каждого 32-битного слова |
| `112..119` | использованный uint64 counter LE |
| `120..123` | исходное template word `+08` |
| `124..127` | исходное template word `+2c` |
| `128..131` | исходное template word `+30` |
| `132..163` | исходные template bytes `+0c..2b` |
| `164..167` | raw key шаблона |

Смещения здесь задают доказанное отображение байтов, без новых имён vendor
полей. Key не объявляется доказательством живого pool/job identity.

## Контракт API

Field views — изолированные host-типы, не native cgminer work/pool и не ABI
оригинального 104-byte шаблона. Используется существующий
`vn135_work_job_snapshot` на 168 байт; не создаётся новое ядро заданий.
В ring доступны 768 строк; input buffers, counter и выходы не перекрываются.
Шаблон и входные массивы неизменны в callbacks. Counter принадлежит функции;
callbacks не изменяют его. Ring head/tail/содержимое строк могут изменяться
на синхронных границах; row storage и переданные identities стабильны.

Все callbacks обязательны. Аллокатор возвращает отдельную доступную память,
включая запрос нулевой длины. Input pointers доступны и при нулевой длине.
Counter width ограничена 0..8, patch помещается в coinbase, положительное число
ветвей помещается в доступный массив без 32-bit size/address wrap. Оригинальные
непроверенные повреждённые указатели или отказ malloc не преобразуются в
выдуманный успешный исход. Огромный count с непрерывным drain может не завершиться;
терминация входит в контракт вызывающей стороны. Mutex identity `633bf0`
передаётся как число, без host-разыменования.

Возврат `void` означает лишь достижение конца данного участка. Это не
vendor return code, ACK ASIC, валидность задания или принятая шара.
Реальная синхронизация, гонки, смена epoch, freshness 32 hardware slots,
дренирование и восстановление после ошибки не следуют из этой проверки.

## Проверки

```sh
make -f integration/work-producer-135.mk CC=gcc PRODUCER_DIR=build/b06-gcc all sanitize negative regressions
make -f integration/work-producer-135.mk CC=clang PRODUCER_DIR=build/b06-clang all sanitize negative regressions
```

Полное сравнение C с ARM: 351 сценарий, 978 строк, 8 385 событий,
43 181 633 ARM-шагов, 670 разных наблюдённых PC; расхождений нет.
Число PC не означает доказательство всех возможных путей и состояний.

Native/C suite проверяет все 768 начальных индексов, ширину counter 0..8,
размеры coinbase 0..129, wrap32/64, граничные signed counts, запись только
выбранных строк, guards allocation/queue, неизменность входов и изменение live
head на границах. 1 919 сценариев / 248 193 013 проверок. Expected C-layout
составляется прямым отображением полей; SHA helper общий, поэтому независимая
проверка значений находится в ARM/Python-тесте. Санитайзеры используют
`-fno-pie -no-pie` из-за ранее воспроизведённого PIE ASan startup failure в WSL;
production flags не меняются.

Negative suite требует, чтобы baseline прошёл, а каждый из 16 mutants
собрался и дал `SEMANTIC_MISMATCH` относительно 107 original fixtures.
Build error, crash или timeout не засчитываются как обнаруженная семантическая
ошибка. Варианты портят signed limit, head reread/wrap, SHA, counter, reverse64/
reverse12, metadata или момент публикации.

Workflow использует exact head checkout, GCC/Clang, ASan/UBSan, analyzer,
старые route/TX88, SHA/rebuild/candidate и nonce-регрессии. Логи, head и
каждый mutant log сохраняются в CI artifacts. Конкретные выполненные результаты
и подтверждённые количества публикуются в issue/PR после завершения запусков.

Полная прошивка, production driver, ASIC, pool submission и accepted shares
не проверены. Следующий отдельный пробел `c2498` — outer template lifecycle
и wait/start/exit; эту границу нельзя считать закрытой этим PR.

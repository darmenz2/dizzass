# R-02: ограниченный буфер ранних RX-ответов

Кандидат по #61; координация #2. Отдельная ветка от `12446bed`.
Это новый opt-in программный модуль, а не восстановленная функция VNish,
не второй майнер и не зарегистрированный аппаратный драйвер.
Работа C-01/#60 по объединению веток остаётся отдельной.

## Что меняется

В `native_jobs.c/.h` предложены два **добавочных** API:
`dizzass_jobs_capture_reply` сохраняет точный ticket существующего задания
под блокировкой реестра, разрешая состояния PREPARED и WRITTEN;
`dizzass_jobs_check_captured` проверяет serial/epoch и выполняет прежнюю
нативную проверку nonce **под той же блокировкой**.
Старый `jobs_check` сохраняет сигнатуру и поведение, вызывая общий внутренний
проверяющий код. Структура work, allocator, SHA, target и submit не заменены.

`early_rx.c/.h` хранит только копии декодированных ответов и ticket.
Никаких заимствованных RX-буферов или дополнительных work/pool-структур.
Готовое задание по-прежнему принадлежит native_jobs.

Простой повтор `jobs_check` по номеру слота недостаточен: после доказанного
NOT_SENT локальный слот может освободиться и получить другое задание.
Поэтому отложенный ответ привязан также к первоначальному serial и epoch.
Проверка ticket_live отдельно от последующего jobs_check оставляла бы окно
между двумя блокировками; новый API устраняет именно это программное окно.
Это не доказывает физическую принадлежность позднего пакета до его приёма.

## Контракт

Один RX-владелец последовательно вызывает create/offer/take/stop/destroy.
Сам буфер не создаёт потоков или mutex. TX может параллельно работать с уже
синхронизированным реестром. jobs и его pool-контекст должны оставаться живы;
уничтожение не может конкурировать с вызовами. Владелец исключает deferred
cancellation на участке take → обработка/освобождение результата либо
обеспечивает эквивалентный cleanup. Async cancellation не поддерживается.

Ёмкость задаётся явно: 1..1024 ответа, независимо от **32 аппаратных слотов**.
До проверки вместимости отбрасываются неверные epoch/chain/format/version.
При переполнении выдаётся OVERFLOW и фиксируется отказ; старые записи не
вытесняются и не перезаписываются, дальнейшие offer/take прекращаются.
Сброс ошибки автоматическим продолжением или таймаутом не предусмотрен.

`take` проверяет не более текущего ограниченного числа записей. PENDING
остаётся в очереди; более поздний уже завершённый ответ может пройти первым.
Относительный порядок оставшихся записей сохраняется. PAUSED, QUARANTINED,
EMPTY, старый epoch и заменённый ticket возвращаются явными событиями отказа.
При частичном отказе native strdup-copy запись остаётся для повторной проверки.
Успешный результат владеет настоящей копией work и освобождается через
`dizzass_early_rx_event_clear`. Non-OK результат take не меняет выходной объект.

Пример одного RX-владельца:

```c
/* jobs/gate/session already established externally; no hardware setup here. */
int rc = dizzass_early_rx_offer(inbox, captured_rx_epoch, &decoded_reply);
/* OVERFLOW/STOPPED: notify the driver lifecycle; do not continue silently. */
struct dizzass_early_rx_event event = {0};
rc = dizzass_early_rx_take(inbox, &event);
if (rc == DIZZASS_EARLY_RX_OK) {
    /* event.job_status == 0: native check completed, NOT pool acceptance.
     * Submission freshness and duplicate policy remain separate. */
    dizzass_early_rx_event_clear(&event);
}
/* WAITING: retain inbox and retry after TX progress, not a busy loop. */
```

## Выполненные проверки MainPC

GCC 11.4 и Clang 14: **25 сценариев, 1918 проверок нового набора** на каждом.
Каждый runner отдельно собрал обычное ядро в ANTS2 host-конфигурации без
запуска драйвера. Новые C-модули и настоящее root cgminer.c компилируются;
A-16 берётся точно из #58@0977235d, её код не переписывается.

11 размеров фрагмента RX; ответ во время удержания реального write до finish;
пауза и deferred cancellation настоящего отправителя; освобождение исходного
work только после возврата/соединения потока; все32 отправки и проверки;
ёмкости1/2/31/32/33/1024; переполнение без вытеснения; старый serial/epoch;
пропуск PENDING, явные отказы и повтор после ошибки копирования.
Часть переходов реестра задаётся явно в тесте, не изображая аппаратный ACK.
PTY-peer отправляет контрольный nonce; это не найденная ASIC или принятая пулом шара.

Все5 скомпилированных смысловых мутантов обнаружены на обоих компиляторах:
игнорирование serial, ошибочный EMPTY вместо ожидания, незапоминаемое
переполнение, потеря ответа при copy failure, изменение исходного epoch.
Падение/таймаут/ошибка компиляции не считаются обнаружением.

Старые проверки native jobs/nonce/hash/source-boundary прошли. Для ANTS2 без
libusb-dev понадобилось только предварительное объявление непрозрачного
libusb_context в тесте старой abort-обёртки: `host_compat.h`. Исходные тесты
и их assertions не изменены. Первоначальная ошибка компиляции сохранена.
Новый early_rx прошёл Clang analyzer без диагностик. Runner:5 тестов в Python
и5 в Python -O. Полные команды, exit codes и хеши логов находятся в results.json
и архиве, указанном в нём; число проверок вспомогательной PTY-обвязки отдельно.

Оба локальных sanitizer-запуска имеют **BLOCKED_SANITIZER_HEALTH**:
обязательный независимый pthread-cancel пример без dizzass выдаёт диагностику
раньше запуска приложения. Это не PASS и не новая доказанная ошибка early_rx.
Проверки памяти и cancellation не отключались. CI отдельно проверяет Icarus
на GCC/Ubuntu22.04 и Clang17/Ubuntu24.04 с обязательным health-примером;
его фактический результат нужно читать отдельно, не выводить из этого файла.

## Воспроизведение

Сначала read-only fetch всех точных commit из manifest.json, затем:

```sh
python3 integration/review/early_rx/test_runner.py
python3 -O integration/review/early_rx/test_runner.py
python3 integration/review/early_rx/run.py --cc gcc --out build/rxq-gcc --mutants
python3 integration/review/early_rx/run.py --cc clang --out build/rxq-clang --mutants
python3 integration/review/early_rx/run.py --cc gcc --out build/rxq-san --sanitize
```

Runner требует закоммиченные входные исходники и создаёт новый каталог,
извлекая **текущий кандидат HEAD**, а не старый native_jobs из снимка.
Все зависимости имеют проверяемые commit/path/blob/SHA256. Никаких fetch,
установки пакетов, сетевых подключений, перезаписи refs или запуска прошивки
внутри runner нет. Сетевые/USB вызовы теста завершаются abort.

## Не решено этим PR

Нет production RX-потока, его подключения к device_drv или штатного запуска.
Нет физического stop/drain, UART baud/ARM проверки, доказанной смены epoch,
атомарного check-and-submit, deduplication или управления пулом. Stop буфера
не отключает ASIC и не разрешает переиспользование слотов. Не изменены
частоты, напряжения, защиты, devfee или32-слотная политика. Нужны независимое
ревью добавочных API и последующее подключение к единственному RX-владельцу.

# R-15 — очистка callback отключённого драйвера

Задача #93, отдельный кандидат поверх R14 `2c2d0b21216bedf3155ee39d219490918fbfe05d`.
R14 добавил `device_drv.queued_stop_wake`, однако `null_device_drv` оставлял
его указатель без изменения. Последующий `cgminer_request_queued_stop`
мог вызывать обработчик прежнего драйвера уже после его нейтрализации.

Исправление рабочего кода — одна строка в `null_device_drv`:
`drv->queued_stop_wake = NULL;`.
Проверка в request остаётся прежней; `fill_device_drv` и `copy_drv` сохраняют
callback живого драйвера. Исправление не заменяет нейтрализацию остановкой:
до очистки таблицы вызывающий код по-прежнему обязан остановить и соединить
все использующие её потоки, исключить новые вызовы и гонки с teardown.
Уже исполняющийся callback эта запись не отменяет.

Стенд использует настоящие функции ядра и безвредный callback-счётчик,
возвращающий 0/EIO, без освобождённых указателей. Он доказывает лишний вызов
и его отсутствие после исправления, не демонстрирует use-after-free.
Восемь сценариев: первый stop после null (два результата старого callback),
сохранение живого callback и повторный stop, ошибка stop до null и повтор,
fill после null, независимость исходной и скопированной таблиц, повторный
null без callback, сохранение первых semaphore-post с NULL-дырой и отсутствие
накопления токенов при повторе. Одно отрицательное изменение удаляет строку
исправления и должно вызвать конкретную R15_ASSERT с exit1, не crash/timeout.

R14 и все предыдущие C-проверки остаются без изменений: 551 прежний сценарий
плюс 8 новых = 559; 81 прежний контроль плюс 1 новый = 82.
Новый runner расширяет прежний R14 и использует его проверку фактических
входов компилятора, не подставляет старые реализации из build/*-deps.
Прямая тестовая единица ядра и адаптеры инструментируются ASan/UBSan;
библиотеки поддержки не объявляются полностью инструментированными.

Манифест явно обновляет только запись cgminer.c, сохраняя полную прежнюю
запись в supersedes/input_revisions.json. Исторический Python-тест R14
проверяет текущие байты и наличие своей точной записи в цепочке supersedes,
вместо требования навсегда оставаться последней версией. C-проверки не ослаблены.

Воспроизведение из чистого коммита после установки host-зависимостей:
```
python3 -B integration/review/null_driver/test_runner.py
python3 -B integration/review/null_driver/run.py --cc gcc-14 --baseline icarus --out build/r15-gcc --mutants
python3 -B integration/review/null_driver/run.py --cc clang-17 --baseline icarus --out build/r15-clang --mutants
python3 -B integration/review/null_driver/run.py --cc gcc-14 --baseline icarus --out build/r15-san --sanitize
```
`--groups null_driver` выбирает только 8 новых сценариев. Это не полный прогон.
Runner требует сохранённых Git-входов и нового каталога результата; не скачивает,
не устанавливает пакеты и не изменяет ветки. Подробные фактические результаты
до/после и точные head/tree публикуются в PR и пакетах evidence отдельно.

Никакого аппаратного запуска, освобождения слотов, нового поколения работы,
внешней отправки на пул или изменения защит/напряжений/частот/devfee.
Лимит 32 слотов прежний. Этот PR не принимает автоматически ожидающий стек
и не меняет main/work либо чужие рабочие ветки.

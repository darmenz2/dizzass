Задача #74. Основа — непринятый кандидат R-06 / PR #73:
`e09a7c6b1aaac301acd44ec678f4abd30df3a77f`, дерево

## Операция вместо нового контроллера

R-05 управляет одной цепью; submitter может принадлежать всему устройству.
Цикл `stop(chain0); stop(chain1); ...` может ждать уже допущенный submit первой
цепи, пока остальные ещё допускают TX. Это ограничение прежнего одноканального
контракта, а не новая обнаруженная ошибка реализации R-05.

`dizzass_io_stop_many` полностью проверяет список, вызывает `request_stop`
каждого участника и только затем начинает дочерние `stop`. Ошибка/таймаут
не прерывает сбор остальных результатов. Всем передаётся один неизменный
абсолютный TX deadline. Нет нового owner, очереди, реестра, потока или майнера.
Новая функция сама не выделяет память, не открывает/закрывает устройства.

Вход — 1..16 различных ненулевых lifecycle. 16 является программным пределом
API, не числом хеш-плат модели и не изменением 32 аппаратных слотов задания.
Неверный ввод не меняет объекты и отчёт. Выход содержит все статусы request/stop
и прежний полный отчёт каждой цепи. Первая ошибка выбирается сначала в порядке
request, затем stop. `all_quiescent` требует отсутствия ошибок и программного
покоя всех участников. Отката stop нет; незавершённый набор можно проверить
повторно после завершения TX. Отмена потока исключена до публикации отчёта;
её восстановление может не дать функции вернуться. Память отчёта должна
пережить отмену вызывающего потока.

## Границы контракта

Владелец передаёт полный набор устройства и удерживает все внешние объекты,
порты, пулы и алиасы. Пропущенную цепь или два разных объекта на одном порту
этот API не обнаруживает. Один controller выполняет lifecycle start/stop/join/
destroy. Нельзя вызывать batch stop из RX callback или TX producer, конкурировать
с индивидуальным lifecycle stop/destroy либо перекрывать входные/выходные буферы.

Рассылка request последовательна, не атомарна для всех портов. Ранее допущенная
операция может завершиться во время неё. До первого ожидания дочернего stop
запрошен каждый участник; сами mutex рассылки также не имеют жёсткого deadline.
TX deadline не ограничивает целиком submitter stop, callback или RX join.
Даже all_quiescent не разрешает освобождать ещё используемые внешние ссылки.
Нет физического off/drain, новой epoch, CRC, device_drv или разрешения повторного
использования слотов. Аппаратная или принятая внешним пулом шара не заявляется.

## Тесты и воспроизведение

26 новых сценариев используют старые R-04 helpers, реальные PTY/RX-потоки,
реестр и один общий submitter. В наборе 1/3/16 участников, незапущенный набор,
9 неверных входов, ошибки в каждой позиции, две разные ошибки, задержанный
write и окно до finish, удержанный общий submit и отмена controller.
Контрольный nonce подаёт тестовый peer, не ASIC. Ошибки и барьеры явно внедрены.
Первое ожидание submit удерживается: остальные цепи уже обязаны отказать новым
командам. При таймауте одной цепи остальные завершают программную остановку.

Runner расширяет неизменённый R-06 runner: все прежние 197 сценариев и 24 мутанта
сохраняются. Полный набор — 223 сценария и 31 скомпилированный смысловой контроль
(7 новых). Санитайзеры повторяют 223 положительных сценария после обязательного
независимого pthread-cancel примера. Сигнал/таймаут/сборочная ошибка не считается
обнаружением мутанта. Три unit-теста runner проверяют сохранение старых групп,
мутантов и новые якоря; они не заменяют выполнение C-приложения.

Все реализации компилируются из текущего отслеживаемого дерева, без build/*-deps.
Guard R-06 записывает фактические входы компилятора. ASan/UBSan покрывают прямые
тестовые единицы и адаптеры, но не все библиотеки поддержки. TSan и доказательство
всех чередований потоков не заявляются. Результаты фактически завершённых запусков
содержатся в results.json и полных logs/compile-records, а не следуют из наличия CI.

```
python3 -B integration/review/device_stop/test_runner.py
python3 -B -O integration/review/device_stop/test_runner.py
python3 -B integration/review/device_stop/run.py --cc gcc-14 --baseline icarus --out build/r07-gcc --mutants
python3 -B integration/review/device_stop/run.py --cc clang-17 --baseline icarus --out build/r07-clang --mutants
python3 -B integration/review/device_stop/run.py --cc gcc-14 --baseline icarus --out build/r07-gcc-san --sanitize
```

Нужен checkout одного коммита и host dev-пакеты. Runner требует коммит входов,
создаёт свежий каталог и не меняет refs/пакеты/сеть. --groups явно ограничивает
набор и число сценариев. Локально ANTS2/no-libcurl используется лишь для сборки
обычного ядра без libusb-dev; запускаются --version и offline-тесты, не драйвер.

## Сохранённая ошибка разработки

Первый dev-прогон прервался в очистке стенда: общий submitter освобождался раньше
остальных RX-пользователей. Исправлена только очистка теста: остановить/соединить
всех, уничтожить все lifecycle, затем освободить контексты. Рабочий helper не
менялся. Первоначальный неуспешный журнал сохраняется. Это дополнительная проверка
тем же ассистентом, не независимая сторонняя приёмка и не разрешение на прошивку.

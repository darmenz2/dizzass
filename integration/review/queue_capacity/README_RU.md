# R-11 — свободные слоты до извлечения задания из cgminer

Задача #82. Основа — опубликованный R-10 / PR #81:
`2855ad18b6bc93a1727c587fa35886546e11fa84`, дерево
`6dd6ae83f1250378114fb74451ff9bb6c549f13c`.
Это кандидат поверх непринятой ветки, не готовая прошивка.

В этой беседе сохранился иной незавершённый локальный R-09 с
`dizzass_io_send_queued`. Он НЕ добавляется. Используется уже опубликованный
`dizzass_queued_work_send` и его учёт `active_queue` из R-10.

## Поведение

`dizzass_jobs_capacity` под существующим mutex реестра формирует 32-битную
маску только SLOT_EMPTY. PREPARED, WRITTEN и QUARANTINE не свободны.
Пауза, старое поколение и исчерпание serial возвращают существующие ошибки;
выходной объект при ошибке не меняется. Маска 0 — успешный ответ без ёмкости.
Нет выделения памяти, копирования work или изменения состояния слотов.

`dizzass_io_capacity` использует собственные jobs/received_epoch lifecycle,
а не отдельный потенциально несвязанный реестр, переданный вызывающим кодом.
Остановленный, незапущенный или завершивший RX lifecycle не допускает работу.
Это снимок, не резервирование: stop может произойти сразу после проверки.

`dizzass_queued_work_step` выбирает младший свободный слот и вызывает прежний
`dizzass_queued_work_send` на фиксированном маршруте 2/0/2. Нулевой budget,
неверные аргументы, истёкший deadline, остановка или отсутствие ёмкости
проверяются до core dequeue. При ENOSPC исходное staged work остаётся в
`cgpu->unqueued_work`, а выходной receipt не изменяется. Это существенно:
`queued_count == 0` после native completion НЕ означает свободные wire-слоты.

При return 0 публикуется receipt с выбранным слотом, снимками ёмкости,
статусом повторного запроса и полным прежним результатом queued_work_send.
`queue_full` означает «закончить текущий проход наполнения», а не физическое
состояние чипов. Только полностью успешные transport/finish/notify и новый
снимок свободной ёмкости разрешают `queue_full = false`. Пустой/stale handoff,
неверные метаданные, copy failure и ошибки TX завершают текущий проход, чтобы
немедленный повтор не превращался в бесконечный цикл. Последующий вызов
после временной ошибки возможен по решению внешнего планировщика.

Будущий callback обязан обрабатывать ненулевой код как full/error:

```c
struct dizzass_queue_step_receipt receipt = {0};
int rc = dizzass_queued_work_step(thr, io, deadline, budget, &receipt);
/* Store/log rc and nested receipt as appropriate. */
return rc != 0 || receipt.queue_full;
```

Это пример адаптации, НЕ зарегистрированный device_drv. Сам native
fill_queue/get_work producer, scanwork и его ожидание здесь не запускаются.

## Конкурентность и владение

Один последовательный владелец должен сериализовать ВСЕ передачи work и
прямые prepare для этого реестра. Query не выдаёт reservation/ticket.
При искусственно внедрённом конкурирующем prepare прежняя A-16 возвращает
BUSY и не затирает билет; уже извлечённый оригинал завершается по контракту
R09/R10. Сохранение staged work в такой неподдерживаемой гонке не обещается.
Поддерживаемая гонка control stop проверяется прежним queue_enter и A-16.

R-10 по-прежнему считает core queue от входа до work_completed и публикации
внутреннего receipt. Новый внешний шаг исключает deferred cancellation до
публикации своего receipt. Его начальные/заключительные advisory checks не
являются дополнительной scope-арендой. Даже quiescent не даёт разрешения
освобождать внешние ссылки: нужно join/exclude ВСЕХ вызывающих, затем destroy.
Все прежние требования к native queue/pool/qlock, отсутствию reentry и
неперекрывающейся памяти аргументов сохраняются. Async cancellation запрещена.

Нет автоматического reclaim/modulo, нового epoch, аппаратного drain или
разрешения переиспользования отправленного/retired слота. Только доказанный
NOT_SENT допускает прежнее освобождение SLOT_EMPTY. Положительная CRC и
успешная запись не являются ACK, принятой шарой или доказательством свежести.

## Проверки

41 новый составной сценарий: аргументы/пауза/старое поколение, маски состояний,
32 реальные host TX и сохранённое 33-е work, отказ повторного использования
после retire, существующая посторонняя native очередь, empty/stale/metadata,
четыре copy failures, prefix/EIO и полная поздняя запись, stop/slot races,
11 размеров раннего CRC-ответа, отмена producer и удержанное work_completed.
Реальные cgminer helpers, Linux PTY и pthreads, но nonce от тестового peer.
Сценарии только состояния реестра и внедрённые ошибки явно отмечены в C.

Все 455 прежних сценариев R02..R10 подключаются импортом прежнего runner.
Полный набор — 496 положительных сценариев; 50 прежних и 9 новых
компилируемых смысловых контролей. ASan/UBSan запускают те же сценарии после
обязательной независимой проверки pthread cancellation. Прямые test/core TU
и adapters инструментированы, библиотеки поддержки — обычные. Не заявляется
TSan, перебор всех interleavings или полностью санитайзированная прошивка.

Четыре исходных runtime/header файла получают ТОЛЬКО добавления. Прежние C
assertions и queued_work_tx.c неизменны. Четыре записи input manifest явно
обновлены с полными предыдущими значениями в supersedes/input_revisions.json.
Проверка происхождения в R10 test_runner теперь принимает точную историческую
запись в цепочке supersedes и отдельно сверяет текущие байты — не требует,
чтобы версия R10 оставалась последней навсегда. Остальные её проверки сохранены.
Исторический frozen A13 scope guard не меняется: при будущей приёмке/retarget
на work/reconstruction понадобится отдельное решение по новым версиям реестра.

## Воспроизведение

```
python3 -B integration/review/queue_capacity/test_runner.py
python3 -B -O integration/review/queue_capacity/test_runner.py
python3 -B integration/review/queue_capacity/run.py --cc gcc-14 --baseline icarus --out build/r11-gcc --mutants
python3 -B integration/review/queue_capacity/run.py --cc clang-17 --baseline icarus --out build/r11-clang --mutants
python3 -B integration/review/queue_capacity/run.py --cc gcc-14 --baseline icarus --out build/r11-san --sanitize
```

`--groups queue_capacity` — только 41 новый сценарий, не весь набор.
Runner использует текущий committed source и реальные compiler input receipts;
не скачивает файлы, не устанавливает пакеты, не меняет refs. Старые каталог
результата/незакоммиченные исходники отклоняются. Локальная история восстановлена
из проверенного архива, а не выдаётся за подлинную историю GitHub.

Фактические завершённые результаты записываются отдельно в handoff/CI receipt.
Нет физических ASIC/портов/пула, установки прошивки, MainPC, изменения частот,
напряжений, защит, devfee, main/work или принятия стека независимым разработчиком.

# R-01: native work → UART → RX

Независимый хостовый стенд по задаче #57, координация #2.
Это не новый майнер, не готовый T21-драйвер и не реализация A-16.
Производственные исходники не изменены; зависимости не объединены с общей веткой.

Восемь C/header-файлов проверяются по Git blob и SHA-256 из manifest.json.
Тест включает настоящий корневой cgminer.c с переименованным только main:
используются struct work, make_work, copy_work_noffset, _free_work, test_nonce,
fulltest и существующие native_jobs/native_work_tx88/native_nonce/RX parser.
Главный цикл, драйверы и сеть не запускаются. Socket/connect/USB имеют
аварийные тестовые обёртки. Все терминалы создаются локально через openpty.

## Что проверено

Восемь сценариев: ранний RX с фрагментами 1/2/11 байт; реальные первые пять
байт TX и внедрённый EIO; реальные 88 байт с поздним возвратом write;
отмена между send и finish без внешней защиты и с ней; все 32 слота,
карантин и отказ старым epoch/token.

PTY-peer принимает фактический пакет и отправляет заранее заданный nonce.
До finish проверка возвращает PENDING. Тест сохраняет ответ и после finish
получает ожидаемый genesis hash настоящими функциями cgminer. Исходное work
уже изменено и освобождено: проверяется сохранённая копия и её строки.
Это не аппаратный ACK, не доказательство T21-селекторов и не принятая пулом шара.
Очередь ранних ответов и непрерывная RX-служба здесь не реализованы.

Намеренно неправильный вызывающий код оставляет ticket в PENDING после
записи всех 88 байт и отмены потока. Внешняя защита позволяет выполнить
finish перед отменой. Это подтверждает требование к вызывающей стороне,
а не объявляет ошибку A-14. Подготовка в тесте выполнена заранее:
защиту самой подготовки и неопубликованную A-16 этот стенд не проверяет.

При частичной или полной, но просроченной записи слот уходит в карантин.
Остановленный канал отказывает и в INACTIVE: stop UART не доказывает
физическую остановку ASIC. Смена epoch в тесте явно синтетическая,
не аппаратный барьер очистки. Увеличение лимита 32 не применяется.

Падения, таймауты и ошибки компиляции не считаются обнаруженными мутациями.

Сводка и хеши отчётов/логов находятся в evidence/results.json.
Полные команды и логи сохранены в указанном там архиве на MainPC.
Runner создаёт новые результаты и полные логи при каждом воспроизведении.

## Сборка и нерешённая диагностика

Из-за отсутствия development headers libcurl/libusb хостовый core собран
с --enable-ants2 --disable-curses --disable-libcurl, без запуска драйвера.
Это не ARM/T21 и не обычная Icarus CI-конфигурация. Вариант runner
--baseline icarus здесь не запускался.

Санитайзеры инструментируют тест, включённый cgminer.c и прямые адаптеры.
Прочие native support objects и библиотеки остаются обычной сборкой.
Полная инструментированная сборка проекта не заявляется.

Первый Clang PIE запуск упал без диагностики. Пустой main независимо упал
3/8 раз с PIE и 0/8 без PIE. Только sanitizer test executables поэтому
используют -fno-pie -no-pie; проверки памяти не отключены.

GCC sanitizer FAIL не подавлен и не переименован в PASS. Минимальный пример
pthread_cancel без dizzass также даёт сообщения в 5/5 запусках обоих
компиляторов; у Clang это stack-buffer-overflow при завершении потока.
Исходники probe сохранены в evidence/. Это отдельный воспроизводитель,
но не доказательство окончательной причины. Успешные Clang-прогоны полного
стенда не отменяют диагностику probe. Весь sanitizer набор не принят.

## Воспроизведение

Нужны Linux, Python 3.10+, make, Autotools, выбранный компилятор и зависимости
хостовой сборки. Точные коммиты должны уже существовать в локальном клоне.
Runner не скачивает файлы, не устанавливает пакеты и не изменяет Git refs.
Каждый --out должен указывать новый каталог внутри build.

```sh
python3 integration/review/native_uart_stack/test_runner.py
python3 -O integration/review/native_uart_stack/test_runner.py
python3 integration/review/native_uart_stack/run.py --cc gcc --out build/r01-gcc --mutants
python3 integration/review/native_uart_stack/run.py --cc clang --out build/r01-clang --mutants
python3 integration/review/native_uart_stack/run.py --cc clang --out build/r01-clang-san --sanitize
# Воспроизведение НЕПРИНЯТОГО GCC sanitizer результата:
python3 integration/review/native_uart_stack/run.py --cc gcc --out build/r01-gcc-san --sanitize
```

## Следующая приёмка

A-16: проверить её опубликованный точный код, включая отмену от prepare до
finish/сохранения результата. RX: явно ограниченное удержание PENDING и
разрешение после finish/ошибки/pause; не блокировать реестр на всём I/O.
Останов: отдельно доказать прекращение новых работ, завершение потоков,
физическую остановку с охлаждением и отсутствие старых ответов до новой эпохи.
Затем — согласованный интеграционный SHA, ARM-сборка и отдельно разрешённый
аппаратный тест. Ни один из этих этапов данным PR не считается выполненным.

Нет merge, изменений A-16/чужих деревьев, production device_drv, ASIC/пула,
firmware execution, частот/напряжений/защит/devfee или лимита 32.

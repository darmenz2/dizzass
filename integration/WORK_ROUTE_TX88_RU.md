# SHA256d: выбор отправителя TX88 и подготовка native work

## Что установлено в исходном ELF

Это проверка конкретного сохранённого cgminer из AML-образа VNishNet T21 1.3.5,
не заявление о работоспособности устройства. Оригинал читается как данные и
исполняется только ограниченными участками в локальном ARM-интерпретаторе.

Исходный разбор алгоритма записывает `sha256d -> 0`, `scrypt -> 1`, неизвестное
имя -> 2. Разбор JSON и hwscan целиком не запускаются. В отдельном исследованном
вызывающем участке инициализации контрольки передаётся числовой селектор **2**;
его запись в исходное глобальное состояние проверена до периферийных операций.

Затем оригинальный диспетчер `0x738a4..0x73af8` выбирает:

| Уже загруженные селекторы | Инициализатор | Рабочие процедуры, передаваемые pthread_create |
|---|---|---|
| Ненулевая платформа, алгоритм 0 (`sha256d`) | `0xc3b54` | `0xc4054`, `0xc2498`, **`0xc4b18`** |
| Алгоритм 1 (`scrypt`) | `0xc1c0c` | **`0xc0018`** |
| Платформа 0, алгоритм 0 | `0xbfce8` | Другая ветвь; здесь не портируется |

**TX86 из предыдущего этапа находится в scrypt-процедуре `0xc0018`.
Отправитель `0xc4b18` относится к проверенной SHA256d-ветви и формирует TX88.**
Это не взаимозаменяемые форматы, которые можно выбрать по длине или названию ASIC.
В инициализаторах действительно выполнены оригинальные инструкции выбора
адресов потоков; pthread_create перехвачен, никакие потоки оригинала не запускаются.

У неизвестного алгоритма исходный селектор может попасть в общую ветвь TX88.
Новый `dizzass_work_route_select` намеренно отклоняет неизвестные значения.
Это добавленная защита, не найденное поведение производителя. Проверенный домен
нового API: платформа 0..4, алгоритм 0..1; числа не объявляются списком
поддержанных реальных контрольных плат.

## TX88 и индекс записи

`integration/work_tx88.c/.h` реализует чистый кодировщик исследованного пакета:

```
55 AA | 21 36 | (slot << 3) | 01 | 00 00 00 00 | reverse(work->data[0:76]) | CRC16
```

Всего 88 байт. `0x36` сохранён как исходный литерал, не заменён длиной 88.
CRC16: полином 0x1021, начальное значение 0xffff, по байтам [2:86], результат
старшим байтом первым. Нужен внутренний словный формат `work->data` cgminer,
а не сериализованный Bitcoin header. Старый nonce [76:80] не передаётся.

Разрешены слоты 0..31. Оригинальные отправитель и приёмник ссылаются на одну
таблицу `0x653458`, что проверяется независимым разрешением их PC-relative
ссылок. Это привязка к общей внутренней таблице, **не доказательство свежести
произвольного аппаратного ответа**.

В обычном RX-варианте 2 для BM1368 слот декодируется как:
`((payload[4] & 1) << 4) | (payload[5] >> 4)`.
Поэтому байт отправки `(slot << 3)` нельзя просто скопировать в байт ответа.
Native-тест явно создаёт синтетический ответ с этой раскладкой, не выдаёт его
за захват UART и не проверяет аппаратное принятие задания.

## Связь с настоящим cgminer

Новые `integration/native_work_tx88.c/.h` не заменяют ранее добавленный TX86.
Рабочее ядро, `Makefile.am`, прежние тесты и reference ELF не меняются.

`dizzass_native_work_tx88` проверяет маршрут и кодирует уже созданный native work.
`dizzass_jobs_prepare_tx88` сначала создаёт пакет во временном буфере, затем
сохраняет то же неизменяемое задание через существующий `dizzass_jobs_prepare`,
который вызывает **родной copy_work_noffset**. Только после успеха публикуются
пакет и ticket. Это новая интеграционная операция, не восстановленный ABI VNish.

Исходное задание должно удерживаться и не изменяться на протяжении вызова;
буфер результата не должен пересекаться с source/его строками/реестром.
При ошибке пакет и ticket не публикуются. При частичном отказе strdup действует
существующий откат реестра; другие fail-fast аллокаторы cgminer не заменены.
Рабочая запись остаётся **PREPARED**. Успех НЕ означает WRITTEN, chip ACK или шару.
Фактический отправитель позднее должен сообщить реальный исход через finish.

Сложность, SHA256d, coinbase/Merkle, `struct work`, владение строками, математическая
проверка nonce и освобождение остаются нативными. Variant RX передаётся явно:
его не выводят из одного лишь алгоритма или длины TX. Version-rolling отсутствует;
для фиксированного задания базовая версия читается непосредственно из work.

## Проверки

Наборы ниже описывают тесты, не заменяют журнал их выполнения:

- Оригинальный разбор имён: 7 входов; 16 снимков передачи платформы из вызывающего
  участка; 10 комбинаций platform/algorithm; 2 набора адресов создаваемых потоков.
- 128 TX88-пакетов и 36 CRC-наборов против оригинальных инструкций; дополнительно
  независимые перестановка/CRC через Python. Нет замены CRC готовым результатом.
- Нативная связка: 64 случайных native work-вектора; все 32 слота с PREPARED,
  явным синтетическим finish, обратным декодированием и родными test_nonce/fulltest.
- Независимость исходника и сохранённой копии, жизнь результата после удаления
  реестра; 4 частичных отказа strdup; NOT_SENT/UNCERTAIN; занятый слот, карантин,
  неверная эпоха и отклонение неподходящего алгоритма без публикации результата.
- Чистые C-проверки границ и перекрытия буферов: 11225 утверждений.

```sh
make -f Makefile -f integration/work-route.mk dizzass-work-route-original dizzass-work-route-bounds dizzass-work-route-native
make -f Makefile -f integration/work-route.mk SANITIZE=1 dizzass-work-route-bounds dizzass-work-route-native
make -f Makefile -f integration/work-route.mk CC=clang DIZZASS_ROUTE_DIR=build/work-route-clang DIZZASS_JOBS_DIR=build/route-jobs-clang DIZZASS_NONCE_DIR=build/route-nonce-clang dizzass-work-route-original dizzass-work-route-bounds dizzass-work-route-native
```

После обычной сборки cgminer. Workflow `work-route.yml` повторяет эти проверки.
ASan/UBSan покрывают новую интеграцию, реестр/адаптер и тестовую единицу с
корневым cgminer.c; не все уже собранные зависимости. Clang пересобирает эти
единицы, не весь upstream. Это не проверка TSan/всех гонок и не аппаратный тест.

## Оставшиеся границы

Теперь маршрут SHA256d на исследованной AML-платформе доказан условно по
загруженной конфигурации. Но **полный путь физического hwscan -> модель T21 ->
согласованный аппаратный профиль ещё не восстановлен**. Не следует автоматически
присваивать любому устройству BM1368 или число чипов из теста.

Не реализованы реальный UART TX, проверка CRC аппаратных ответов, подтверждённая
граница смены заданий и повторное использование слотов. Отправленный слот по-прежнему
нельзя повторно занять в той же эпохе. Сброс программного счётчика не заменяет
аппаратную очистку. Защиты/PSU/запуск цепей/автотюн не добавлены этим этапом.

Нет физического ACK, живой отправки пулу, регистрации T21 или firmware release.
**Не заменять штатный `/usr/bin/cgminer` этой офлайн-интеграцией.**

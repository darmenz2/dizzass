# Учёт отправленных заданий на основе родного cgminer

`integration/native_jobs.c/.h` — новый адаптер учёта аппаратных слотов.
Это не реконструированный менеджер VNish, не альтернативный `work` и не
драйвер, который уже отправляет задания на T21.

## Что переиспользуется

В каждой записи хранится копия **настоящего `struct work`** через
`copy_work_noffset()`. Строки копирует штатное ядро; очистка — `free_work()`.
Проверка ответа вызывает ранее добавленный `dizzass_nonce_check_matched()`,
то есть родные `test_nonce()` и `fulltest()`. Нового SHA, target, Stratum,
формирования coinbase или второй структуры задания нет.

Копирование `work` НЕ увеличивает счётчик ссылок на `pool` — его срок жизни
по-прежнему обеспечивает вызывающий код/ядро. Снимок результата принадлежит
вызывающему коду и освобождается `dizzass_job_result_clear()`. Он сохраняет
заголовок и строки после удаления записи реестра или самого реестра.

## Переходы состояний

| Операция | Результат |
|---|---|
| `prepare` | Резервирует свободный слот и независимо копирует native work |
| `finish(...WRITTEN)` | Делает запись доступной для сопоставления ответа |
| `finish(...NOT_SENT)` | Освобождает слот, только если ни один байт не мог попасть на устройство |
| `finish(...UNCERTAIN)` | Карантин после частичной/неопределённой отправки |
| `retire` | Освобождает native work, но НЕ разрешает повторное использование слота |
| `pause` | Блокирует prepare/check и отменяет также незавершённые подготовки |
| `begin_drained_epoch` | Открывает новую эпоху после внешнего доказанного завершения старого TX/RX |

Реестр сам не выполняет `write()` и не подтверждает аппаратный ACK. Исход
передачи сообщает будущий реальный транспорт. Тесты подают эти исходы явно.
Неправильный или повторный ticket не изменяет другую запись. При отказе одной
из четырёх `strdup` неполная копия освобождается, запись не публикуется.
Штатное fail-fast поведение ядра при других OOM сохраняется.

## Почему слот нельзя просто перезаписать

Ответ содержит пятибитный индекс 0–31, но не введённые нами `epoch`/`serial`.
Эти поля — только локальная защита от устаревших программных операций.
Они не позволяют угадать поколение произвольного старого аппаратного кадра.
Поэтому **один отправленный слот используется только один раз за эпоху**.
После исчерпания 32 слотов нельзя молча начать круг заново.

Смена эпохи требует остановленного TX/RX и подтверждения, что старые задания
хешчипов, данные контрольки/UART и неполные кадры уже не появятся. Один лишь
сброс программного буфера, произвольная задержка или `epoch++` этого не дают.
`begin_drained_epoch` записывает внешне обеспеченную границу, но не реализует
и не проверяет её аппаратно. RX должен получать метку эпохи на границе сеанса,
а не считывать текущую эпоху после поступления потенциально старого кадра.

Это намеренно ограниченный контракт для интеграции. **Непрерывный цикл reuse
слотов на T21 ещё не реализован**: нужна проверенная семантика смены аппаратных
заданий/буферов, а не выдуманный таймер. Version-rolling также не добавлен.

## Потоки и актуальность

Операции над таблицей и копирование хранимого work защищены mutex.
Уничтожение реестра допускается только после остановки и join всех пользователей.
`ticket_live` — мгновенная проверка состояния, НЕ атомарный check-and-submit.
Готовый математический результат может устареть сразу после возврата функции.
Дедупликация, свежесть задания, нативная статистика и `submit_nonce` — следующий
слой. Текущий адаптер не отправляет шары и не выдаёт код 0 за принятие пулом.

## Воспроизводимые проверки

После обычной сборки настоящего cgminer, из корня дерева:

```sh
make -f Makefile -f integration/native-jobs.mk dizzass-native-jobs-test
make -f Makefile -f integration/native-jobs.mk SANITIZE=1 dizzass-native-jobs-test
make -f Makefile -f integration/native-jobs.mk CC=clang DIZZASS_JOBS_DIR=build/native-jobs-clang DIZZASS_NONCE_DIR=build/native-nonce-clang dizzass-native-jobs-test
```

Используется прежний тестовый модуль с настоящим корневым `cgminer.c` и
условным подключением шести групп registry-тестов. Обычные nonce-тесты остаются
без нового реестра. Набор дополнен отказами `strdup`, удержанием снимка после
очистки/смены эпохи, проверкой всех 32 слотов, 11 фрагментациями RX и четырьмя
читателями с 4000 проверками на фоне 200 синтетических смен эпохи.
Проверка символов не допускает recovery SHA/frontend/work вместо родного ядра.
Результаты 128 родных SHA256d-векторов дополнительно сверяются с Python hashlib.

Санитайзеры инструментируют реестр, адаптер, тестовый cgminer.c и RX-модули;
прочие уже собранные зависимости отдельно не инструментируются. Clang-цель
пересобирает эти же модули, но использует остальные GCC-объекты ядра.
Это не полный аудит потоковых гонок и не аппаратное испытание.

Прохождение подтверждается журналом CI конкретного commit, не этим описанием
набора. `Makefile.am`, production-ядро, Stage 14 и исходный ELF не изменяются.
Реестр пока не включён в production-бинарник, устройство не регистрируется.

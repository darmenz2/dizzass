# A-07 — координатор настройки температуры `0x6ec4c`

Задача #25, координация #2. Независимая база:
`12446bed78a060a49364a80bcbfb4340b13f4f27`, дерево
`2e73cb80b2ccbb15d24d9a7deb3c51f65bcd23ac`.
Рабочая ветка `chatgpt/temperature-setup-135`, PR в `work/reconstruction`.
Никакого автоматического слияния или включения непринятых PR.

## Что перенесено

`vn135_backend_temperature_setup_135` воспроизводит управляющее тело
`6ec4c..6f188`, литералы до `6f1cc`. Исходный путь в диагностике:
`/tmp/build/src/backend/base.c`. Новый `src/backend/temperature-setup.c` —
отдельная единица офлайн-сборки проекта, не имя файла производителя.

Это не драйвер одного датчика и не новый реестр обработчиков. Функция
координирует проверку описаний, инициализацию цепей, реакцию на ошибки,
регистрацию температурного ответа и итоговую проверку работоспособных цепей.

Переиспользованы существующие `vn135_general_monitor`, `vn135_route_chain`,
`vn135_resume_description` и `vn135_monitor_handlers`. В описание добавлена
только отдельная ссылка на поле role (второе слово исходной записи длиной 28
байт), отсутствующее в прежнем resume-view. Количество и типы описаний берутся
из существующего description, а не из состояния датчиков цепи.

**`vn135_monitor_chain_decision_135` вызывается непосредственно.** Алгоритм
`60a2c` не переписан и не заменён успешным callback. Двухусловный предикат
последнего подсчёта сохраняет `56fcc`: present и unsigned `(state - 3) > 2`.
Прежние файлы, общие заголовки, эталон и ARM-интерпретатор не менялись.

## Порядок оригинала

1. Сначала получить количество цепей через `fe668` и сохранить его для
   инициализации. Затем искать описание типа 2, при его отсутствии — типа 1.
   Если обоих нет, вернуть **0**, не вызывая инициализацию, регистрацию,
   `78eb8`, `60a2c` или окончательный подсчёт. Так бывает и при отсутствии
   работающих цепей. Нулевой результат не является подтверждением запуска.
2. Для каждого индекса исходного количества вызвать `58b50(chain, mode)`.
   Указатель массива цепей и mode перечитываются перед каждым вызовом.
   Сам координатор не фильтрует отсутствующие/остановленные цепи: такие
   проверки относятся к нижнему `58b50` и не дублируются наверху.
3. При ненулевом результате выдать диагностику строки 1811 уровня 1:
   `chain#%d - failed to init temp sensors`. Индекс читается после возврата
   инициализатора и увеличивается с 32-битным переполнением.
   После диагностики перечитать существующий `general.suppress_thermal`
   (backend+f6). При нуле вызвать `56d18` с причиной
   `Failed to init temp sensors`; его результат игнорируется. Продолжить цикл.
   Указатель цепи для сообщения/остановки остаётся тем, который выбран до
   инициализатора, даже если callback переключил общий массив.
4. Заново прочитать текущее описание. Если в нём ещё есть тип 2, получить
   ключ из backend+19c и передать `(key, backend, 78aa4)` границе регистрации.
   Старую пару, возвращаемую оригиналом через scratch, вызывающий код не
   использует; типизированный callback её намеренно не предоставляет.
   Ключ передаётся полным 32-битным словом без обрезки и без значения по умолчанию.
5. После регистрации заново проверить описания: если хотя бы одно имеет
   тип 1/2 и role=2, вызвать `78eb8`. **Нулевой** результат этого вызова
   означает возврат `-1`; ненулевой разрешает продолжить. Для остальных
   описаний проверка не вызывается.
6. Выполнить существующую `60a2c`. При её ненулевом результате вернуть `-1`.
   При нулевом — ещё раз получить количество цепей и подсчитать пригодные
   через исходный предикат. Хотя бы одна даёт 0, иначе результат `-1`.

Ни ошибка отдельного инициализатора, ни возврат из регистрации не означают
немедленный выход сами по себе. Регистрация может уже произойти, а последующая
проверка вернуть `-1`: **эта функция не выполняет её откат**. Это описание
локального тела; поведение внешнего вызывающего кода проверяется отдельно.

Непрозрачные арифметические ветви исполняются в ARM-сравнении. Произведение
соседних 32-битных чисел чётно, поэтому соответствующие альтернативные пути
не добавлены как выдуманные повторные аппаратные операции.

## Сохранённые границы

- `58b50` — обязательный callback инициализации цепи; его тело здесь ещё
  не перенесено. Прочтение соседних инструкций не выдаётся за его реализацию.
- `56d18` — отдельный callback с контрактом существующей `vn135_chain_stop_135`;
  тело в новом ARM-наборе не исполняется, результат задан сценарием.
- `78eb8` — обязательный callback проверки; его внутренние алгоритмы вне этапа.
- backend+19c — обязательный getter. A-06 показал выбранный BM1368-ключ,
  но его непринятый PR не включён и ключ не назначен всем чипам автоматически.
- `108b40` — только внешняя граница регистрации с проверяемыми аргументами.
  A-04 с блокером публикации не копируется, не перепаковывается и не повторяется.
  Реальный реестр, его конкурентность и время жизни контекста не реализованы.
- `78aa4` уже восстановлена ранее. Её адрес — идентификатор исходного
  обработчика в тесте, не исполняемый указатель хоста; заново она не создаётся.

Объекты backend/general и таблицы операций живы и стабильны. При замене
описания/массива старые захваченные объекты не освобождаются до возвращения
вызова. Положительные количества соответствуют выделенным массивам. Данные
меняются только в последовательных callback. Эти условия не доказывают
безопасность произвольных гонок, ошибочных размеров или повреждённых указателей.

## Проверки

Полный оригинальный координатор исполняется с исходной `60a2c`, её getters
и предикатами. Новый C вызывает прежнюю реализацию решения по цепям.
Сравниваются результат, состояние на границах вызовов, порядок и аргументы:
**1 041 сценарий, 8 738 событий, 377 630 ARM-шагов, 456 адресов инструкций**.
Сценарии охватывают отсутствие нужных типов, signed count, role, ошибки
инициализации, подавление ошибки после logger, переключение массивов/описаний,
полные ключи, разные количества на разных стадиях и повторные вызовы.
Контроль запрещает необъяснённые записи оригинала вне стека.

Нативный набор: **1 363 сценария / 23 227 проверок**, включая две ограниченные
связки с существующей `vn135_backend_resume_135`. Они проверяют, что отказ
настройки не достигает создания потока, а принятый этап доходит до первого
create, который тест намеренно отклоняет. Это C-композиция, **не** полное
вложенное исполнение оригинального resume или аппаратный запуск.

Все **12** неправильных вариантов должны скомпилироваться и завершиться
именно `TEMPERATURE_SETUP135_MISMATCH`. Для них используется явный набор
из 13 различающих сценариев; неизменённая baseline проходит тот же набор.
Полные положительные 1 041 сценарий выполняются отдельно на GCC и Clang.
Ошибка сборки, crash или timeout не считается успешным отрицательным контролем.

Нативный набор повторяется с ASan/UBSan; отдельно запускаются прежние
monitor-handlers и backend-resume. Контрольные суммы 23 прежних зависимостей,
байтов оригинала и диагностических литералов закреплены в evidence.
Конкретные результаты команд, в том числе прерванные запуски, хранятся в логах.
Статус удалённого CI всегда проверяется отдельно по SHA, не выводится из файла
workflow или локальных PASS. PR-тестирование не является слиянием веток.

Никаких обращений к ASIC, UART, GPIO, пулу, реальным потокам и реестру.
`device_drv`, частоты/напряжения/защиты/devfee, ядро cgminer и ограничение
32 аппаратных work-слотов не менялись. Следующий кандидат — нижний `58b50`:
сначала проверить существующие sensor helpers, затем переносить только

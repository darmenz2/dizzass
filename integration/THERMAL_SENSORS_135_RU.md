# 1.3.5: показания температуры и исходные аварийные решения

База: `975f609f7e34adedb5e80a055c97333f0706fd8e`.
Переносится поведение сохранённого бинарника 1.3.5, а не новая система защит.
Корневые cgminer.c/Makefile.am, питание, регулятор вентиляторов и слоты не изменяются.
Новый модуль пока является отдельной офлайн-целью, не рабочим драйвером T21.

## Объём переноса

В подтверждённом `src/backend/temp.c` заменена pending-запись. Исходный путь
подтверждён исполнением конструктора строк оригинального ELF. Перенесены:

| Назначение | Объём |
|---|---|
| Сброс состояния датчика | Целая исходная процедура |
| Приём показания, поправка, история и контроль скачка | Целая исходная процедура |
| Инициализация датчика прямого доступа | Целая исходная процедура с исходным ограничением типов |
| Проверка давности одного датчика | Целая исходная процедура |
| Проверка давности группы датчиков | Целая исходная процедура |
| Чтение локального регистра температуры | Только исходный путь типа 1 без удалённого канала |

Ещё две целые процедуры — решение о перегреве цепи и общий контроль тайм-аутов —
помещены в `reconstruction/support/thermal_trip_135.c`. Их исходное имя файла
пока не доказано; вспомогательный путь не выдаётся за оригинальный.
**Итого семь целых точек входа и один ограниченный путь, НЕ весь драйвер датчиков.**
Адреса, диапазоны и хеши находятся в `evidence/thermal_sensors_135.json`.

## Инициализация и показания

Инициализатор обслуживает исходные типы доступа 1 и 2. Для иных типов он
возвращает -1 без замены транспорта. Последовательность: подготовка интерфейса,
чтение регистра идентификации, проверка допустимого кода, запись исходных
настроек, завершающий вызов для соответствующего типа, отметки времени и состояния.
Для идентификации сохранены три попытки и ожидание 50 мс после каждой неудачной,
включая последнюю. Кодами принимаются 26, 85 и 89. Коммерческие названия датчиков
к ним не приписаны. Коды не доказывают комплектацию конкретной хешплаты T21.

Приём показания использует локальную либо удалённую поправку, сохраняет предыдущие
значения, время новой выборки и обнуляет счётчик ошибок. Для типа доступа 4
при наличии истории проверяется скачок более 30 относительно предыдущего sample.
Порядок 32-битных вычитания и смены знака сохранён, включая переполнение.
Ограничение не превращено в новый универсальный фильтр для всех датчиков.
В исходном состоянии 3 процедура возвращает 0, не обновляя показания.

Сброс намеренно не обнуляет всё: время последнего измерения, локальная поправка
и счётчик ошибок остаются прежними. Нельзя считать его полной очисткой объекта.

Локальный reader перенесён лишь для `access_kind==1 && remote_enabled==0`.
Он читает регистр 0, вычитает 64 с байтовым переполнением, расширяет знак и
вызывает восстановленную процедуру приёма показания. Исходный возврат updater
игнорируется. При ошибке чтения увеличивается счётчик, а начиная с третьего
отказа при обычном начальном нуле записывается исходное состояние 3.
Состояние и сохранённый счётчик влияют на эту границу; новой политики повторов нет.
Другие транспортные ветви и удалённое измерение этим reader не реализуются.

## Давность измерений — разные проверки

Одиночная проверка применяет тайм-аут только к типу доступа 2. Равенство
тайм-ауту допустимо; отказ возникает при строгом превышении. Иные типы эта
функция не объявляет отказавшими даже по одному лишь состоянию 3.

Групповая проверка не выбирает самое старое измерение. Она ищет **самое новое
из сохранившихся допустимых**, затем сравнивает возраст с тайм-аутом группы.
Отказавший датчик с ролью 2 блокирует этот путь отдельно. Если все описания
имеют тип 2 или группа пуста, исходная функция возвращает успех без этого обхода.
Это не новый критерий безопасности и не гарантия свежести каждого датчика.

Общая процедура сначала вызывает одиночные проверки. Неудачная одиночная
проверка ведёт к отказу при режиме 2 либо роли датчика 2. Затем выполняется
групповая проверка. Процедура пишет диагностику и возвращает -1, но **сама
не выключает питание**. Тайм-ауты и температурные пределы передаются явно;
значения для реального T21 не придуманы и не зафиксированы тестовыми константами.

## Перегрев: исходный порядок действий

Сначала под блокировкой читаются две кэшированные температуры. Приоритет имеет
температура платы, затем температура чипов. Срабатывание происходит при
достижении соответствующего предела, не только при его превышении:

```
Диагностика причины
    -> исходный вызываемый обработчик остановки цепи
    -> аварийный режим общего регулятора вентиляторов
    -> запись события
    -> исходный возврат -1
```

При перегреве чипов в двух исходных селекторах дополнительно вычисляется индекс
самого горячего элемента для диагностики. Сохранено строгое сравнение; при
максимуме в первом элементе выходной индекс остаётся исходным нулём.
Возвраты остановки, полного обдува и записи события игнорируются как в оригинале.
Проверка использует кэш и не выполняет отдельную проверку свежести перед сравнением.

**Тело нижней остановки цепи остаётся внешним.** Вызов не объявляется доказанным
электрическим отключением PSU, разрядом платы или очисткой очередей старых nonce.
Ранее созданные защитные адаптеры не ослаблены: они отдельны от точного переноса.

## Проверки и их границы

Дифференциальный набор: **1766 сравнений / 7504 внешних события** за прогон.
Исполняются исходные инструкции сброса, приёма, инициализации, двух проверок
давности, общего контроля, решения о перегреве и ограниченного чтения. Общий
контроль исполняет вложенные проверки, а reader — исходный updater: их возвраты
не подставляются заранее. Внешними остаются шина, часы, mutex, диагностика и
действия остановки/обдува. Сравниваются поля, времена побайтно, возвраты и порядок
операций. В тестах неиспользованные байты исходной записи остаются неизменными.

Нативный набор: **2835 сценариев / 13409 утверждений**. Дополнительная C-композиция:
**253 сценария / 9650 утверждений** — новый overheat вызывает существующий
аварийный режим общего fan_ctrl, затем существующий AML-setter обоих PWM-каналов.
Проверяются порядок, восемь записей успешного пути, отказы stop, каждого открытия
и каждой записи. Все файлы представлены RAM-сценариями. Это C-композиция ранее
проверенных модулей, а не исполнение всего составного оригинального ARM-графа.

Новые сравнения, native и C-композиция прошли GCC и Clang. Оба C-набора также
прошли ASan/UBSan на обоих компиляторах. Анализ Clang новых C-модулей — без
диагностик. Локально повторены прежние GCC-наборы fan control и AML fan driver.
Повторы компиляторами не увеличивают число уникальных случаев.

Используется прежний ограниченный ARM-интерпретатор без изменения его файлов.
В локальном подклассе добавлено только расширение знака байта SXTB с вращениями;
1024 арифметических фикстуры проверяют все байты и четыре вращения, совпадение
регистров и сохранение флагов. Диапазоны исполненных инструкций ограничены,
неизвестные исполняемые тела приводят к ошибке. ELF и выделенные диапазоны
сверяются хешами. Это не независимая сертификация полной архитектуры ARM.

Типы — проекции известных полей, не vendor ABI. Область проверки: конечная
binary64-арифметика времени без переполнения и с обычным округлением, корректные
объекты/буферы/размеры, стабильные описания и указатели, сериализованный жизненный
цикл. Callbacks меняют только оговорённые выходы. NaN/Inf, повреждённые указатели,
асинхронные гонки, реальная точность датчиков и системные отказы вне сценариев
не проверены. Санитайзеры покрывают C и нативную композицию, не ctypes/Python
или все зависимости майнера.

Рабочая локальная папка собрана из сохранённого Stage14 и архивов последних
этапов, не является полным текущим checkout. Три используемых предыдущих C-модуля
сверены с опубликованными Git blob. Новый CI использует точный опубликованный
commit; его фактический результат определяется журналом, не наличием workflow.

## Остаток

Не закрыты все маршруты чтения (включая передачу через хешчипы), физическая
привязка датчиков конкретного T21, глобальные workers мониторинга, тела нижних
аварийных действий и производственное связывание с драйвером cgminer.
Полное питание, аппаратные защиты и безопасный оборот слотов не объявляются
готовыми. Процессы исходной прошивки, реальный T21 и физические I2C/PWM не запускались.

```sh
make -f integration/thermal-sensors-135.mk dizzass-thermal135-original dizzass-thermal135-test dizzass-thermal135-airflow
make -f integration/thermal-sensors-135.mk SANITIZE=1 dizzass-thermal135-test dizzass-thermal135-airflow
```

**Не устанавливать вместо штатного cgminer: это офлайн-перенос выбранной логики.**

# I2C 1.3.5: исходный программный GPIO-обмен под побайтовым PSU

База изменения: `57fd09a0a86cce8d928a124b6b5e5a938785cd87`.
Восстанавливается сохранённый VNishNet 1.3.5. Это не новый контроллер I2C,
не усиленный адаптер ошибок и не готовый аппаратный запуск T21.

## Семь исходных точек входа

| Адрес | Новый C-символ | Объём |
|---|---|---|
| `0x126e0c` | `vn135_i2c_soft_sda_input` | Перевод SDA на ввод и переоткрытие value |
| `0x1287c4` | `vn135_i2c_soft_sda_output` | Перевод SDA на вывод и переоткрытие value |
| `0x127030` | `vn135_i2c_soft_start` | Исходная последовательность START |
| `0x127e28` | `vn135_i2c_soft_stop` | Исходная последовательность STOP |
| `0x12728c` | `vn135_i2c_soft_send_bits` | Восемь бит и четыре окна ожидания ACK |
| `0x126fcc` | `vn135_i2c_soft_write_byte` | Адрес, необязательный регистр, байт, STOP |
| `0x128188` | `vn135_i2c_soft_read_byte` | Адрес, необязательный регистр, восемь бит, STOP |

Перенос добавлен в подтверждённый `libbitmain/src/i2c.c`, рядом с уже
восстановленными аппаратными open/close. Их функции не меняются.
`integration/i2c_soft_135.h` — новый типизированный интерфейс, не vendor ABI:
представлены только известный флаг направления, три fd и путь SDA/value.
Флаг по смещению +0x24 и дескрипторы +0x230/+0x234/+0x440 относятся к исходному
объекту, а не к новой структуре C. Восстановления полной структуры нет.

В evidence закреплены SHA-256 оригинального ELF и диапазонов, исходный путь
из XOR-строки, три зашифрованных байта литерала out и его конструктор.
Конструктор этих трёх байтов выполняется исходными инструкциями перед тестом.
Новые инструкции к историческому ARM-интерпретатору не добавлены.

## Отличия, которые нельзя заменять привычной реализацией I2C

Исходная смена направления записывает in/out в descriptor направления,
закрывает старый value-fd, задаёт -1 и открывает value заново. Для input
используется числовой flags=2, для output=1. Ошибки записи диагностируются,
но процедура продолжает работу. Флаг направления меняется даже после ошибки
open. При ненулевом флаге повторный output вообще ничего не делает.

Передача данных идёт старшим битом вперёд. После восьми бит выполняется до
четырёх окон ACK, в каждом до шести чтений. Успехом признаётся именно ASCII 0
(0x30), не нулевой байт. **При повторном окне восемь бит не передаются заново.**
После исчерпания окон выдаётся исходная диагностика; обёртка записи байта
всё равно продолжает следующие части и возвращает 0. Это не аппаратный ACK.

Чтение сначала отправляет `(address << 1) | 1`, даже когда затем следует
необязательный регистр. Дополнительный repeated START не придумывается.
На каждом из восьми бит SDA/value закрывается и открывается с flags=0;
в отличие от смены направления, до возврата open старый fd остаётся в объекте.
Любой прочитанный байт, кроме ASCII 0, устанавливает соответствующий бит.
Ошибка open/read завершает процедуру через STOP и значение **255**, не -1.

Сохранены порядок GPIO-записей, вызовов ожидания с аргументом 1 мс, записи
состояния, диагностики и продолжение после ошибок. Физические фронты и точность
миллисекунд на контрольке этим не измеряются. START/STOP/ACK helpers представлены
как void: их случайное содержимое ARM r0 не используется исходными вызывающими
процедурами и не входит в новый интерфейс. У байтовых обёрток результат сравнивается.

## Составной тест с исходным PSU

Исполняется исходный `0x105938` (побайтовый обмен PSU) вместе с `0x102bd0`
(валидатор ответа) и всеми перечисленными GPIO-процедурами. Byte read/write,
START/STOP, битовый цикл и валидатор не подменяются готовыми результатами.
На стороне C существующий `vn135_psu_exchange_bytes()` вызывается с callbacks
на восстановленные байтовые процедуры. Нового протокола PSU здесь нет.

Внешними остаются только RAM-сценарии write/read/open/close, ожиданий,
mutex и диагностического вывода. Заданные биты ответа не считаются захватом
реального PSU. Сравниваются возврат, полный ответ, изменения fd/направления,
каждая GPIO-запись и весь порядок событий. Проверяются четыре режима checksum,
успех первой/второй/третьей попытки, три отказа, ошибки внешних операций.

## Проверки и границы

Основной набор содержит **4207 сравнений**: input 173, output 173, START 203,
STOP 215, send bits 682, byte write 1351, byte read 1410. Перебираются все
256 байтов, положения успешного ACK, ошибки на отдельных вызовах,
ненулевые режимы, крайние 32-битные значения и неканонические входные байты.
Отдельный составной набор содержит **32 PSU-обмена** с GPIO-процедурами.

Нативный C-набор: **9993 сценария / 2280524 утверждения**, включая полные
байтовые переборы, ошибки и ограничители вокруг состояния. Большое число assert
не является числом восстановленных функций или процентом готовности.
ASan/UBSan проверяют новый C-код и C-набор; не Python-интерпретатор и не
составной ctypes-набор. Полный ARM-эмулятор или аппаратный стенд не используются.

```sh
make -f integration/i2c-soft-135.mk dizzass-soft135-original dizzass-soft135-composed dizzass-soft135-test
make -f integration/i2c-soft-135.mk SANITIZE=1 dizzass-soft135-test
make -f integration/i2c-soft-135.mk CC=clang SOFT135_DIR=build/soft-clang dizzass-soft135-original dizzass-soft135-composed dizzass-soft135-test
```

CI по умолчанию компилирует настоящий текущий libbitmain/src/psu.c.
При локальной проверке составного пути допустим SOFT135_PSU_SOURCE с неизменённым
подтверждённым префиксом пяти PSU-процедур; такой запуск не считается сборкой
полного текущего PSU-файла. Результат каждого режима подтверждается его журналом.
Предусловия интерфейса описаны в заголовке: корректные объекты/callbacks,
завершение внешних вызовов и сериализованный жизненный цикл. Гонки не тестируются.

## Что ещё не восстановлено

Не добавлены физическое открытие GPIO, их export/init, выбор номеров выводов,
регистрация программной шины, полный вызывающий запуск питания и проверки
электрических условий. Наличие этой ветви не доказывает, что конкретный T21
выбирает её вместо аппаратного AML I2C. Это устанавливается отдельно по dispatch.
STOP этой шины не равен остановке хеширования и не очищает очередь nonce.
Оборот слотов, защитные адаптеры, частоты, напряжения и devfee не изменены.
Модуль компилируется отдельной целью; production cgminer.c/Makefile.am,
reference ELF и исторический инвентарь не переписываются.
**Не устанавливать этот набор вместо штатного cgminer: физический запуск ещё не проверен.**

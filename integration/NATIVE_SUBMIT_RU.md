# Штатный submit_nonce поверх реестра native work

## Добавлено

`integration/native_submit.h` объявляет устройство-общий обработчик передачи
результатов в **настоящий `submit_nonce()` корневого cgminer**. Реализация находится
в `integration/native_jobs.c`: это позволяет брать согласованную копию из закрытого
реестра без публикации указателей на его слоты. Новый основной цикл, структуры
work/pool, SHA, target, Stratum и алгоритм устаревания не создаются.

Общий валидатор chain/slot/variant/version вынесен в
`dizzass_nonce_match_status()`. Его используют как старый проверочный адаптер,
так и новый путь отправки. Версия заголовка при несовпадении не подменяется.

```
Обычный разобранный nonce + ранее зафиксированная эпоха RX
    -> общий для cgpu submitter mutex
    -> проверка живого WRITTEN-слота под mutex реестра
    -> проверка сопоставления и нативного контекста
    -> copy_work_noffset(): собственная копия native work
    -> освобождение mutex реестра
    -> настоящий submit_nonce(thr, copy, nonce)
       -> штатный new_nonce / test_nonce / inc_hw_errors
       -> штатные update_work_stats / fulltest
       -> штатный submit_work_async / stale_work
       -> штатный tq_push в Stratum-очередь, когда ядро решает её пополнить
    -> free_work(copy)
    -> освобождение submitter mutex
```

`Makefile.am` и корневое ядро не меняются. Новый путь пока собирается только
интеграционной тестовой целью. Нет регистрации T21, аппаратных команд,
самостоятельной отправки заданий, изменения питания или devfee.

## Возвраты не означают принятие пулом

Код 0 у адаптера означает, что нативная процедура была вызвана. Поля результата:

* `native_valid_nonce` — исходный bool из `submit_nonce`: nonce прошёл diff1 и
  не равен непосредственно предыдущему nonce этого cgpu.
* `meets_target` — математическое сравнение, выполняемое только для valid nonce.

Даже два true не подтверждают помещение в очередь: ядро может отбросить stale,
не обнаружить очередь или получить отказ от замороженной очереди. При превышении
target сам `submit_nonce` также возвращает true. Никакого `accepted=true` нет.
Подтверждение принятия принадлежит обычному обработчику ответа пула cgminer.

Дедупликация не заменена: это прежнее сравнение last_nonce на уровне cgpu, не
полная история всех пар job/nonce. Повтор после промежуточного другого nonce и
одинаковый nonce на разных работах сохраняют исходную семантику ядра.

## Конкурентный доступ и остановка

Должен существовать **один submitter на cgpu**, общий для всех его цепей. Другие
вызовы submit_nonce для того же cgpu должны пользоваться тем же порядком
сериализации, а не идти в обход. Сам конструктор не ведёт глобального реестра
cgpu и не препятствует неправильному созданию двух обработчиков вызывающей
стороной. Это явное обязательство будущего драйвера.

Проверка и копирование происходят в одной критической секции реестра.
После допуска копия независима от retire/pause. Они блокируют будущие допуски,
но не отзывают уже допущенную работу. Для остановки диспетчеризации сначала
вызвать `dizzass_submitter_stop()` из управляющего потока: он дожидается выхода
из текущего нативного вызова и навсегда запрещает следующие вызовы через этот
обработчик. Уже созданные ядром очередные записи не отменяются.

Во время нативного вызова mutex реестра отпущен: hw_error может инициировать
pause/retire без взаимной блокировки. Но hw_error не должен рекурсивно вызывать
run/stop/destroy того же submitter. Уничтожение — только после остановки/join
всех пользователей. Порядок блокировок: submitter -> registry; вызов ядра — только
под submitter. Не держать при входе внешние блокировки, нужные cgminer.

Копия work НЕ удерживает pool/thr/cgpu/driver дополнительным refcount. Их жизнь
и корректность нативных указателей обеспечивает ядро/будущий драйвер. Поддержан
только фиксированный Stratum-work: совпадающий thr_id, pool и строковые поля,
положительная конечная work/device difficulty. GBT/solo/time/version rolling
этим адаптером не добавлены.

## Ограничения, которые не снимает этот этап

32 аппаратных слота и требования доказанной границы TX/RX из NATIVE_JOBS_RU.md
сохранены. Остановка submitter не останавливает чипы и не доказывает очистку UART.
Нет CRC новых ответов, выбора T21-драйвера или автоматического reuse слотов.
Новый путь не заменяет нативную stale-политику собственной проверкой job_id.

Отказы strdup проверяются для **первой копии допуска**. Дополнительную внутреннюю
копию, создаваемую самим submit_tested_work, обрабатывает исходный cgminer; его
поведение при частичном отказе strdup этим этапом не исправлено. Остальные
fail-fast аллокаторы ядра также сохранены. Это не полная OOM-гарантия runtime.

## Проверки

После нормальной host-сборки cgminer:

```sh
make -f Makefile -f integration/native-submit.mk dizzass-native-submit-test
make -f Makefile -f integration/native-submit.mk SANITIZE=1 dizzass-native-submit-test
make -f Makefile -f integration/native-submit.mk CC=clang DIZZASS_SUBMIT_DIR=build/native-submit-clang DIZZASS_JOBS_DIR=build/native-jobs-clang DIZZASS_NONCE_DIR=build/native-nonce-clang dizzass-native-submit-test
```

Шесть новых групп проверяют реальную native-очередь и её копию work, дубликат и
HW-учёт, превышение/равенство target, старый блок и срок, разрешение submit_old,
замороженную/отсутствующую очередь, ошибочные контексты, первую копию при OOM,
11 фрагментаций RX и 64 конкурентных вызова из четырёх потоков на двух реестрах
цепей. Для одинакового nonce на одном cgpu ожидается один valid и 63 нативных
отказа-дубликата, не 64 принятые шары.

Отдельный синхронизированный сценарий останавливается внутри tq_push, разрешает
pause реестра, затем снимает блокировку и проверяет завершение stop. Обёртка
вызывает **настоящий tq_push**, а не возвращает заранее заданный успех.
Проверяется также hw_error, который сам вызывает pause реестра.

Оригинальный сетевой consumer не запускается: тест извлекает записи настоящим
tq_pop и освобождает их. socket/connect/libusb_init запрещены аварийными обёртками
для прямых вызовов тестовой сборки; это не универсальная песочница для всех
динамических библиотек. Старые проверки nonce, реестра и hashlib повторяются.

ASan/UBSan инструментируют реестр/адаптер, включённый корневой cgminer.c и RX,
но не все ранее собранные объекты и зависимости. Clang также пересобирает эти
единицы, а не весь upstream. TSan и физический ASIC не проверяются. Итог
прохождения устанавливается по CI конкретного commit, не по этому описанию.

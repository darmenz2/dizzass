# 1.3.5: запуск постепенного снижения частоты — 0x65b3c

База: `ed54e2d033965e944361d14a588dab70e21e539b`, дерево
`3c41912a14ee3dc8ba941fd61946e4b460b27070`. Продолжение уже опубликованной
остановки `663cc`. Прежние патчи повторно не применяются.

## Восстановленная функция

`vn135_backend_fall_frequency_135` добавлена в `src/backend/base.c` под
отдельным флагом `VN135_FREQUENCY_FALL_135`. Перенесено управляющее тело
`65b3c..65f68`; далее до `65fcc` находятся литералы. Файл установлен по
полному литералу `/tmp/build/src/backend/base.c` в диагностике функции.

Это не освобождение кэша и не остановка ещё одного постоянного потока.
Функция подготавливает временные массивы и запускает по цепям рабочую функцию
`65fcc`. Исходные сообщения — `Setting freq to %d Mhz gradually` и сообщение
об ошибке создания `fall freq thread`. Само тело `65fcc` **пока не перенесено**:
этот этап не реализует команды изменения PLL/частоты или новый автотюн.

## Порядок вызовов

1. Получить представление конфигурации через `a71e8`, затем первое количество
   цепей через `fe668`. Оно сохраняется для выделения памяти и запуска потоков.
2. Два отдельных вызова `593bb4`: сначала `count × 8` байт под пары
   `{backend, chain}`, затем `count × 4` под исходные 32-битные handle.
   Выделение происходит **до** проверки необходимости снижения частоты.
3. При ошибке первого выделения — сообщение строки 4481 и возврат `-1`.
   При ошибке второго — строка 4487, освобождение первого массива, возврат `-1`.
4. Повторить getter конфигурации; отдельно получить количество цепей для
   просмотра текущих частот. Среди цепей, допустимых по исходному `56fcc`,
   найти минимальное знаковое слово `chain+28`. При отсутствии таких цепей
   исходное значение минимума — ноль, не `INT_MAX`.
5. Взять большее из этого минимума и поля второго getter+`0c` и сравнить
   с полем первого getter+`18`. Если оно **меньше или равно** целевому полю,
   сразу освободить оба массива и вернуть 0. Поле `floor_0c` в C — название
   этой границы сравнения, не утверждение об электрически безопасном минимуме.
6. Иначе вывести строку 4496 с целевой частотой и создать по одному потоку
   `65fcc` для **каждой** позиции из первого количества цепей, включая позиции,
   исключённые предикатом при поиске минимума. Фильтрации при создании нет.
7. Если все создания завершились с нулевым кодом — вызвать join для всех
   сохранённых handle по порядку; результат join не влияет на продолжение.
   Затем получить **ещё одно** количество цепей и заново подсчитать допустимые.
8. Освободить сначала массив аргументов, затем массив handle. Возвратить
   исходный управляющий результат, не синтетическое подтверждение частоты.

Предикат цепи переиспользован: `present != 0 && unsigned(state - 3) > 2`.
Текущее слово частоты — уже существующее `thermal.cleared_words[0]`; отдельного
дублирующего поля не введено. Сравнения частот и конфигурационных полей знаковые.

## Неочевидные ветви оригинала

**Частичный отказ создания.** При ненулевом результате create функция сохраняет
этот код, выводит строку 4506 с номером позиции `i+1`, освобождает **оба** массива
и возвращает код. Ранее созданные потоки здесь не cancel/detach/join. Дожидание
успехов, повторная попытка и rollback не добавлены. При реальной конкуренции
это требует отдельной проверки времени жизни аргументов: тесты не доказывают,
что ранее запущенные worker уже перестали пользоваться освобождаемой памятью.
Этот путь нельзя выдавать за безопасный production-алгоритм завершения.

**Пустое начальное количество.** Исходный allocator допускает результат
NULL либо ненулевой освобождаемый указатель для нулевого размера. В последнем
случае функция продолжает получать новые количества. Если частотная ветвь
выбрана при initial=0, а заключительный подсчёт не находит допустимых цепей,
возвращается `-1`; при появлении допустимых цепей — 0. После успешного создания
всех потоков для положительного initial результат остаётся 0 даже при нулевом
заключительном количестве допустимых цепей. Новая «ошибка всех цепей» не добавлена.

**Три количества нельзя объединять.** Первое определяет размер массивов и число
create/join; второе — поиск минимального слова; третье — заключительную проверку.
Третий вызов отсутствует на пути раннего сравнения и на пути ошибки create.

**Живые чтения и сохранённые указатели.** Первый указатель конфигурации сохраняется
до вызовов количества/выделения, второй — после второго выделения. Их содержимое
читается после поиска минимума. Адрес массива цепей перечитывается при каждой
итерации; в каждый аргумент записывается конкретный адрес соответствующей цепи.
Handle читаются по мере join, поэтому более ранний callback может изменить
handle будущего join. Проверены замены конфигурационного/цепного указателя на
другое валидное представление, а также изменения полей на границах вызовов.

## Представления и границы

Используются существующие `vn135_general_monitor`, `vn135_general_chain`,
`general_alive` и `bits_signed`. Новые конфигурационные и временные записи —
типизированные проекции, **не vendor ABI** и не `pthread_t`.

Поскольку в оригинале указатель занимает 4 байта, а на хосте может занимать 8,
allocate получает исходные `count` и `source_stride` отдельно от типа хостового
массива. Adapter обязан выделить обнулённый **типизированный** массив: ему нельзя
просто выделить `count*8` сырых байтов под хостовые пары указателей. Сохраняются
порядок, возможность отказа и исходные условия 32-битного переполнения размера.
Native-тест выделяет/освобождает настоящую защищённую хостовую память; потоки
при этом не запускаются. В Python-оракуле allocator/free — явные модели.

`create` получает именно `65fcc`, адрес выходного handle и адрес записи
аргументов; атрибуты в оригинале NULL. `join` получает NULL для результата.
Неизвестные эффекты worker не заменены успешным производственным заглушечным кодом.

Родительская `663cc` не изменена. Её прежний `step(65b3c,0)` связывается с новой
функцией только в тестовом адаптере. Ошибки новой функции родитель, как и оригинал,
игнорирует и продолжает обнуление рабочих полей и сообщение `Mining stopped`.

## Проверки

Оригинальный ELF читается ограниченным ARM-интерпретатором, не запускается как
процесс. Интерпретатор, старые oracle и прежние тела функций не изменены.

- Прямой набор: **1 019 сценариев, 10 665 событий, 260 694 шага ARM**.
  Исполняются исходные `65b3c`, getter `a71e8` и предикат `56fcc`.
- Вложенный набор: **145 сценариев**, **1 009 событий `663cc` и 1 730 событий
  `65b3c`**, 50 617 шагов. Вызов новой функции не подменяется callback успеха:
  оригинальные тела родителя и дочерней функции исполняются в одной модели.
- Нативный набор: **439 сценариев, 333 622 проверки**. Проверки включают
  защитные области и неиспользованные части массивов, реальные malloc/free
  хоста, отказ каждого выделения и создания, границы знаковых сравнений,
  соединение с прежними остановками и прекращение внешнего `60730` при выходе.
- **10 отрицательных контролей** обязаны сначала скомпилироваться, затем
  отвергаться именно несовпадением с оригиналом. Ошибка компиляции, авария
  процесса или иное исключение не засчитываются как обнаруженное расхождение.

GCC/Clang используют отдельные build-каталоги. Native-набор повторяется с
ASan/UBSan. Существующий нативный fixture mining-stop переиспользуется через
генерируемый в build include: меняется только имя его `main`, исходный файл
и прежние тесты не правятся. Числа относятся к конечным тестовым наборам,
не к математическому доказательству всех состояний или работы реальных потоков.
Полная очистка `5f0fc/5fc54` с новой функцией проверена как C-составная цепочка;
новое вложенное сравнение с ARM ограничено связкой `663cc → 65b3c`.

```sh
make -f integration/frequency-fall-135.mk CC=gcc dizzass-fall135-original dizzass-fall135-test dizzass-fall135-negative
make -f integration/frequency-fall-135.mk CC=gcc SANITIZE=1 dizzass-fall135-test
make -f integration/frequency-fall-135.mk CC=clang FALL135_DIR=build/fall-clang dizzass-fall135-original dizzass-fall135-test dizzass-fall135-negative
make -f integration/frequency-fall-135.mk CC=clang SANITIZE=1 FALL135_DIR=build/fall-clang-san dizzass-fall135-test
```

Точные результаты прогонов и CI проверяются по логу и SHA, не выводятся из
наличия workflow. В evidence закреплены ELF, диапазоны, литералы, связи вызовов,
прежний префикс `base.c` **52 805 байт** с исходным blob
`8b6e93385e59d8d04844d229344a3b55d3eada59` и неизменённые файлы.

## Продолжение

Следующий самостоятельный участок — **`0x65fcc`**, рабочая функция постепенного
снижения частоты, которую теперь достигает восстановленный диспетчер `65b3c`.
Параметры аппаратных операций и выходы при ошибках нужно установить отдельно.
Её готовность не следует из успешных create/join-моделей этого этапа.
Остаются и предыдущие нижние узлы `fe218`, `b8e54`, `58d08/5a9fc`, backend+`19c`,
`108b40`, `f98b8`. Production driver, реальные потоки, частоты/напряжения,
пулы, devfee, ограничения 32 слотов и аппаратная приёмка T21 не менялись.

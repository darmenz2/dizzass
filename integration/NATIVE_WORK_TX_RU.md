# Кодирование 86-байтного задания из native work

## Что добавлено

`integration/work_tx86.c/.h` восстанавливает сборку пакета из участка
`0xc069c–0xc07e4` функции `0xc0018` в сохранённом ARM ELF.
`integration/native_work_tx.c/.h` передаёт в него первые 80 байт **настоящего
`struct work`** из `miner.h`. Формирование coinbase, Merkle root, заголовка,
SHA256d и target остаётся в родном cgminer. Новый майнер или тип `work` не создаётся.

Это законченный кодировщик исследованного пакета, но не законченный отправитель
и **не подтверждённый формат заданий именно T21**. Имя исходного файла этого
участка и диспетчеризация модели/контрольки пока не установлены. Поэтому файлы
честно названы интеграционными и не приписаны `chip1398.c` или другому драйверу.

## Формат и порядок байтов

| Смещение | Длина | Содержимое |
|---|---:|---|
| 0 | 2 | Преамбула `55 AA` |
| 2 | 1 | Байт команды `20` |
| 3 | 1 | Передаваемый ID задания |
| 4 | 80 | Переставленные данные заголовка с начальным nonce = 0 |
| 84 | 2 | CRC16, старший байт первым |

В исходном коде две ветви: равенство числового селектора **7** и остальные
значения. Новый интерфейс принимает явный формат, не угадывает его по модели.
До общего разворота тела обычная ветвь формирует `work->data[0:76] + 4 нуля`,
а специальная — `4 нуля + work->data[0:76]`. Затем оригинальная процедура
**разворачивает все 80 байт целиком**. Это не просто смена порядка байтов в словах.

`work->data` здесь — внутреннее словное представление cgminer, не сериализованный
80-байтный Bitcoin header. Байты прежнего nonce `[76:80]` игнорируются. Код не
меняет версию, время, сложность или исходное задание. CRC считается по байтам
`[2:84]`, полином `0x1021`, seed `0xffff`, без отражения и завершающего XOR.

Оригинальный фрагмент при ID с установленным старшим битом подставляет **1**.
Новый интерфейс вместо скрытой подмены принимает только `0..127` и возвращает
ошибку для остальных. ID **0** покрыт как вход данного фрагмента; это не
утверждение, что весь оригинальный поток выдаёт его в обычном цикле.

## Почему ещё нет соединения с реестром 32 слотов

Передаваемый ID и пятибитный индекс в ответе — **не доказанно одно поле**.
Поэтому здесь нет `id & 31`, автоматического обхода слотов, `finish(WRITTEN)`
или отправки пакета после его успешной сборки. Нужны подтверждённые выбор
отправителя/приёмника и соответствие их идентификаторов, затем семантика
замены старого задания на хешчипах. Ограничения `native_jobs` не снимаются.

Успех кодировщика означает только готовые **86 байт в памяти**. `write()`,
UART, подтверждения хешплаты, PSU, PLL и аппаратные команды не вызываются.

## Контракт API

Чистая функция требует ровно 80 доступных входных байт, известный формат и
ёмкость результата не меньше 86. При отказе результат не изменяется, при успехе
записываются ровно 86 байт. Локальный временный пакет допускает перекрытие
входа и выхода чистого интерфейса. CRC-helper имеет обычное C-предусловие:
указатель доступен на заданную длину; NULL допустим только при нулевой длине.

Нативная обёртка читает неизменяемый удерживаемый вызывающей стороной `work`.
Её выход не должен пересекаться с самим `work`. Она не копирует и не освобождает
объект, не увеличивает native allocation counter и не удерживает `pool`.

## Сравнения и тесты

`integration/tests/tx86_oracle.py` выполняет **оригинальные инструкции** сборки,
полного разворота и CRC16, включая таблицу из ELF. Из внешних вызовов подменяется
только `memcpy`; модель и предварительно вычисленные данные задания/корня —
явные входные границы теста. Оригинальный producer coinbase и его рабочие потоки
не запускаются. ELF открывается только как данные. Контролируется его SHA-256.

Основной набор: **521 сравнение пакетов**, **300 сравнений CRC** одновременно с
оригиналом и Python `binascii.crc_hqx`, **384 отдельных проверки** добавленных
форм инструкций SXTB/REV16. Дополнительно проверяются неверные параметры,
высокие ID, размеры, ограниченные выходные буферы и перекрытие чистого интерфейса.

Нативный harness включает настоящий корневой `cgminer.c`: **256 пакетов** для
двух форматов и всех поддержанных ID, **64 дополнительных native-вектора**,
сверяемых с оригинальными инструкциями, и **2 исторических roundtrip-проверки**
с восстановлением известного nonce и штатными `test_nonce/fulltest`.
Обратная перестановка находится только в тесте и не выдаётся за ответ ASIC.
Проверяются неизменность исходного объекта/строк, отсутствие новых выделений
при кодировании, границы буферов и независимость пакета от прежнего nonce.

```sh
make -f Makefile -f integration/native-work-tx.mk dizzass-tx86-differential
make -f Makefile -f integration/native-work-tx.mk dizzass-native-work-tx-test
make -f Makefile -f integration/native-work-tx.mk SANITIZE=1 dizzass-native-work-tx-test
make -f Makefile -f integration/native-work-tx.mk CC=clang DIZZASS_WORK_TX_DIR=build/native-work-tx-clang DIZZASS_NONCE_DIR=build/native-nonce-clang dizzass-native-work-tx-test dizzass-tx86-differential
```

Команды выполняются после обычной сборки cgminer. CI повторяет прежние native
nonce/jobs/submit-тесты и отдельно новый набор. ASan/UBSan инструментируют новый
код, тестовую единицу с native cgminer.c; не все уже собранные
зависимости. Clang также пересобирает эти единицы, а не весь upstream.
Фактическое прохождение подтверждается журналом конкретного commit.

`integration/evidence/tx86/` содержит адреса, хеши и границы исследованных участков.
`Makefile.am`, корневой `cgminer.c`, старый reference ELF и исторический
инвентарь не меняются. Новые модули не включены в production-бинарник;
регистрации T21 и испытания физического оборудования на этом этапе нет.

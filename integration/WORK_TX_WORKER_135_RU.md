# B-04: исходный отправитель TX88 `0xc4b18`

Задача [#15](https://github.com/darmenz2/dizzass/issues/15), координация
[#2](https://github.com/darmenz2/dizzass/issues/2). База
`12446bed78a060a49364a80bcbfb4340b13f4f27`. Это восстановление наблюдаемого
потока отправки из VNish 1.3.5. Производственный драйвер T21 здесь не подключён.

## Источник и проверяемые границы

Из пользовательского `vnishnet-t21-aml-nand-v1.3.5.tar.gz` повторно извлечён
`usr/bin/cgminer` без исполнения. SHA-256 архива:
`20fabdd66255889315e61ae2a33ff2e4623566ca430f1cb8c90d9b938dc7b43c`;
ELF: `b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.
В `evidence/work_tx_worker_135.json` сохранены хеши участков, скрипт и вывод
Ghidra 12.1.4, включая дизассемблирование и декомпиляцию трёх функций.

Ghidra работает с ELF как с данными. После обозначения `5a52d0` как
не возвращающегося вызова декомпилятор перестал считать литералы за ним
продолжением потока. Сохранённый listing функции ещё включает `c503c..c504b`:
это **литералы**, а не исполняемые инструкции worker. Граница кода — `c503c`.
Названия и прототипы декомпилятора не являются доказательством ABI.
Двойной CRC, остаток деления в `r2:r3` и адреса литералов проверены по A32.
IDA Free 9.4 найдена на X:, но её доступный процессорный модуль не поддерживает
этот ARM ELF; анализ с помощью IDA здесь не заявляется.

Файл `work-tx-worker.c` — новое имя изолированной единицы переноса в уже
существующем каталоге work-gen. Это не заявление о наличии такого имени
файла в исходниках производителя. Старый `work-gen.c` и общие заголовки
не изменены. Используются уже существующие `vn135_route_chain`, снимок
`vn135_work_job_snapshot[168]` и CRC из `integration/work_tx88.c`.

## Наблюдаемое поведение

1. Число цепей `fe668` сохраняется один раз. Локальные 16 байт времени
   обнуляются; выполняются `5a6b2c(1,NULL)` и имя через `593af8` с аргументом
   `5e977d`. Worker выставляет backend `+105c` в 1, независимо от старого флага.
2. Каждый проход сначала вызывает clock ID 1 и получает интервал `fedc4`.
   `10f544` добавляет миллисекунды: целые секунды, остаток в наносекундах,
   одна коррекция переносом/заёмом. Восстановлен **32-битный знаковый домен
   интервала этого caller**, а не произвольный 64-битный домен общей функции.
   Первые 64 бита времени складываются с переполнением как в ARM;
   наносекунды складываются по модулю 32 бит, затем сравниваются как signed.
   Последнее слово сохраняется. Ошибка clock не обнуляет старое время.
3. Lock `633ba8`, timedwait `(633bc0,633ba8,time)`, unlock. Результаты
   всех трёх вызовов игнорируются. Нет придуманного повтора или deadline.
4. Для каждой цепи заново читается backend `+230`. UART `chain+2b8`
   фиксируется до дальнейших callback. Проверка `56fcc`: ненулевой `+24`
   и состояние `+20` вне 3, 4, 5.
5. В очереди `633bf0` под отдельными парами lock/unlock сначала читаются
   head `+18` и tail `+1c`, затем tail перечитывается. Пустая очередь или
   unsigned tail >=768 завершает **весь проход**, а не только одну цепь.
6. Все 168 байт строки `633c10 + tail*168` копируются в
   `653460 + slot*168`. Индекс `653458` увеличивается с переходом 31→0.
   Затем под ещё одной парой lock/unlock перечитывается и увеличивается
   tail с переходом 767→0. Оба изменения предшествуют UART-вызову.
7. Кадр: `55 aa 21 36 (slot<<3) 01 00 00 00 00`, затем байты строки
   64..75 и 0..63. Исходный CRC вызывается дважды для 84 байт с начальным
   `ffff`; в конце стоят high/low байты. Отправка: `fef0c(uart,frame,88)`.
   Возврат UART игнорируется. Повторных отправок или ремонта частичных
   записей эта функция не вводит; B-01 остаётся отдельным opt-in адаптером.
8. Флаг работы проверяется после прохода. Снятый в wait или первом write
   флаг не отменяет оставшиеся цепи текущего прохода. Выход через `5a52d0(0)`.

## API и ограничения

`work_tx_worker_135.h` задаёт проекции полей и явные callback границы.
Числовые адреса в `call` служат идентификаторами исходных операций; они
не исполняются и не преобразуются в адреса функций хоста. Возвращаемый
`VN135_TX_THREAD_EXIT` — маркер конца offline-потока, а не успех оборудования.
Все достигнутые callback обязательны, реальные OS/UART defaults отсутствуют.

Входная очередь имеет 768 строк, таблица — 32; память не пересекается,
указатели стабильны, число цепей укладывается в предоставленные массивы.
Callbacks сериализованы и обеспечивают завершение теста. Повреждённый индекс
выходной таблицы вне 0..31 исключён из контракта: оригинал сначала выходит
за таблицу при копировании, затем разыменовывает NULL при формировании кадра.
Эта ошибка не маскируется новым успешным поведением.

Снимок 168 байт остаётся историческим представлением для сравнения.
Он не передаётся в native `struct work`; pool/Stratum/submit_nonce здесь
не дублируются. Исходный повтор 32 слотов **не доказывает свежесть nonce**.
Ограничение 32 отправок в существующем native channel не снято.

## Проверки

```sh
make -f integration/work-tx-worker-135.mk CC=gcc TX_DIR=build/tx-gcc all sanitize negative regressions
make -f integration/work-tx-worker-135.mk CC=clang TX_DIR=build/tx-clang all sanitize negative regressions
clang --analyze -I. -Iinclude -std=c11 -Wall -Wextra -Wpedantic -Xanalyzer -analyzer-output=text src/backend/work-gen/work-tx-worker.c
```

Интерпретатор исполняет немодифицированные ARM-инструкции worker, predicate,
CRC и временного helper. Подменяются перечисленные в evidence внешние границы,
включая memcpy и ABI signed division. Это локальная ограниченная модель ARM,
не аппаратный эмулятор всей прошивки. Единственное добавленное в тесте
инструкционное правило — точный UMULL по `10f584`; ADC и остальная арифметика
используют имеющийся интерпретатор. Native тесты отдельно проверяют память
и сопоставляют формат с ранее проверенным TX88 encoder.

Первый полный запуск original-сравнения: 674 сценария worker, 885 вариантов
времени, 22842 внешних события, 6283243 шага. Native: 3779 сценариев.
Отрицательные проверки компилируют 16 семантически ошибочных вариантов:
baseline обязан пройти, каждый mutant — дать явное несовпадение с fixtures
оригинала. Crash/timeout/ошибка компиляции не считаются успешным обнаружением.
Локально весь указанный набор прошёл на GCC 11.4 и Clang 14, включая
ASan/UBSan с проверкой утечек и clang analyzer без диагностик. Регрессии
work-route: 7 имён, 16 снимков caller, 10 выборов, 2 набора потоков;
TX88: 128 кадров и 36 CRC; native bounds: 11225 проверок.
Дополнительно проверен прежний потребитель nonce-снимка: native SHA KATs,
фикстура кандидата, guards, 176 вариантов фрагментации и lookup failures,
плюс 864 сравнения подготовки nonce с оригиналом на каждом компиляторе.
Логи: `build/b04-logs/`; результаты опубликованного head доступны в PR/CI.

ASan/UBSan собирают новые native проверки и регрессии формата с non-PIE
из-за ранее воспроизведённой проблемы запуска PIE ASan в этой WSL-среде.
Это флаги тестовых исполняемых файлов, не production.

Не проверены реальные потоки/гонки, OS timedwait, UART helper и аппаратный ACK,
производитель входной очереди `c2498`, полный RX worker `c4054`, запуск плат,
регистрация T21 device_drv и живой пул. Принятых шар этим PR не заявляем.

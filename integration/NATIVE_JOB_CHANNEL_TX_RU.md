# A-16: настоящее задание cgminer → общий канал → учёт результата

Задача #56; общая координация #2. Новая opt-in интеграция, **не восстановление
ещё одной vendor-функции и не готовый производственный драйвер**.
База: `12446bed78a060a49364a80bcbfb4340b13f4f27`, дерево
`2e73cb80b2ccbb15d24d9a7deb3c51f65bcd23ac`.

## Реализация

`integration/native/native_job_channel_tx.c` добавляет только
`dizzass_native_job_channel_send`. Существующие функции используются напрямую:

1. `dizzass_jobs_prepare_tx88` кодирует пакет и резервирует слот, удерживая копию
   **настоящего** `struct work` через `copy_work_noffset`. До отправки запись PREPARED.
2. `dizzass_uart_channel_send` получает именно сохранённый `prepared.packet`,
   один раз, через тот же объект A-14, которым пользуются команды A-15.
3. `dizzass_jobs_finish` получает классификацию фактического результата.

Кодировщик повторно не вызывается после резервирования. Нет нового work-типа,
реестра, назначателя слотов, владельца fd, SHA, CRC или цикла write. Уже имеющаяся
`native_tx_channel.c` не переписывалась: это другая, прежняя интеграция с прямым
`posix_tx88`, которую нельзя использовать одновременно в обход нового gate.

## Когда задание становится доступным для проверки ответа

Только `status == OK`, `written == 88` и `error == 0` дают `DIZZASS_TX_WRITTEN`.
Любой другой результат после входа в канал даёт `DIZZASS_TX_UNCERTAIN`:
частичная запись, нулевой результат, отказ остановленного канала, истёкшая очередь,
полная, но опоздавшая передача и противоречивый ответ нижнего слоя.

Это намеренно консервативная новая политика. A-14 не сообщает, был ли достигнут
низкоуровневый write. Поэтому из `written == 0` нельзя автоматически вывести
`NOT_SENT` и разрешить повторное использование слота. Даже заведомо безвредный
отказ очереди здесь расходует слот до внешне подтверждённой смены эпохи.
При подготовительной ошибке запись не резервируется и finish не вызывается.

После неопределённой передачи или ошибки finish адаптер дополнительно вызывает
`channel_stop(..., 0)`. Запрещается дальнейший TX через gate, но уже активная
чужая передача может ещё выполняться. `stop_status == ETIMEDOUT` **не разрешает
закрыть fd**. Адаптер не сбрасывает эпоху, не выполняет pause всего реестра,
не повторяет пакет и не объявляет очередь ASIC очищенной.

Receipt сохраняет отдельные признаки/результаты prepare, channel и finish,
точный ticket, размер кадра, исходные transport status/written/error и результат
запроса stop. Нулевые поля раннего отказа не означают успешную отправку: проверять
признаки вызовов. outcome и finish_status значимы только при finish_called.

## Владение и ещё не решённые границы

Отложенная pthread cancellation отключается до подготовки, остаётся отключённой
на всё время send/finish/stop и восстанавливается после записи результата.
Это закрывает разрыв, при котором A-14 уже завершила свой учёт, но отмена не
позволила вызвать jobs_finish. Ожидающая отмена всё ещё может помешать доставке
receipt вызывающему. Освобождение исходного work остаётся обязанностью вызывающего.
Асинхронная cancellation, обработчики сигналов и concurrent destruction запрещены.

jobs и gate должны относиться к **одной подтверждённой извне цепи/сессии**.
Адаптер не устанавливает соответствие fd ↔ chain и не проверяет физическую модель.
Source и строки должны быть живыми и неизменными на время вызова. Копия work
не удерживает pool по счётчику ссылок: время жизни pool остаётся в ядре.

**RX может увидеть PREPARED до finish.** Приём/проверку ответа надо согласовать с
этим промежутком — через задержку обработки или внешнюю синхронизацию.
Тест проверяет именно PENDING на этой границе, не маскирует её ранней публикацией.
Буферизация ранних ответов, атомарная проверка актуальности перед submit,
полная остановка RX/ASIC и безопасная смена эпохи этим этапом не реализованы.
32 слота по-прежнему нельзя оборачивать по модулю и переиспользовать после таймаута.

Проверяются Git blob SHA и SHA-256. Подготовщик не обращается к сети, не меняет
Git refs и не исполняет reference ELF. Offline `--source-tree` проверяет байты,
не выдавая архив за исходную историю коммитов. Предыдущие PR не слиты и не приняты
этими тестами. Файлы Codex и заблокированный A-04 не изменены.

## Фактически выполненные локальные проверки

GCC 14.2 и Clang 17, отдельные каталоги обычной и ASan/UBSan-сборки:

- **269 контрольных сценариев**. Настоящие work, prepare/finish, native nonce/hash
  и gate; целый нижний вызов передачи в этой группе задан сценарием.
  216 сочетаний status/count/error проверяют передачу результата, а не достижимость
  всех комбинаций на физическом порту. Проверены PENDING до send, точное кодирование,
  четыре частичных отказа strdup в настоящем копировании, pause во время send,
  deferred cancellation, все 32 слота, старый epoch и карантин после retire.
- **6 сценариев PTY**. Реальная передача 88 байт с последующей проверкой сохранённого
  native work после освобождения source; остановленный/истёкший канал; смешанная
  передача **32 native jobs и 8 команд — 2 904 байта** с пятью producer-потоками.
  Все полные кадры сравниваются, затем все 32 сохранённых задания проверяются
  штатной математикой cgminer на локальном известном nonce.
- Один PTY-сценарий **явно гибридный**: первые 7 байт записываются настоящим write,
  затем тест вводит EIO. Это не естественное отключение ASIC. Проверяются точный
  префикс, карантин и запрет следующей команды.
- Отдельный сценарий использует настоящее заполнение PTY большой служебной
  передачей: native job истекает в очереди, получает карантин, stop возвращает
  ETIMEDOUT, а fd сохраняется до окончания активной передачи. Байты задания не
  обнаруживаются в собранном потоке. Служебный filler не является mining work.
- **15 мутаций** компилируются и отклоняются через `NATIVE_JOB_TX_ASSERT`, exit 1;
  baseline проходит тот же набор. Ошибка сборки, сигнал или timeout не засчитываются.
- **12 проверок staging**, в Python и `-O`; tamper, лишние include-файлы, symlink,
  запрещённый каталог и перезапись отклоняются.
- Проверка символов подтверждает настоящие copy/free/test_nonce/fulltest/SHA и
  отсутствие старого прямого TX/session path. Network/USB setup имеют abort-guards.
- Clang analyzer без сообщений; восемь прежних тестов границы native core проходят.

Санитайзеры охватывают новый код, связанные модули и включённый в тест root
cgminer.c. Остальные штатные объектные файлы ядра собраны обычным baseline build;
полная инструментированность всех библиотек не заявляется. Новый TSan-прогон
и target ARM-проверка не выполнялись.

Локально отсутствуют libusb development headers. Настоящий upstream Autotools
был настроен с `--enable-ants2 --disable-curses`, без запуска его драйвера;
GCC собрал штатные core objects. Обе тестовые конфигурации используют эти же
core objects, но каждая заново компилирует свой root cgminer.c и адаптеры.
Это **не стандартная Icarus baseline-сборка**. В PR workflow предусмотрена обычная
Icarus-конфигурация и отдельный core build для каждого компилятора; её результат
нужно смотреть отдельно по точному head, не выводить из локального успеха.

Начальные локальные ошибки сохранены в логах: создание нового файла до mkdir;
затем проверка символов обнаружила, что linker удалил неиспользуемый USB abort-guard
в non-USB конфигурации. В новом make-target guard закреплён через --undefined.
Тесты и санитайзеры не ослаблены; исходники прежних модулей не правились.
Autoreconf локально регенерировал два отслеживаемых jansson-файла; перед фиксацией
их точные исходные байты восстановлены, в commit они не входят.

## Повторение

После получения точных dependency commits и обычной native configure/build:

```sh
python3 tools/prepare_native_job_channel.py
make -f Makefile -f integration/native-job-channel-tx.mk CC=gcc NJ_DIR=build/a16-gcc native-job-test native-job-negative
make -f Makefile -f integration/native-job-channel-tx.mk CC=gcc NJ_DIR=build/a16-gcc-san SANITIZE=1 native-job-test
python3 integration/tests/test_native_job_channel_negative.py --staging-checks
python3 -O integration/tests/test_native_job_channel_negative.py --staging-checks
# Повторить CC=clang с отдельными каталогами.
```

Команды и CI не меняют production Makefile, не регистрируют device_drv,
не отправляют команды физическому UART, не меняют пулы/devfee/частоты/напряжения.
Локальный известный nonce — тест настоящей математики, **не принятая пулом шара**.

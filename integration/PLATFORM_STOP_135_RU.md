# A-02 — платформенный вызов остановки `0xfe218`

Задача #7, координация #2. База `12446bed78a060a49364a80bcbfb4340b13f4f27`,
дерево `2e73cb80b2ccbb15d24d9a7deb3c51f65bcd23ac`.
A-01 / PR #6 и Codex B-01 / PR #5 не включены в этот независимый PR.

## Диспетчер и выбор метода

`fe218` содержит три инструкции: загрузить смещение, прочитать указатель
из глобального слота `654b34`, сделать хвостовой переход через него.
У него нет собственного UART, ожидания, проверки backend или новой диагностики.
Он не получает backend как осмысленный аргумент: перед переходом r0 содержит
сам адрес метода. Возвращаемый регистр вызывающая `663cc` не использует.
Поэтому новый интерфейс `vn135_platform_stop_dispatch_135` — **void**, не
искусственный статус успешного отключения.

Прочтён исходный инициализатор `fb994`; 45 исполнений от его начала до первой
записи слота проверяют сочетания первого селектора 0..4, второго 0/4/7 и
третьего 0/1/0xffffffff. После нужной записи исполнение прекращается: остальная
инициализация и её аппаратные операции не выполняются и не объявляются готовыми.

| Первый селектор `fb994`, сохраняемый в `654b08` | Метод `fe218` |
|---|---|
| 0 | `115d88` — условная последовательность изменения двух слов |
| 1 | `11fda4` — только непрозрачная арифметика/чтения, без внешних эффектов |
| 2 | `11bfbc` — одна `BX LR`, выбранный AML-путь |
| 3 | `1238cc` — одна `BX LR` |
| 4 | `10cf34` — одна `BX LR` |

Это НЕ тот же селектор, что второй аргумент инициализатора: он сохраняется
в `654b0c` и возвращается `fdfbc`. В старых отчётах оба вида параметров местами
названы platform; равенство чисел между ними нельзя использовать как доказательство
одинаковой платы. Никакого физического обнаружения T21 не произведено.

В C отсутствует автоматический switch платформ и fallback на no-op.
Вызывающая сторона обязана предоставить инициализированный слот с известным
методом. Замена метода между вызовами и повторный вход проверены. Context —
новая возможность типизированного host-интерфейса, не исходный параметр ARM.

## No-op действительно подтверждён, а не придуман

`vn135_platform_stop_noop_135` представляет четыре выбранных метода без записи
состояния и внешних вызовов. Для `11fda4` сравнение выполняет исходные загрузки
и арифметику; произведение соседних 32-битных чисел имеет нулевой младший бит.
Прежний интерпретатор не менялся. Равенство времени исполнения, регистров
caller-saved и микроархитектуры не утверждается.

No-op не возвращает 0 и не означает завершение другого потока, снижение частоты,
выключение питания или подтверждение ASIC. Соседние функции, выполняющие GPIO,
в это тело не включены. Неизвестный метод нельзя заменять этим no-op.

## Ветка `115d88`

Для controller=0 добавлена `vn135_platform_stop_xil_135`. Суффикс xil —
проектное обозначение ветви из области Xilinx. В самом теле нет строки пути;
точное владение производителя этим исходным файлом не заявляется. Проектный
`libbitmain/src/platform-stop.c` — отдельная офлайн-единица, не восстановленное
имя файла производителя.

Обычный путь оригинала:

1. Через getter `fe024` прочитать байт `654b22`. Если он ненулевой — возврат.
2. Вызвать `112320(27)`, снять бит 22 из полученного слова.
3. Вызвать `111c48(27, word & ~0x00400000)`.
4. Вызвать `fe7b4()`, снять бит 6 из его результата.
5. Вызвать `fe83c(word & ~0x40)` и завершить.

Байт не проверяется повторно после нижних вызовов. Второе слово читается
после первой записи, не заранее. Коды обеих записей игнорируются: новая
проверка ошибки, повтор, rollback или задержка не добавлены. Точное электрическое
назначение битов этим тестом не устанавливается.

Четыре нижние операции — явно заданные callbacks; их тела здесь не перенесены.
`fe024` исполняется в оригинальном тесте, а в C использует явную ссылку на байт.
Подструктуры не накладываются через cast на vendor ABI. Binding/таблица callbacks
стабильны; данные могут изменяться только на последовательных границах вызовов.
При ненулевом байте callback-таблица может отсутствовать, поскольку недостижима.

## Переиспользование

Существующая `vn135_backend_stop_mining_135` подключена к новому диспетчеру
через её прежний callback `step(fe218, 0)`, без изменения `base.c` и старых типов.
В ARM-сравнении исполняется оригинальная `663cc`, затем настоящий `fe218` и
выбранный нижний метод, а не успешная заглушка вместо этих трёх тел.
Остальные операции родителя (`b8e54`, `65b3c`, потоки, задержка и лог) остаются
явными тестовыми границами. A-01 не заимствован из ещё не принятого PR.

Прежний native `driver-bitmain.c` имеет собственную модель команд, а не этот
глобальный слот. Нельзя подменить им `fe218` только по похожему смыслу остановки.
Новый алгоритм UART, CRC, PLL, работы/пула или второй майнер не добавлен.

## Выполненные проверки

- **659** прямых сравнений методов: **1 516** событий, **20 065** ARM-шагов.
  Проверяются все 256 значений байта, однобитовые/полные слова, порядок вызовов,
  изменение байта и второго слова в callbacks, ошибочные результаты записей,
  отсутствие незаявленных записей вне стека.
- **8** сценариев смены метода и повторного входа в диспетчер.
- **60** вложенных сценариев `663cc -> fe218 -> selected method`:
  **314** событий, **4 019** шагов, сравнение состояния родителя и границ вызовов.
- **45** проверок установки метода исходным инициализатором; не полный запуск.
- **527** нативных сценариев, **5 411** проверок, включая составной mining-stop,
  защитные поля, NULL у недостижимых callbacks и повторный вход.
- **8** отдельно скомпилированных неправильных вариантов отвергаются именно
  несовпадением с оригиналом. Ошибка сборки, таймаут или crash не считается PASS.

На GCC и Clang выполнены новые наборы, ASan/UBSan, неизменённые mining-stop и
exit-cleanup регрессии. Статический анализ нового C-модуля выполнен отдельно.
Точные команды, результаты и ограничения — в логах данного этапа. CI нового PR
проверять по его SHA; сам файл workflow не свидетельствует о прохождении.

```sh
make -f integration/platform-stop-135.mk CC=gcc PLATFORM135_DIR=build/a02-gcc dizzass-platform135-original dizzass-platform135-test dizzass-platform135-negative
make -f integration/platform-stop-135.mk CC=gcc SANITIZE=1 PLATFORM135_DIR=build/a02-gcc-san dizzass-platform135-test
# CC=clang — обязательно другой PLATFORM135_DIR.
```

## Граница и дальнейшие задачи

Проверки конечны, все callbacks последовательны. Нет реального MMIO/UART,
блокировок, гонок, ответов чипа, электрического отключения или аппаратной приёмки.
Производственная сборка, лимит 32 слотов и настройки оборудования не изменены.
Старые исходники и доказательства сохранены. Безопасные UART/владение аргументами
остаются отдельными задачами; область Codex B-01 не затрагивалась.

Для продолжения именно Xilinx-ветви остаются `112320/111c48` и `fe7b4/fe83c`.
Для выбранного AML-пути `fe218` нижней работы нет; следующий отдельный узел
общей очистки — `58d08` (его тело и назначение ещё требуют самостоятельного разбора).

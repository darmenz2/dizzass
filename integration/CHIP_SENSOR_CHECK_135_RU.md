# A-10 — доступность датчика температуры чипов, `0x78eb8`

Задача #44, координация #2. Независимая база:
`12446bed78a060a49364a80bcbfb4340b13f4f27`, дерево
`2e73cb80b2ccbb15d24d9a7deb3c51f65bcd23ac`.

## Что восстановлено

`vn135_backend_has_chip_sensor_135` в проектном файле
`src/backend/chip-sensor-check.c` переносит управляющее тело `78eb8`.
Это **проверка существования хотя бы одного подходящего датчика**, не чтение
температуры, проверка свежести, калибровка или аппаратный тест.
Тело не содержит строки исходного имени файла; проектный путь не объявляется
доказанным именем производителя.

Исходная последовательность:

1. Через `a720c` разрешить модель и получить число датчиков из model+58 -> +18.
2. Сохранить это знаковое число, затем один раз вызвать `fe668` для числа цепей.
3. Проходить текущий массив backend+230. Предикат `56fcc` допускает только
   присутствующую цепь со знаковонезависимой проверкой `(state - 3u) > 2u`.
4. Для допустимой цепи с положительным числом датчиков взять chain+290.
5. Вернуть **1** на первом датчике с видом доступа **1 или 2**, ролью **2**
   и состоянием **не 3**. Если совпадений нет, вернуть **0**.

Состояние **0** не исключается. Показания, ошибки чтения, смещения, отметки
времени и общее состояние запуска backend не проверяются. Другие неисправные
датчики и цепи не отменяют уже найденное совпадение. Это не «все датчики исправны».
Вид 4 эта функция не принимает: в общем мониторе для него есть отдельная ветвь.
Вид/роль/состояние — полные 32-битные поля, не усечённые байты.

Число датчиков захватывается **до** count-callback. Замена модели в callback
не меняет текущий лимит обхода. Замена массива цепей учитывается, поскольку
он читается позже. Отдельное поле chain.sensor_count не используется.
При неположительном количестве цепей возвращается 0; count вызывается и тогда,
когда число датчиков уже неположительно. Нового успеха по умолчанию нет.

## Переиспользование и интерфейс

Переиспользованы существующие general/model/chain/sensor представления.
Прежний `general_alive` имеет file-local видимость в base.c. Вместо изменения
этого файла и общего интерфейса в новом модуле оставлено то же двухполевое
выражение `56fcc`; другого алгоритма управления цепями не создаётся.

Единственный callback — обязательный `chain_count(context)`. Функция возвращает
исходный булев результат. Подключение из `general_ops.call` по идентификатору
`VN135_G_CHIP_SENSOR_TEST` показано в составных тестах. Count направляется в тот
же внешний `VN135_G_CHAIN_COUNT`. Автоматического подключения к device_drv нет.

Оригинальные `a720c` и `56fcc` исполняются внутри прямого ARM-сравнения, а не
подменяются ответом 1. Непрозрачные произведения соседних целых в исходнике
также исполняются; их младший бит всегда нулевой. Утверждения о совпадении
тактов, микроархитектуры и побочных каналов отсутствуют.

## Составная проверка

Новый набор исполняет **полную исходную `79778` вместе с исходной `78eb8`**,
а со стороны C — существующий общий монитор с новым предикатом. Обработчик
прежнего теста сохраняется как наблюдатель границы; его заданный возврат
отбрасывается перед входом в настоящее тело `78eb8`.

Проверены пропуск через условия родителя, короткое замыкание после `772d8`,
успех kind1/2, отсутствие датчиков, отдельный fallback kind4 и аварийное
событие/попытка создания процедуры остановки. Прочие нижние действия монитора
остаются последовательными тестовыми callbacks; реальных потоков нет.

A-07, A-08, A-04 и ветки Codex **не включены**. Поэтому полный путь
`6ec4c -> 58b50 -> b7798`, вся инициализация, реестр ответов и первый запуск
T21 этим PR не объявляются готовыми. Новая проверка закрывает ещё одну
явную зависимость, а не заменяет интеграционную приёмку.

## Ограничения

Все достигнутые указатели и размеры валидны. Положительные количества
помещаются в выделенные массивы; захваченные объекты остаются живыми.
Единственный count-callback может последовательно менять описанные поля,
после него память стабильна. Реальные гонки, повреждённые объекты и произвольные
некорректные указатели не входят в проверенный контракт.

Нет реальных датчиков, измерений, аппаратных ответов, UART/GPIO, mutex или
потоков, изменения напряжений/частот/защит/пулов/devfee. Лимит 32 аппаратных
work-слотов, производственное ядро и прежние файлы сохранены. Успех CI относится
к конкретному head/test-merge; он не является слиянием PR или разрешением
на аппаратный запуск. Дальнейшее объединение температурных этапов требует
независимого ревью и явной составной проверки.

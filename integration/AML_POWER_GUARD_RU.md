# AML: питание, температурная отсечка и граница остановки

База: `df3ddd1220c3a36bd5561412e3ba1801dcce910d`. Архитектура — настоящее ядро
cgminer; вторые work/SHA/Stratum/submit не добавляются. Полного аппаратного
запуска T21 этот набор **не завершает**. Все проверки ниже программные.

## Подтверждённый оригинальный маршрут

Оригинальный вызывающий участок AML передаёт селектор платформы 2. Внутренняя
инициализация выполняется до первой периферийной операции и устанавливает:

- PSU ON: `0x11c978`, через исходный диспетчер `0xfe310`.
- PSU OFF: `0x11ca74`, через `0xfe398`.
- Reset цепи: `0x11bc14`, через `0xfde14`.
- Число доступных цепей: `0x11b6c8`, возвращает 3.

В новых сравнениях исполняются и косвенные BLX-переходы оригинальных диспетчеров,
и выбранные процедуры, не только чтение адресов. Используется уже существующий
ARM32Verify с BLX, без изменения исторического интерпретатора. Это ограниченная
локальная модель инструкций, не независимый сертифицированный ARM-эмулятор.

PSU использует GPIO 437: sysfs-значение 0 для включения, 1 для выключения.
Reset использует таблицу 454/455/456 для цепей 0/1/2, значение 0 для assert.
Это числовые привязки именно исследованного AML-образа; не универсальная карта
любой контрольки T21 и не измеренная полярность на физическом выводе.

На основании подтверждённого ограничения цепей потребитель hwscan теперь
отклоняет nominal_boards > 3 и ID >= 3, а не допускает весь внутренний массив
на 16 записей к AML-каналу. Физический hwscan и runtime-снимок не получены.

## Почему исходный return 0 недостаточен

В ограниченных оригинальных путях воспроизведены три особенности:

1. Если флаг инициализации PSU не равен 1, OFF возвращает 0 без GPIO-записи;
   ON в таком состоянии возвращает -1.
2. GPIO-helper после успешного fopen игнорирует результат fprintf и fclose.
   Подставленные ошибки этих двух операций не мешают возврату 0.
3. Верхний shutdown вызывает PSU OFF, затем assert reset трёх цепей и очищает
   два программных поля. Ошибки reset не проверяются. При ошибке самого PSU OFF
   процедура завершается до reset. В этом участке нет подтверждения снижения
   напряжения, отсутствия новых nonce, аппаратного ACK или очистки RX.

Это наблюдения о конкретных процедурах с явно подставленными внешними операциями,
а не утверждение, что физический VNish всегда работает неправильно или что все
остальные защитные механизмы отсутствуют.

## Новый код

`aml_power.c/.h` формирует типизированные запросы GPIO и воспроизводит исходную
температурную проверку: сначала PCB >= limit, затем chip >= limit. Копируется
целочисленное сравнение и приоритет, не вся исходная диагностика и обработка
событий. Дополнительная ветка подробного per-core логирования не переносится.
Пределы и единицы передаются вызывающим кодом: T21-настройки не угадываются.

Отдельная новая политика телеметрии отклоняет неполный снимок, неправильную эпоху,
будущую метку времени, просроченный возраст, отказ вентиляторов или PSU.
Нет значений «датчик исправен» по умолчанию. Источник реальных измерений и
периодический мониторинг остаются обязанностью аппаратного драйвера.

`gpio_value_io.c/.h` — фактические Linux openat/read/write/close для уже
предоставленного доверенного каталога конкретной GPIO-линии. Записывается один
байт value, проверяются возвраты write и close. Отказы не превращаются в успех.
Перед записью проверяются direction=out и active_low=0; эти атрибуты не меняются.
Нет export/unexport, угадывания путей, системных shell-команд, настройки питания.
Файлы-атрибуты должны быть обычными файлами; symlink и FIFO не допускаются.
Сами sysfs class-каталоги могут быть ссылками: вызывающий код обязан заранее
предоставить правильно разрешённый каталог и проверить его связь с номером pin.
Дескриптор каталога заимствован, открытые атрибуты закрываются здесь.

Новый consumer использует legacy ABI для совместимости с исследованным образом.
Документация ядра отмечает устаревание sysfs GPIO и влияние active_low на значение.
См. https://cdn.kernel.org/doc/html/latest/userspace-api/gpio/sysfs.html .
Это не универсальная рекомендация использовать sysfs для новых платформ.

Успешная системная запись доказывает только её программный результат. Она не
измеряет напряжение на хешплате. Sysfs callback ядра может блокироваться: жёсткая
гарантия времени отключения не заявляется. EINTR повторы ограничены; close не
повторяется. Ошибка close после write отражается как неопределённый результат,
с сохранённым фактом записи одного байта.

`native_power_guard.c/.h` соединяет новое аварийное действие с существующими
native TX88-каналами: сначала stop всех существующих каналов общего PSU,
затем попытка PSU OFF и reset каждой из трёх цепей. При отказе одного действия
остальные не пропускаются. Результат содержит семь отдельных кодов и маски
попыток/успешных возвратов. Отсутствующий GPIO callback — ошибка, не заглушка.
Отмена pthread на время этой последовательности отключена. Вызывающий код
исключает конкурентное уничтожение и сериализует вызовы; I/O-callback не должен
повторно вызывать этот guard. Полный concurrent stress/TSan здесь не выполнен.

Остановленные каналы остаются остановленными даже после охлаждения. Функция
check без превышений говорит только о пригодности входного снимка, не об
аппаратной готовности и не о состоянии каналов. Ошибочная конфигурация пределов
тоже вызывает best-effort shutdown перед возвратом ошибки. Контроль входных
данных не заменяет физических температурных/тахометрических/PSU-драйверов.

**Функция проверки сама не запускает мониторинговый поток.** В основной бинарник
модуль не зарегистрирован, следовательно, защита реальной фермы этим коммитом
не включается. Существующие аппаратные защиты нельзя отключать. Нет готового
последовательного запуска PSU, проверки power-good, адресации/инициализации
всех чипов, термодатчиков и аппаратного watchdog. ON пока только кодирует запрос.

## Граница очистки: отрицательный контроль

Новый native-тест специально нарушает предусловие CLEAN DEVICE при создании
второго канала: старый программный канал уничтожается, создаётся новый с новой
эпохой, но аппаратной очистки между ними нет. Два задания имеют одинаковый
заголовок и wire-пакет, разные job_id. Старый ответ с корректным nonce и CRC
может разрешиться в новый job_id. Проверяется реальное ядро cgminer, не SHA-заглушка.

Это **контрпример к доказательству через один epoch++**, не новая операция
resume и не эксперимент на T21. Штатный канал по-прежнему не использует слоты
повторно: после 32 успешных отправок EXHAUSTED. Отрицательный контроль не снимает
ограничение. Кодировщик reset, запрос выключения, GPIO-readback, тишина UART
за произвольное время и очистка только Linux-буфера не объявляются доказанной
границей. Нужен установленный физический механизм остановки и сброса вычислений,
подтверждение его завершения, затем очистка всех аппаратных/программных RX-очередей
в отсутствие новых источников старых ответов.

## Воспроизводимые проверки

- 7 исходных установок таблицы callbacks с разным тестовым chip_count.
- 32 проверки PSU ON/OFF и 30 проверок reset через оригинальные диспетчеры.
- 32 оригинальные shutdown-трассы; 36 комбинаций libc-ошибок GPIO-helper.
- 832 сравнения температурного предиката и внешних действий оригинала.
- Все 128 комбинаций отказов семи действий новой остановки.
- Реальные временные файлы: запись value, режим/полярность, короткая/нулевая
  запись, EINTR/EIO, ошибка close, symlink и FIFO. Это не физическая GPIO.
- Новый native-тест: три PTY-канала, успешный и ошибочный cutoff, отсутствие
  дальнейших TX, сохранение остановки после охлаждения, контрпример epoch++.

```
make -f integration/aml-power.mk dizzass-aml-power-original dizzass-aml-power-test
make -f integration/aml-power.mk SANITIZE=1 dizzass-aml-power-test
# После стандартной configure/make настоящего cgminer:
make -f Makefile -f integration/native-power.mk dizzass-native-power-test
make -f Makefile -f integration/native-power.mk SANITIZE=1 dizzass-native-power-test
```

Наличие теста не равно прохождению: результаты см. в журнале CI конкретного commit.
ASan/UBSan native-теста не инструментируют все ранее собранные библиотеки. Повтор
Clang пересобирает новые тестовые объекты, не весь upstream. Оригинальный ELF
не запускается как процесс. Питание/пулы/devfee/NAND не менялись. **Это не firmware
release и не завершённый аппаратный запуск; штатный cgminer не заменять.**

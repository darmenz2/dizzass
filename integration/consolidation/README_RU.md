## Проверка именно текущего дерева

После обычной сборки нативного ядра:
```
python3 integration/consolidation/test_runner.py
python3 integration/consolidation/run.py --cc gcc --out build/c01-gcc
```
Точные коммиты из manifest.json должны быть предварительно получены read-only.
run.py сам не скачивает данные, не устанавливает пакеты и не изменяет Git refs.
Для каждой команды сохраняются аргументы, код завершения и SHA-256 полного лога.
Существующий каталог результата не перезаписывается.

current-tree.mk подключается только к тестовым Makefile: положительные составные
проверки компилируют C-файлы из текущего дерева. Старые тела тестов не изменяются.
Дополнительные исторические зависимости берутся через --source-tree . и проверяются
по прежним хешам; они не загружаются из старой ветки в обход текущего кода.
Семантические отрицательные проверки используют эти побайтово равные текущему дереву
копии. План компиляции отдельно отклоняется, если положительный тест ещё берёт
C-файл из каталога сохранённых зависимостей.

CI: три непересекающиеся группы на GCC/Ubuntu 22.04 и Clang 17/Ubuntu 24.04.
Общий итог требует успеха всех шести заданий. Независимая pthread-cancel проба
обязательна перед sanitizer-проверками. Неудачные проверки не подавляются.
--no-sanitize означает только функциональный промежуточный прогон, не полную приёмку.
Старые ошибки Clang 14/R-01 этим не объявляются исправленными; draft #59 не включён.

## Граница приёмки

Принимаются исходники и воспроизводимые host/offline-проверки. Процесс cgminer
запускается только с --version; тесты используют явно выделенные host PTY,
нативные вспомогательные функции и известные nonce/задания, а не реальные ASIC.
Ни слияние, ни зелёный CI не подтверждают первую шару, аппаратное отключение,
готовность автотюна, барьер очистки старого RX или безопасное повторное использование
слотов. Не завершены очередь ранних ответов, согласование check/submit и подключение
полного аппаратного жизненного цикла. Эти границы остаются в исходных контрактах.
Рабочие ветки, repair/* и upstream/ckolivas сохраняются; массового удаления нет.

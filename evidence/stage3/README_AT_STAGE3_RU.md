# VNishNet T21 AML 1.3.5 — модульная реконструкция, Stage 3

## Результат этого этапа

Продолжение `VNish135_modular_cgminer_overlay.zip`: восстановление по наблюдаемым
путям исходников, с добавлением модулей поверх публичного cgminer. Монолитного
файла, симулятора майнера и успешных заглушек аппаратных функций здесь нет.

| Показатель | Предыдущий overlay | Stage 3 |
|---|---:|---:|
| Наблюдаемые исходные пути | 45 | 45 |
| Частично восстановленные исходные файлы | 1 | 3 |
| Невосстановленные файлы, исключённые из сборки | 44 | 42 |
| Компилируемые единицы C, включая новый CRC5-модуль | 2 | 4 |
| Публичные функции нового интеграционного API | 7 | 13 |
| Сравнения с исходными ARM-инструкциями | 2 546 | 5 765 |

13 функций API не означают 13 полностью восстановленных функций оригинала:
например, упаковка AML-кадра вынесена в отдельную новую функцию из одной исходной
процедуры. 45 найденных путей не являются гарантированно полным списком файлов VNish.

**Получены исходники и библиотеки, не рабочий майнер и не install-прошивка.**
Проверка на физическом T21 не проводилась. Штатный `/usr/bin/cgminer` не менять.

## Что добавлено

### `libbitmain/src/pll.c`

Два расчёта делителей PLL, восстановленные по процедурам `0x000ff288` и
`0x000ff660`. Восстановлены вычислительные циклы, порядок кандидатов, ограничения
VCO, преобразования double/int32, условия принятия кандидата, ранний выход и
неуспешный результат. Логирование и избыточная обфускация управляющего потока
не воспроизводятся. Алгоритмы намеренно не объединены в «улучшенную» формулу:
у них различаются порядок обхода, округление и пороги.

На каждом из 619 входов для каждого алгоритма совпали код возврата и все 32 байта
результата с исполнением исходных ARM-инструкций в локальном ограниченном
интерпретаторе. Это проверка выбранных входов, не доказательство для всех чисел
и режимов процессора. Старой выдуманной формулы `MHz * 1000` нет.

### `libbitmain/src/aml/chip.c`

Восстановлены фреймирование команды префиксом `55 AA`, выделение памяти,
последовательность lock → одна запись → unlock → release и возврат ошибки при
неполной записи. Не создаётся фиктивная успешная передача: результат зависит
от реально переданного пользователем обработчика `write`.

Обработчики аллокатора, синхронизации и записи передаются через новый API.
Открытия устройства, самостоятельного обращения к UART и запуска хешплат нет.
В оригинальных тестовых вызовах эти внешние операции тоже явно подменены и
сравниваются их порядок, аргументы и байты. Проверены отказ выделения памяти,
отсутствие UART, короткая, нулевая, отрицательная и избыточная длина записи.

Восстановлена целочисленная маска цепи из `0x00118180`; результат исходного
определения модели задаётся явно. Само определение модели не восстановлено.

### `libbitmain/src/chip/chip1398.c`

Добавлено формирование слова PLL-регистра `0x08` из четырёх делителей —
517 сравнений на границе вызова оригинального `SET_CONFIG`.
Сохранены ранее проверенные преобразования TICKET_MASK, CLOCK_DELAY,
SWEEP_CLOCK, ANALOG_MUX, MISC_CONTROL и девятибайтовый пакет SET_CONFIG.

Из адреса `0x005ebea8` также восстановлена 56-байтовая запись ограничений PLL,
на которую ссылаются два вызова в модуле `chip1398.c`. Это **не профиль безопасных
частот для T21**. Наличие chip1398 в бинарнике пока не доказывает выбор этого
драйвера конкретной моделью T21. Связь модели и драйвера остаётся открытой.

Не заявляется, что ранее исследованный SET_CONFIG уже прослежен через весь
диспетчер `0x000d26ac` до AML-send. Это отдельные проверенные границы; соединять
их в готовый аппаратный тракт без проверки диспетчера нельзя.

## Структура

```text
libbitmain/src/
├── pll.c                    # две вычислительные процедуры
├── aml/chip.c               # фреймирование, передача через callbacks, маска
└── chip/chip1398.c          # слова регистров, пакет, запись ограничений PLL
include/xminer/recovery/
├── pll.h                    # новые имена API и восстановленные смещения
├── aml_chip.h               # явно передаваемый транспорт
└── chip1398.h
reconstruction/support/crc5.c
src/backend/tuner/           # пути сохранены; алгоритмы пока не реализованы
src/backend/work-gen/        # пути сохранены; рабочий тракт пока не реализован
evidence/stage3/             # ARM-листинги и описание границ проверки
evidence/validation/stage3/  # результаты сборок и тестов
```

Остальные наблюдаемые пути, включая `src/frontend`, PSU, I2C, STM, другие чипы
и платформы, сохранены. Невосстановленные единицы имеют явный `#error` и не
попадают в список сборки. `tools/build_source_tree.py` обновляет карту путей,
не заменяя реализованные модули заглушками. EHABI — карта интервалов раскрутки
стека, а не полный перечень функций.

## Сборка и повторение тестов

Из корня распакованного проекта:

```sh
make -f Makefile.recovery clean all test arm evidence-check sanitize
python3 tests/test_assembler.py
```

Нужны Python 3.10+, C-компилятор, Make; для ARM — Clang и llvm-ar. Host-тесты
рассчитаны на Linux. Для пересборки синтетических ARM-fixtures:

```sh
make -f Makefile.recovery fixtures
```

Результаты:

```text
build/libvn135_recovered.a                 # host-библиотека
build/libvn135_recovered-armv7.a           # ARMv7 библиотека, НЕ cgminer
build/differential-results.json           # повторённые 2 546 предыдущих случаев
build/stage3-differential-results.json     # 3 219 новых случаев
build/stage3-interpreter-results.json      # отдельные 1 318 проверок интерпретатора
```

Компиляция: C11, `-Wall -Wextra -Wpedantic -Werror -ffp-contract=off`.
Проверены GCC и Clang; новые дифференциальные случаи повторены на обоих.
Число 3 219 не удваивается из-за повторного прогона другим компилятором.
AddressSanitizer/UndefinedBehaviorSanitizer прошли на двух наборах host C-тестов.
ARM: freestanding ARMv7-A, A32, VFPv3-D16, hard-float; нет Linux sysroot и
проверки исполняемого файла на контрольной плате.

Запрещён `-ffast-math`: PLL использует чувствительные к порядку вычислений
сравнения. Новые проверки указателей/ёмкости буфера/конечных чисел/лимитов
итераций — наши защитные условия, не поведение оригинального API. Структуры
входа и выхода PLL не должны перекрываться. Требуется обычное округление
binary64 без расширенной точности промежуточных результатов.

### Ограничения сравнения

Локальный A32/VFP-интерпретатор не является независимым сертифицированным
эмулятором. Он проверен синтетическими инструкциями и прекращает работу на
неподдерживаемых командах или превышении лимита шагов. VFP-проверки ограничены
конечными нормальными числами и стандартным округлением; исключения FPSCR,
сигнальные NaN, субнормальные режимы и все особенности реального процессора
не моделируются. Исходный ELF не запускается как Linux-процесс. Нет системных
вызовов, обращения к пулу, аппаратуре или сетевым устройствам.

## Наложение на оригинальный публичный cgminer

Зафиксирована база `ckolivas/cgminer`, commit
`b8491c66e7e22f23a9edf095dd1337ee581e88bd`. Это выбранная база интеграции,
не доказанный точный предок VNish. Полное дерево upstream по-прежнему не
включено: повторное скачивание в этой среде завершилось ошибкой DNS. Полная
сборка upstream здесь не проверялась.

```sh
python3 tools/assemble_on_cgminer.py --fetch --output ../cgminer-vnish135
```

Либо с уже имеющимся чистым checkout указанного commit:

```sh
python3 tools/assemble_on_cgminer.py   --source /path/to/cgminer   --output ../cgminer-vnish135
```

Создаётся новый каталог. Существующий checkout не изменяется. Проверяются
commit, дерево, Makefile.am и SHA-256 файлов overlay. При конфликте имён
скрипт прекращает работу. Исходное ядро cgminer, Stratum, другие драйверы,
лицензии и авторство не подменяются. `Makefile.am` подключает четыре единицы
C и новые заголовки. Это пока подключение модулей, не регистрация T21-драйвера.

Тест сборщика проверяет операции с файлами на локальном тестовом Git-дереве,
а не майнинг и не полную сборку настоящего upstream.

## Что осталось

Не восстановлены до рабочего состояния: привязка T21 к правильному драйверу,
инициализация AML и цепей, полный UART/I2C/GPIO-транспорт, установка и чтение PLL
на железе, кэш регистров, PSU, датчики и аварийные защиты, тракт job → nonce →
принятая пулом шара, адаптер устройства в cgminer и состояния автотюна.

`make -f Makefile.recovery full-runtime` намеренно завершается ошибкой.
Это не установочный архив; библиотеку нельзя положить вместо `/usr/bin/cgminer`.

Исходный референс: `reference/cgminer.vendor.elf`, 6 228 004 байта,
SHA-256 `b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.
`dashd`, `hwscan`, `updater`, ядро и WebUI этим этапом не восстанавливаются.

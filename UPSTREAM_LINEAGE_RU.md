# Происхождение cgminer и подготовка форка — Stage 14

## Вывод

Найдена подтверждаемая публичная линия cgminer с Bitmain/S9-изменениями. **Точный
репозиторий, ветка и commit, от которых ответвился VNish 1.3.5, не установлены.**
Поэтому текущий pin `ckolivas/cgminer@b8491c66e7e22f23a9edf095dd1337ee581e88bd`
сохранён как выбранная основа интеграции, а не переименован в «найденный исходник VNish».

## Что проверено в публичном коде

В выбранном `cgminer.c` присутствует Bitmain_SOC `get_work_by_nonce2`: получение
nonce2 и версии, вызов `gen_stratum_work`, установка реального pool, увеличение
`pool->works`. Это соответствует характерной последовательности в исследованной
обёртке `0x300ac`. В `bitmaintech/bmminer-mix` найдено то же семейство функций.

`gen_stratum_work` содержит уже знакомые детали: little-endian nonce2 в coinbase,
счётчик с пост-инкрементом, Merkle-ветви, копирование **112 байт** шаблона,
**32 байта root по +36**, независимые job_id/nonce1/ntime и расчёт target.
Соответствие общей структуры сильно полезнее одного совпавшего имени, но не
доказывает уникальный исходный commit. Vendor-добавления и поля всё ещё отличаются.

Четыре массива midstate, target и hash в публичном `struct work` объясняют часть
ранее найденного расположения данных. Это не основание приводить vendor work
размером 632 байта к типу upstream: указатели, time_t, условные поля и ABI нужно
сверять отдельно. Целиком совместимый layout этим этапом не установлен.

## Проверенная история S9

PR [ckolivas/cgminer#730](https://github.com/ckolivas/cgminer/pull/730) из
`jameshilliard/cgminer:s9` был слит **29 сентября 2018 года**. PR head:
`00869e55139c4834d48da5e8999d6417b9f7f519`; merge:
`5e676a72133066964fbd198eee95f29205e9e711`.

GitHub compare подтвердил, что наш pin находится на 93 commits впереди этого
merge, behind=0, merge-base совпадает с merge. Поэтому Bitmain/S9-слой уже входит
в выбранную базу. Переходить на случайный bmminer-форк только ради его наличия нет
технического основания. Это история публичной базы, **не доказательство того,
что VNish ответвился после этого merge**: он мог получить похожий код другим путём.

## Практическое направление

Открытые frontend-функции сначала сопоставлять с исходниками cgminer/Bitmain,
сохраняя изменения VNish как отдельные проверяемые отличия. Основной реверс
сосредоточить на отсутствующей аппаратной части, её dispatch и автотюне.
Из совпадений не следует, что любой старый cgminer уже поддерживает T21.

## Что с форком

**Удалённый форк в этой сессии не создан.** Текущее GitHub-подключение предоставляет
чтение/поиск, но не действие создания форка. Отдельная доступная write-операция
после проверки каталога инструментов/плагинов не найдена. Локальное скачивание
полного upstream также не выполнено. Старый пользовательский репозиторий не менялся.

Добавлен `tools/prepare_cgminer_fork.py`. Он использует официальную команду GitHub CLI,
сначала проверяет активный аккаунт, создаёт **только публичный upstream-форк**, клонирует
его с историей в НОВУЮ папку и создаёт локальную ветку на точном pin. Опция
`--apply-overlay` добавляет реконструкцию только локально. Есть проверки commit/tree/blob,
коллизий файлов и отказ при существующей выходной папке. Ничего не коммитится и не пушится.
Vendor ELF/дизассемблерные материалы дополнительно исключены в `.git/info/exclude`.
Это страховка от обычного `git add .`, не замена проверки перед любой публикацией.

Предварительный план без сети и изменений:

```sh
python3 tools/prepare_cgminer_fork.py --output ../cgminer-vn135-base --apply-overlay
```

Явное выполнение на компьютере с настроенным `gh` и интернетом:

```sh
python3 tools/prepare_cgminer_fork.py --output ../cgminer-vn135-base --apply-overlay --execute
```

По умолчанию ожидается аккаунт `darmenz2`, имя нового fork — `cgminer-vn135-base`.
Если такой репозиторий уже существует и не является требуемым прямым fork,
инструмент останавливается. При неудаче локального шага созданный удалённый fork
не удаляется автоматически. Программа не устанавливает ПО и не запрашивает токены
в аргументах. **В этой сессии проверены только план и локальные guards, не live-fork.**

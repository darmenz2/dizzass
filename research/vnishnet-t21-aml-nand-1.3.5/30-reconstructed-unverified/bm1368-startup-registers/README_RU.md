Они запускаются обычным Python и с `-O`; это регрессионные проверки границ
инструмента, не новое доказательство аппаратной эквивалентности.

Важное уточнение контракта `read_chain`: переданный output является write-only
до присваивания. Callback не наблюдает его начальное содержимое, полностью
заполняет его при успехе и не сохраняет указатель после возврата. В исходном
`e3c04` начальные stack slots не инициализированы, а host-локальные переменные
L‑16 обнулены; реальный переиспользованный cache getter читает только кэш и
записывает output. Эквивалентность для произвольного callback, читающего
начальные output bytes, не заявляется. Также сохраняются требования обычной
памяти, отсутствия гонок и нормального возврата callbacks; зависший callback
не получает нового timeout. Ошибки и частичные записи не откатываются.

Статус: **проверенный на host исходный кандидат; не готовая прошивка**.
База: `work/reconstruction` / `01299b84255542c16ee6d3f0c65a3e33e7aa876a`,

L‑15 сохранён и повторно проверен. L‑16 добавляет только новые файлы и может
применяться как поверх полной базы, так и после отдельного патча L‑15.
L‑14 (reg58) и незавершённый R13–R17 здесь не импортируются и не принимаются.

## Реализованный код

Новый модуль `libbitmain/src/chip/chip1368-startup-registers.c` — явно выделенная
единица интеграции из доказанного исходного `chip/chip1368.c`, а не якобы
восстановленное имя файла. Включается только макросом
`VN135_BM1368_STARTUP_REGISTERS_135`. Старый `chip1368.c` не изменён.
Нового main, майнера, планировщика, формата work/pool или сетевого стека нет.

| Оригинал | Метод C | Восстановленный обычный путь |
|---|---|---|
| `e35c0` | `vn135_bm1368_set_analog_mux_135` | Одна broadcast-запись reg54: `setting & 7`. Ошибка writer → одно сообщение, line425, затем −1. |
| `e3098` | `vn135_bm1368_set_nonce_bin_overflow_135` | Одна broadcast-запись reg3c: `(setting ^ 1) | 0x80008dee`. Ошибка → сообщения line387 и line593, затем −1. |
| `e3290` | `vn135_bm1368_write_reg68_pattern_135` | Одна broadcast-запись reg68: `0x5aa55aa5`. Результат writer передаётся без преобразования; собственного сообщения нет. |
| `e3c04` | `vn135_bm1368_update_soft_reset_misc_135` | Общий кэш: прочитать a8, затем18; изменить слова; записать a8, затем18; остановиться на первой ненулевой ошибке. |

`setting` для NONCE_BIN_OVERFLOW — полное 32-битное слово. Нормализация до
boolean или маскирование только младшего бита НЕ эквивалентны оригиналу.
Второе сообщение об ошибке перечитывает `device->index` после первого logger
callback. Индекс аргумента увеличивается по модулю 2^32; это не внешний индекс
координатора. Сохраняются исходные component/source/function/format/line/severity.

Для `e3c04`:

- Любой ненулевой mode: `soft |= 0x10f`, `misc &= ~0x00f00000`.
- Нулевой mode: `soft &= ~0xf0`, `misc |= 0xff0f0000`.

Индекс устройства читается заново перед вторым cache read. Оба прочитанных и
изменённых слова остаются сохранёнными через первый write callback. Изменение
кэша этим callback не меняет второе подготовленное слово. Нет дополнительного
чтения, sleep, отката первой записи или нового сообщения самой обёртки.

Переиспользованы настоящие `vn135_bm1368_write_register_135`, encoder/CRC и
`vn135_reg_cache_get_chain`/`set_chain`. Два коротких типизированных адаптера
подключают их без собственной реализации кэша/протокола. Поле device — уже
существующее host-представление, НЕ cast исходной структуры ARM.

## Что именно подтверждают свидетельства

Оригинал: `reference/cgminer.vendor.elf`, 6 228 004 байта, SHA256
`b2663b3aa753cc14ae9d3b11a14d3d93c74b605a3e433b02101c3c17c69d95e9`.
Этот файл уже был в полученном L‑15; MainPC для его чтения не требуется.
Он читался только как данные. Ни оригинальный процесс, ни интерпретатор ARM
не запускались. Второй оригинал hwscan в этом проходе не проверялся.

`static-witness.json` сохраняет 33 неперекрывающихся диапазона / 3 605 байт,
135 слов инструкций, 14 прямых call-сайтов (включая недостижимые дубли логгера),
11 PC-relative привязок, 6 расшифрованных строк и 19 контрольных сумм входов.
Код и literal/data отдельно представлены в `original-code.asm`.
Проверены XOR-инициализаторы новых строк, источник и имя функции. Инициализация
строк предполагается однократной и обычной; повторная модификация строк вне
контракта. Строка `driver` также сохранена из уже принятого общего свидетельства.

Четыре constructor slot: `0x80 → e35c0`, `0x68 → e3098`, `0x6c → e3290`,
`0x94 → e3c04`. Проверяются PC/literal/GOT/store-цепочки. Адреса остаются ДАННЫМИ:
их не преобразуют в указатели host-функций. Оригинальные startup-сайты с owner
`+0x190`, `+0x178`, `+0x17c`, `+0x1a4` сохранены отдельно. Это не реконструкция
полного переноса таблицы методов, ABI или всей функции `55774`.

В оригинальном координаторе вызовы зависят от флагов и других условий; наличие
методов не разрешает безусловно вызвать их на устройстве. Здесь добавлены тела
методов, а не новый общий startup. Включение/порядок/паузы/ошибки всего
координатора предстоит восстановить отдельно.

Сопоставление C с обычным графом оригинала — ручной статический анализ.
Проверка байтов и pin-ов НЕ является автоматическим доказательством
эквивалентности. Исключение непрозрачных parity-веток опирается на тождество
`x * (x - 1)` чётно в 32-битной арифметике. Предполагаются корректная обычная
память, стабильные исходные данные, отсутствие гонок и нормальное возвращение
callbacks с соблюдением ABI. Ошибки отображения памяти и исключения оригинала
не воспроизведены. Успешный cache-read обязан полностью заполнить output.

## Выполненные проверки

Каждый из четырёх финальных прогонов GCC 14.2 / Clang 17 (обычный и
ASan+UBSan) завершил **53 031 сценарий / 1 436 687 проверок**:
40 032 вызова простых методов, 12 768 RMW-сценариев, 231 сценарий композиции.
В двух обычных прогонах все 33 отдельно скомпилированные семантические мутации
выявлены ожидаемым assertion/exit1. Ошибка компиляции, crash или timeout за
обнаружение не засчитываются. Поля проверяются битовым oracle, отдельно от
выражений упаковки нового runtime. Количество тестов — не процент прошивки.

Матрицы проверяют оба знака ошибок и крайние int32, все 0..255 входы и отдельные
старшие биты, ненулевые mode с чистым старшим битом, порядок/отсутствие эффектов,
переполнение индекса, изменение состояния callbacks и NULL незадействованных
callbacks. Композиция вызывает настоящий writer, encoder, CRC и общий/чиповый
кэш; терминальный send только записывает либо возвращает заданную ошибку.
В одном сценарии кэш и индекс назначения меняются после двух RMW-чтений, что
проверяет сохранение второго слова и позднее чтение индекса writer.
Положительные статусы writer в отдельных raw-тестах проверяют прямую передачу
результата e3290; реальный существующий e4a74 всё так же возвращает 0/−1.

Во всех sanitizer-сборках инструментированы все шесть прямо компилируемых
единиц трансляции, включена leak detection. Эти прогоны прошли; TSan и полнота
всех возможных interleavings не заявляются. Отдельный Clang analyzer нового
runtime завершился без диагностик. 25 тестов статической проверки прошли как
обычно, так и с Python `-O`; полные ELF bytes совпали со всеми диапазонами.

Новый runtime отдельно скомпилирован Clang для `armv7a-none-eabi` с
`-ffreestanding`: объект ELF32/ARM, EABI5. Это только объектная компиляция:
нет Linux target sysroot, полной линковки прошивки, boot-теста или запуска ARM.

Регрессии: L‑15 — 66 517/1 131 053, GCC с 21 control и Clang ASan/UBSan
(старый L‑15 отключает leak detection); register/frequency — 2 360/64 853;
control bounds — 6 455 проверок/1 088 reset cases; L‑13 address — 315/4 318.
Оригинальные инструкции в этих прогонах не исполнялись. Сохраняются прежние
ограничения всех зависимостей, включая не восстановленные внутренние логи кэша.

У каждого `--out` должен быть новый каталог. Скрипты ничего не скачивают,
не обновляют Git refs и не запускают firmware. Новый workflow предоставлен,
но GitHub CI этого кандидата НЕ запускался. Независимого review ещё нет.

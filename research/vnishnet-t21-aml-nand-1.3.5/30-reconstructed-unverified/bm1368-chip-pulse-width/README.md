# BM1368: CLOCK_DELAY_CTRL для отдельного чипа

Восстановлен ограниченный офлайн-метод `cgminer:0xe33e0`, соответствующий
`hwscan:0xf3174`. Конструктор BM1368 помещает его числовой адрес в слот `+0x74`.
Это отдельный метод от уже восстановленного широковещательного `0xe34cc`.
Исходная метка функции в обоих образах — буквально `[redacted]`; имя нового
C-интерфейса описывает поведение, а не выдаётся за найденный символ поставщика.

Метод передаёт существующему register writer один вызов: исходное устройство,
режим 0, исходный указатель чипа, регистр `0x3c` и значение
`0x80008000 | ((pulse_width & 3) << 6) | ((clock_delay & 7) << 3)`.
Верхние биты аргументов отбрасываются без проверки диапазона. Только нулевой
результат writer означает возврат 0. Любая ошибка приводит к двум диагностикам
на строках 387 и 538 и возврату -1. Индекс устройства читается заново перед
каждой диагностикой, включая изменения, сделанные первым logger callback.

Новый файл `libbitmain/src/chip/chip1368-chip-pulse-width.c` — отдельная
тестовая единица трансляции исходного модуля `chip1368.c`, а не восстановленное
оригинальное имя файла. Его код включается только макросом
`VN135_BM1368_CHIP_PULSE_WIDTH_135`. Типы callback и существующий адаптер
register writer переиспользуются из принятого pulse-width интерфейса.
`Makefile.am` и предыдущие исходники остаются прежними. Нет второго ядра,
нового CRC, кэша, transport stack или подключения драйвера к production.

## Воспроизведение

Из этого каталога в Linux с C11-компилятором и Python:

```sh
make test sanitize controls
python3 -B verify_evidence.py
python3 -B -m unittest discover -s tests -p 'test_evidence.py' -v
python3 -O -B verify_evidence.py
```

Дополнительная сверка второго оригинального ELF, без его публикации:

```sh
python3 -B verify_hwscan.py --hwscan /path/to/exact/hwscan
```

`BUILD_DIR=/absolute/path` позволяет отдельно сохранить результаты каждого
компилятора. Обычные и sanitizer-прогоны компилируют все участвующие C-файлы,
включая существующие writer, encoder, CRC, PLL и cache. Host-тесты записывают
или отвергают байты в памяти и проверяют изменения выбранного chip cache.
Они не посылают команды плате и не проверяют ответ ASIC.

Статические доказательства и ограничения — в `STATIC_CONTRACT.md`.
Фактически выполненные проверки — в `validation.json`. Конструктор доказывает
идентичность метода, но вызывающий его путь T21 ещё не установлен. Проверки
не являются выполнением исходной прошивки, аппаратной приёмкой или доказательством
принятых пулом шар. Полный запуск и повторное использование аппаратных состояний
остаются отдельной работой.
